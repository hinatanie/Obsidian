
| Concept                        | Short explanation                                               | RideNow example                        | Services to use                            |
| ------------------------------ | --------------------------------------------------------------- | -------------------------------------- | ------------------------------------------ |
| Microservices                  | Split the system into independent services                      | User, Driver, Trip, Payment            | Amazon EKS, Docker, Kubernetes             |
| Database per Service           | Each service owns its database                                  | Trip Service → Trip DB                 | Amazon RDS / Aurora, DynamoDB              |
| REST API                       | Services communicate through HTTP                               | Trip → Driver Service                  | Spring Boot, Amazon API Gateway, ALB       |
| Redis                          | Very fast cache/shared temporary storage                        | Find nearby drivers                    | Amazon ElastiCache for Redis               |
| Concurrency Control            | Prevent multiple operations from conflicting                    | 2 drivers accept 1 ride                | PostgreSQL transactions, Redis             |
| Idempotency                    | Repeating a request doesn't repeat the operation                | Payment sent twice → charged once      | PostgreSQL, DynamoDB, Redis                |
| SQS                            | Queue for asynchronous work                                     | Send notification later                | Amazon SQS                                 |
| DLQ                            | Stores messages that repeatedly fail                            | Failed notification → DLQ              | Amazon SQS DLQ                             |
| EventBridge                    | Publishes events to multiple services                           | TRIP_COMPLETED → Payment + Analytics   | Amazon EventBridge                         |
| Saga                           | Manages a business transaction across services                  | Trip → Payment → compensation          | EventBridge, SQS, application logic        |
| Retry                          | Try failed operations again                                     | Payment temporarily unavailable        | Spring Retry, AWS SDK retry                |
| Circuit Breaker                | Temporarily stops requests to a failing service                 | Payment keeps failing → stop requests  | Resilience4j                               |
| Timeout                        | Don't wait forever for another service                          | Payment must respond within 3 sec      | Spring Boot, Resilience4j                  |
| Distributed Lock               | Prevent multiple servers performing the same critical operation | Only one driver gets a ride            | ElastiCache Redis, Redisson                |
| Eventual Consistency           | Data becomes consistent after an event is processed             | Trip completed → history updates later | EventBridge, SQS, DynamoDB                 |
| Kubernetes                     | Manages containers automatically                                | Runs all RideNow services              | Amazon EKS, Kubernetes                     |
| Service Discovery              | Finds other services automatically                              | trip-service → payment-service         | Kubernetes Service / CoreDNS               |
| Load Balancing                 | Distributes traffic across instances                            | 3 Trip Service Pods                    | AWS Load Balancer Controller, ALB          |
| HPA                            | Automatically increases/decreases Pods                          | Traffic ↑ → 3 Pods → 6 Pods            | Kubernetes HPA, CloudWatch                 |
| Health Checks                  | Detects unhealthy applications                                  | Restart broken Trip Pod                | Kubernetes probes, ALB health checks       |
| WebSocket                      | Real-time two-way communication                                 | Driver location → passenger            | API Gateway WebSocket, Spring WebSocket    |
| Observability                  | Understands what happens inside the system                      | Logs + metrics + traces                | CloudWatch, AWS X-Ray, Prometheus, Grafana |
| CI/CD                          | Automatically tests/builds/deploys code                         | GitHub → Docker → ECR → EKS            | GitHub Actions, ECR, EKS, Argo CD          |
| Containerization               | Packages application and dependencies together                  | Package Trip Service                   | Docker, Amazon ECR                         |
| API Gateway                    | Single entry point for external API requests                    | Mobile → API Gateway → services        | Amazon API Gateway                         |
| Authentication & Authorization | Verifies users and controls access                              | Passenger vs Driver permissions        | Amazon Cognito, JWT, Spring Security       |
| Secrets Management             | Securely stores passwords/API keys                              | Database credentials                   | AWS Secrets Manager, Kubernetes Secrets    |
| Configuration Management       | Separates configuration from application code                   | DB URL, service settings               | Kubernetes ConfigMap,                      |
