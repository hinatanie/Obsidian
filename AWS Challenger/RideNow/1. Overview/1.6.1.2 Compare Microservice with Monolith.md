Compare that with a **monolith**.
```text
MONOLITH
+--------------------------------+
| One Spring Boot application    |
|                                |
| User module                    |
| Driver module                  |
| Trip module                    |
| Payment module                 |
|                                |
| One deployment                 |
+--------------------------------+
```
With microservices:
```text
MICROSERVICES
+-------------+
| User        |
| Service     |
+-------------+
+-------------+
| Driver      |
| Service     |
+-------------+
+-------------+
| Trip        |
| Service     |
+-------------+
+-------------+
| Payment     |
| Service     |
+-------------+
```
So the simplest definition is:
> **Microservice = split a large backend system into multiple independently deployable services, with each service responsible for one business capability.**  
> The phrase **independently deployable** is extremely important.  
> Imagine Payment Service has a bug.  
> With a monolith, you may need to redeploy:
```text
User + Driver + Trip + Payment
```
With microservices, ideally you deploy only:
```text
Payment Service
```
