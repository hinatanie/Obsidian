##### **What is a `NACL`?**
`NACL` means `Network Access Control List`.
A `NACL` is a subnet-level firewall that controls traffic entering and leaving a `subnet`.
```text
NACL = Network Access Control List
NACL = firewall for subnet
```
A `NACL` does not attach directly to one `EC2` instance.
It attaches to a `subnet`.
So all resources inside that `subnet` are affected by the `NACL` rules.
##### **What does subnet-level firewall mean?**
`Subnet-level` means the firewall rules apply to the whole `subnet`.
Example:
```text
Subnet A
├── EC2 instance 1
├── EC2 instance 2
└── EC2 instance 3
```
If `Subnet A` uses `NACL-1`, then all three `EC2` instances are affected by `NACL-1`.
Simple idea:
```text
Security Group = firewall for EC2 / ENI
NACL           = firewall for subnet
```
**Can one `NACL` protect multiple subnets?**
Yes.
One `NACL` can be associated with multiple `subnets`.
Example:
```text
Subnet A → NACL-1
Subnet B → NACL-1
Subnet C → NACL-1
```
This means `Subnet A`, `Subnet B`, and `Subnet C` all use the same `NACL` rules.
If you change `NACL-1`, the change affects all subnets associated with it.
**Can one subnet use multiple `NACLs`?**
No.
One `subnet` cannot use multiple `NACLs` at the same time.
Correct rule:
```text
One subnet → One NACL
```
A `subnet` must be associated with exactly one `NACL`.
But one `NACL` can be used by multiple `subnets`.
Simple idea:
```text
One subnet can use only one NACL.
One NACL can protect multiple subnets.
```

##### **How do `NACL` rules work?**
`NACL` rules have numbers.
AWS checks the rules in number order.
Lower numbers are checked first.
Example:
```text
Rule 100: Allow HTTPS
Rule 200: Deny all traffic
```
AWS checks `Rule 100` first.
If the traffic matches `Rule 100`, AWS applies that rule and stops checking the later rules.
##### **Why is `NACL` rule order important?**
Rule order is important because AWS stops checking when it finds the first matching rule.
Example:
```text
Rule 100: Deny TCP port 22 from 0.0.0.0/0
Rule 200: Allow all traffic from 0.0.0.0/0
```
This means `SSH` traffic on port `22` is denied first.
Other traffic can still be allowed by rule `200`.
So the order of rules can change the final result.
##### **What is a good practice for `NACL` rule numbers?**
A good practice is to use lower numbers for more specific rules.
Use higher numbers for more general rules.
Example:
```text
Rule 100: Deny bad IP 1.2.3.4
Rule 200: Allow HTTPS from everyone
Rule 300: Deny all other traffic
```
This makes your `NACL` easier to understand and safer to manage.
Simple rule:
```text
Lower number = checked earlier
Higher number = checked later
```
##### **What is the difference between `Security Group` rules and `NACL` rules?**
`Security Groups` only have allow rules.
`NACLs` have both allow rules and deny rules.
```text
Security Group:
Allow rules only
NACL:
Allow rules
Deny rules
```
Example `NACL` idea:
```text
Deny traffic from bad IP 1.2.3.4
Allow traffic from everyone else
```
This is useful when you want to explicitly block some traffic at the `subnet` level.
##### **Why can `NACLs` deny traffic but `Security Groups` cannot?**
`NACLs` support both `Allow` and `Deny` rules.
Example:
```text
Rule 100: Deny TCP port 22 from 0.0.0.0/0
Rule 200: Allow all traffic from 0.0.0.0/0
```
This means:
```text
Block SSH from everyone.
Allow other traffic.
```
A `Security Group` cannot do this directly because it does not have deny rules.
With a `Security Group`, if you do not create an allow rule for `SSH`, then `SSH` is blocked automatically.
##### **What does `NACLs are stateless` mean?**
`NACLs` are `stateless`.
That means they do not remember previous traffic.
If traffic goes out, the `NACL` does not automatically allow the reply back in.
If traffic comes in, the `NACL` does not automatically allow the response back out.
So with `NACLs`, you need rules for both directions.
```text
Inbound request rule
Outbound response rule
```
And for traffic started by an `EC2` instance:
```text
Outbound request rule
Inbound response rule
```
##### **Why do `NACLs` need rules for both directions?**
Because `NACLs` are `stateless`.
Example: a user wants to access your website.
Request flow:
```text
Internet user → EC2 website
```
You need an inbound rule:
```text
Allow inbound HTTPS TCP port 443
```
Then the `EC2` instance sends a response back.
Response flow:
```text
EC2 website → Internet user
```
You also need an outbound rule to allow the response traffic.
##### **What is an example of inbound request and outbound response?**
A user accesses your website using `HTTPS`.
Inbound request:
```text
Internet user
→ HTTPS port 443
→ EC2 in subnet
```
The `NACL` needs this inbound rule:
```text
Inbound rule:
Type:     HTTPS
Protocol: TCP
Port:     443
Source:   0.0.0.0/0
Action:   Allow
```
This allows users from the internet to access your website on port `443`.
Then the `EC2` sends the response back.
Outbound response:
```text
EC2 in subnet
→ response traffic
→ Internet user
```
The `NACL` also needs an outbound rule that allows the response traffic.
Because `NACLs` are `stateless`, the response is not automatically allowed.
##### **What is an example of outbound request and inbound response?**
An `EC2` instance wants to connect to the internet.
Example:
```text
EC2 → HTTPS website
```
The `NACL` needs an outbound rule:
```text
Outbound rule:
Type:        HTTPS
Protocol:    TCP
Port:        443
Destination: 0.0.0.0/0
Action:      Allow
```
Then the website sends a response back:
```text
HTTPS website → EC2
```
The `NACL` also needs an inbound rule to allow the response traffic.
For response traffic, you often need to allow `ephemeral ports`.
##### **What are `Ephemeral Ports`?**
`Ephemeral ports` are temporary high-numbered ports used for return traffic.
When an `EC2` instance connects to a website, the destination is usually port `443`.
But the response comes back to a temporary port on the `EC2`.
Example:
```text
EC2 source port:      49152
Website destination:  443
```
When the website replies:
```text
Website source port:  443
EC2 destination port: 49152
```
Because `NACLs` are `stateless`, you may need to allow ephemeral ports for return traffic.
Common ephemeral port range:
```text
1024-65535
```
This is one reason `NACLs` are more difficult to configure than `Security Groups`.
##### **What is a `Protocol`?**
A `Protocol` is the communication method used by network traffic.
Common protocols are:

|Protocol|Meaning|
|---|---|
|`TCP`|Used by `SSH`, `HTTP`, `HTTPS`, databases, and many applications.|
|`UDP`|Used by services like `DNS`, streaming, or some game/network services.|
|`ICMP`|Used for `ping` and network diagnostic messages.|
A `Protocol` tells AWS what type of traffic the rule applies to.
##### **What does `TCP` mean?**
`TCP` is a common network protocol used by many important services.
Examples:
```text
SSH
HTTP
HTTPS
PostgreSQL
MySQL
Redis
```
Most web and database traffic uses `TCP`.
Example:
```text
HTTPS = TCP port 443
SSH   = TCP port 22
```
##### **What does `UDP` mean?**
`UDP` is another network protocol.
It is often used when speed is more important than connection tracking.
Examples:
```text
DNS
Streaming
Some game servers
Some real-time network services
```
Example:
```text
DNS often uses UDP port 53
```
##### **What does `ICMP` mean?**
`ICMP` is used for network diagnostic messages.
A common example is `ping`.
Example:
```bash
ping 8.8.8.8
```
This command sends `ICMP` messages to test network connectivity.
If `ICMP` is blocked by a `NACL` or `Security Group`, `ping` may fail even if other traffic works.
##### **What does `Source` mean for inbound rules?**
For inbound rules, `Source` means:
```text
Where does the traffic come from?
```
Example:
```text
Inbound rule:
Type:   HTTP
Port:   80
Source: 0.0.0.0/0
Action: Allow
```
This means allowing `HTTP` traffic from anywhere on the internet into this `subnet`.
`Source` is used for traffic entering the `subnet`.
##### **What is an inbound rule allowing `HTTP` from anywhere?**
Example:
```text
Inbound rule:
Type:   HTTP
Port:   80
Source: 0.0.0.0/0
Action: Allow
```
This means:
```text
Allow HTTP traffic from anywhere on the internet into this subnet.
```
`0.0.0.0/0` means all IPv4 addresses.
This may be used for a public web subnet.
##### **What is an inbound rule allowing `SSH` from one IP?**
Example:
```text
Inbound rule:
Type:   SSH
Port:   22
Source: 203.0.113.10/32
Action: Allow
```
This means:
```text
Allow SSH only from 203.0.113.10 into this subnet.
```
`/32` means one specific IPv4 address.
This is safer than allowing `SSH` from everyone.
Avoid this for `SSH` unless it is temporary testing:
```text
Source: 0.0.0.0/0
```
##### **What does `Destination` mean for outbound rules?**
For outbound rules, `Destination` means:
```text
Where is the traffic going?
```
Example:
```text
Outbound rule:
Type:        HTTPS
Port:        443
Destination: 0.0.0.0/0
Action:      Allow
```
This means resources in this `subnet` can connect to anywhere using `HTTPS`.
`Destination` is used for traffic leaving the `subnet`.
##### **What is an outbound rule allowing `HTTPS` to anywhere?**
Example:
```text
Outbound rule:
Type:        HTTPS
Port:        443
Destination: 0.0.0.0/0
Action:      Allow
```
This means:
```text
Allow resources in this subnet to connect to anywhere using HTTPS.
```
Common use cases:
```text
Download updates
Call external APIs
Connect to AWS service endpoints
Pull Docker images
```
##### **What are `Allow` and `Deny` rules in `NACLs`?**
`NACLs` can have both:
```text
Allow rules
Deny rules
```
This is different from `Security Groups`.
Example:
```text
Rule 100: Deny TCP port 22 from 0.0.0.0/0
Rule 200: Allow all traffic from 0.0.0.0/0
```
This means:
```text
Block SSH from everyone.
Allow other traffic.
```
Because rule `100` has a lower number, AWS checks it first.
##### **What happens if a `Deny` rule comes before an `Allow` rule?**
If a matching `Deny` rule has a lower number, traffic is denied before AWS reaches the `Allow` rule.
Example:
```text
Rule 100: Deny SSH from 0.0.0.0/0
Rule 200: Allow all traffic from 0.0.0.0/0
```
`SSH` traffic matches rule `100`, so it is denied.
AWS stops checking.
Rule `200` does not matter for that `SSH` traffic.
##### **What is the structure of a `NACL`?**
A `NACL` has two rule sections:
```text
Inbound rules
Outbound rules
```
The structure is like this:
```text
NACL
├── Inbound rules
│   ├── Rule 100: Allow ...
│   └── Rule 200: Deny ...
│
└── Outbound rules
    ├── Rule 100: Allow ...
    └── Rule 200: Deny ...
```
Inbound rules control traffic entering the `subnet`.
Outbound rules control traffic leaving the `subnet`.
##### **What is a simple `NACL` example for a public website?**
Suppose your `EC2` web server is in a public `subnet`.
You want users to access the website using `HTTPS`.
Inbound rule:
```text
Inbound rule:
Rule number: 100
Type:        HTTPS
Protocol:    TCP
Port:        443
Source:      0.0.0.0/0
Action:      Allow
```
This allows users from the internet to enter the `subnet` using `HTTPS`.
Outbound rule:
```text
Outbound rule:
Rule number: 100
Type:        Custom TCP
Protocol:    TCP
Port:        1024-65535
Destination: 0.0.0.0/0
Action:      Allow
```
This allows response traffic to go back to users.
Because `NACLs` are `stateless`, both rules matter.
##### **What is a simple `NACL` example for blocking bad IP?**
Suppose you want to block traffic from bad IP `1.2.3.4`.
You can create a deny rule with a low rule number.
```text
Inbound rule:
Rule number: 100
Type:        All traffic
Protocol:    All
Port:        All
Source:      1.2.3.4/32
Action:      Deny
```
Then allow other traffic after that:
```text
Inbound rule:
Rule number: 200
Type:        HTTPS
Protocol:    TCP
Port:        443
Source:      0.0.0.0/0
Action:      Allow
```
This means:
```text
Block bad IP first.
Then allow HTTPS from everyone else.
```
##### **What is the difference between `Source` and `Destination`?**
For inbound rules, use `Source`.
For outbound rules, use `Destination`.
```text
Inbound rule:
Source = where traffic comes from
Outbound rule:
Destination = where traffic goes
```
Example:
```text
Inbound HTTP:
Source: 0.0.0.0/0
Outbound HTTPS:
Destination: 0.0.0.0/0
```
##### **What is the difference between `Security Group` and `NACL`?**
`Security Groups` and `NACLs` are both firewall-like controls, but they work differently.
```text
Security Group:
- Instance-level firewall
- Attached to ENI / EC2
- Stateful
- Allow rules only
- Response traffic is automatically allowed
NACL:
- Subnet-level firewall
- Attached to subnet
- Stateless
- Allow and deny rules
- Response traffic must be allowed manually
```
Simple idea:
```text
Security Group = EC2 door
NACL           = subnet gate
```
