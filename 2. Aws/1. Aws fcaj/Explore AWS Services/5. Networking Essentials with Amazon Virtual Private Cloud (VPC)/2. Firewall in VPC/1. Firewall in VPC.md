Amazon VPC has security controls that work like firewalls. They help you decide
```
Who can connect to my resources?
Where can my resources connect to?
Which traffic should be allowed or blocked?
```
The two main security controls are
```
Security groups
NACLs
```

A Security Group is a firewall for your EC2 instance

A Security Group controls two directions of traffic
**Inbound traffic** means traffic coming into your EC2 instance
Example: if you want users to access your web server, you may allow
```
HTTP port 80
HTTPS port 443
```
If you want to SSH into your EC2 instance, you may allow
```
SSH port 22
```

**Outbound traffic** means traffic going out from your EC2 instance
By default, Security Groups allow all outbound traffic. So normally, your EC2 instance can call external services unless you restrict outbound rules

Security Groups are stateful that means they can remember who started the connection
After creating an EC2 instance, people from the internet cannot connect to it unless you add inbound rules

For example, to allow web traffic, you need to add
```
Inbound rule:
Type: HTTP
Port: 80
Source: 0.0.0.0/0
```
Or for HTTPS:
```
Inbound rule:
Type: HTTPS
Port: 443
Source: 0.0.0.0/0
```
---
A Security Group protects an EC2 instance
Security Group is firewall for EC2 instance 

**A NACL protects a subnet**
**NACL is firewall for subnet**

If a NACL is attached to a subnet, it affects traffic going in and out of that subnet
All resources inside that subnet are affected by the NACL rules

So if you have three EC2 instances inside the same subnet.
They are all affected by the NACL of that subnet

**NACLs are stateless**,
that means NACLs do not remember previous traffic
With a Security Group, the response is automatically allowed because Security Groups are stateful
But with a NACL, you need rules for
```
Outbound traffic: EC2 -> Internet
Inbound traffic: Internet -> EC2 response
```

**NACL rules are checked by number**
Lower numbers are checked first
Example
```
Rule 100: Allow HTTP
Rule 200: Deny all traffic
```
So rule order is very important
Good practice
```
Use lower numbers for more specific rules
Use higher numbers for more general rules
```

**One subnet must have one NACL**
Each subnet must be connected to exactly one NACL. A subnet cannot have no NACLS or more than one NACL at the same time
**NACL can be**
```
Default NACL
Custom NACL
```

**Default NACL** allows all inbound and outbound traffic
But if you create a custom NACL, you need to be carefule because rules can block traffic if you do not configure them correctly

---
**Virtual firewall** is a software-based firewall that filters network traffic instead of using physical hardware

**Security group** is a statefule virtual firewall attached to an EC2 instance not directly to the whole subnet.It controls inbound and outbound traffic
Each EC2 instance can have different Security Group rules

**Network Access Control List /  NACL** is a subnet-level firewall that controls traffic entering and leaving a subnet

**Firewall** is a system that allows or blocks network traffic based on rules

**Subnet level** means applied to the subnet, so it affects resources inside that subnet

**Instance level** means applied directly to an EC2 instance, not to the whole subnet

**VPC peering** is a connection between two VPCs that allows resources in them to communicate using private IP addresses

**Protocol** is a communication rule used by network traffic, such as TCP, UDP, or ICMP

**Protocol number** is a number that identifies a network protocol

**SSH** is a protocol used to securely connect to a server remotely

**Port 22** is the standard port used by SSH
