**NACL / Network Access Control List** is a subnet level firewall that control traffic entering and leaving a subnet

A NACL can protect multiple subnets
```
Subnet A → NACL-1  
Subnet B → NACL-1  
Subnet C → NACL-1
```
But one subnet cannot use muti NACLs at the same time

NACL rules have numbers and rule order is very important for AWS to check and stop checking if find the match

Security Groups only have allow rules
But NACLs have both allow rules and deny rules
```
Deny traffic from bad IP 1.2.3.4
Allow traffic from everyone else
```

NACLs are stateless that means they do not remember previous traffic
So with NACLs, you need rules for both directions
```
Inbound request rule
Outbound response rule
```
And for traffic started by EC2
```
Outbound request rule
Inbound response rule
```

Example:
Your EC2 is in a subnet with a NACL. A user wants to access your website
You need inbound rule
```
Allow inbound HTTPS TCP port 443
```
Then EC2 sends a response back, you also need outbound rule to allow the response traffic

**Protocol** is the communication method
Common protocols:

|Protocol|Meaning|
|---|---|
|**TCP**|Used by SSH, HTTP, HTTPS, databases, and many applications.|
|**UDP**|Used by services like DNS, streaming, or some game/network services.|
|**ICMP**|Used for ping and network diagnostic messages.|

---
**Source for Inbound Rules**
For inbound rules, source means `Where does the traffic come from?`

Example:
```
Inbound rule:
Type: HTTP
Port: 80
Source: 0.0.0.0/0
Allow
```
Mean allowing HTTP traffic from anywhere on the internet into this subnet

```
Inbound rule:
Type: SSH
Port: 22
Source: 203.0.113.10/32
Allow
```
Mean allowing SSH only from this one IP address into this subnet

---
**Destination for Outbound Rules**
For outbound rules, destination means `Where is the traffic going?`

Example
```
Outbound rule:
Type: HTTPS
Port: 443
Destination: 0.0.0.0/0
Allow
```
Mean allowing resources in this subnet to connect to anywhere using HTTPS

---
NACLs can have both 
```
Allow rules
Deny rules
```
This is different from Security Groups

Example
```
Rule 100: Deny TCP port 22 from 0.0.0.0/0
Rule 200: Allow all traffic from 0.0.0.0/0
```
This means blocking SSH from everyone and allowing other traffic

the structure is like:
```
NACL 
├── Inbound rules 
│    ├── Rule 100: Allow ... 
│    └── Rule 200: Deny ... 
│ └── Outbound rules      
├── Rule 100: Allow ...      
└── Rule 200: Deny ...
```
