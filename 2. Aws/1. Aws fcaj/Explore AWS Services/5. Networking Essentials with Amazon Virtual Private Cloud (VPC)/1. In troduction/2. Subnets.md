A subnet is a smaller network inside VPC network
For example, your VPC may have this CIDR block
```
10.0.0.0/16
```
Then you can divide it into smaller subnets
```
10.0.1.0/24
10.0.2.0/24
10.0.3.0/24
```
These subnets must be inside the VPC CIDR block. You cannot create a subnet outside the VPC range

---
AWS also reserves 5 IP addresses in every subnet
For example, a /28 subnet has 16 total IP addresses but i can only use 11

You can not use all IP addresses in a subnet. AWS keeps some for internal networking

---
A subnet type is decided by routing
A subnet becomes public or private because of its route table
A public subnet has a route to the Internet Gateway, meaning this subnet can go to the internet
```
Public subnet
Route table
0.0.0.0/0 -> Internet Gateway
```
A public subnet usually put in
```
Web server
Load balancer
Bastion host
```

A private subnet does not have a direct route to the Internet Gateway, meaning Internet cannot directly reach this subnet
```
Private subnet
Route table 
No route directly to Internet Gateway
```
A private subnet usually put in
```
Database
Backend server
Internal service
```

**Availability Zone / AZ** is a separate data center area inside an AWS Region

**You have to use multi AZs** so that if one AZ has a problem, your app can still run in another AZ, Otherwise, if an AZ fails, everything may stop 

**AWS resources** are services or objects created in AWS, such as EC2 instances, RDS databases, Lambda functions, or load balancers
