**Route table** is set of rules that direct traffic for your subnet

A route table has rules like this
```
Destination    Target
10.0.0.0/16    local
0.0.0.0/0      Internet Gateway
```
The first part is Destination
The second part is Target

**Example for local route:** Suppose VPC CIDR block is
```
10.0.0.0/16
```
Inside the VPC
```
EC2 A: 10.0.1.10
EC2 B: 10.0.2.20
```
EC2 A wants to talk to EC2 B, AWS automatically creates this route
```
Desination: 10.0.0.0/16
Target:     local
```
**local** means inside the VPC

**Example for public subnet** : A public subnet has this route
```
Destination: 0.0.0.0/0
Target:       Internet Gateway
```
**0.0.0.0/0** means everywhere else( internet, outside the VPC )
**Internet gateway** is a VPC component that allows resources in public subnet to access the internet


**Example for private subnet**: A private subnet does not have a direct route to an Internet Gateway, so it has this route
```
Destination: 0.0.0.0/0
Target: Nat Gateway
```

## Very simple picture
```
VPC: 10.0.0.0/16

Public Subnet
Route Table:
10.0.0.0/16 → local
0.0.0.0/0   → Internet Gateway

Private Subnet
Route Table:
10.0.0.0/16 → local
```
So:
```
Public subnet = has internet road
Private subnet = no direct internet road
```

---
When you create a VPC, AWS automatically creates a route that lets resources inside the VPC talk to each other
```
Destination: 10.0.0.0/16
Target:      local
```
This works even if the resources are in different subnets
Also, you cannot delete it or change it

**Every subnet** must use one route table
**If you do not manually choose a route table for a subnet**, AWS automatically connects that subnet to the main route table
