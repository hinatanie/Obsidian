**Public subnet** can have direct route to Internet Gateway
**Private subnet** have no direct route to Internet Gateway
**NAT Gateway** is a VPC component that allows private resources to access the internet without allowing the internet directly access them

For example, imagine you have an EC2 instance in a private subnet. Because it is private, users from the internet cannot directly connect to it. That is good for security.

But sometimes, that EC2 instance still needs to go out to the internet, for example to:

download security updates,  
install packages,  
call an external API,  
connect to some AWS services.

---
**NAT Instance** is an EC2 instance manually configured to perform NAT. You manage it yourself

A NAT Gateway is  not free. AWS charges you in two main ways

First, you pay for the tiem the NAT Gateway is running
Second, you pay for the amoun tof data that goes through it

For a small system, you might use one NAT Gateway to reduce cost. However, for a production system that needs high reliability, you usually deploy NAT Gateways in multi AZs

The reason is if one AZ has a problem, resources in another AZ can still use their own NAT Gateway

To create a NAT Gateway, you need three important things
1. A public subnet
The NAT Gateway must be placed in a public subnet because it needs access to the internet
2. An Elastic IP address
The NAT Gateway needs a public IP address so it can send traffic to the intenet on behalf of private EC2 instances
3. Route table configuration
Private subnets need a route like this
```
Destination:   0.0.0.0/0
Target:        NAT Gateway
```

One important detail is that the Elastic IP address must not already be attached to another resource. If it is already connected to a NAT Instance or EC2 instance, you must detach it first

---
A NAT Gateway lets a private EC2 instance start a connection to the internet

But it does not let someone from the internet start a new connection to that private EC2 instance

Example for connection started from private EC2 instance: Your private EC2 instance wants to download software updates
```
Private EC2 -> NAT Gateway -> Ubuntu update server
```
Then the Ubuntu server sends a reply back
```
Ubuntu update a server -> NAT Gateway -> Private EC2
```
This reply is allowed because it is part of the same connection that the private EC2 started.
