Amazon VPC lets you create your own private, controlled, and secure network inside AWS 

Normally, if you run servers in a company data center, you need to design the network yourself ( IP addresses, subnets, routing, gateways, and security ). 
Amazon VPC gives you the same kind of control, but inside AWS Cloud.

Inside a VPC, you choose an IP address range, for example
```
10.0.0.0/16
```
This range is called a CIDR block. 
After you create the VPC, the main CIDR block cannot be changed, so you should choose it carefully

You can also divide the VPC into smaller parts called subnets. For example, you may have public subnet for web servers and private subnet for databases.

A VPC belongs to one AWS Region. For example, if you create a VPC in Singapore Region, it exists only in that Region. 
You can create multiple VPCs in the same Region.

The CIDR block size controls how many IP addresses your VPC can have. For example 
```
/16 means 65,536 IP addresses
/28 means 16 IP address
```
---

Note: Your VPC CIDR block must not overlap with other networks. This is very important when you connect your VPC to another networks, such as your company's on-premises network

For example, imagine your company networks uses
```
10.0.0.0/16
```
Then your AWS VPC should not also use
```
10.0.0.0/16
```
If you use it when the traffic wants to go to 10.0.1.20 the system becomes confused `Is 10.0.1.20 in the office network or in AWS VPC? `

---
Amazon VPC came after Amazon EC2. In the past, AWS had two networking models

The old model was EC2-Classic. In this model, resources used a shared, flat network

The current model is EC2-VPC. In this model, resources run inside isolated virtual networks. This is more secure and gives you more control


AWS also creates a default VPC( EC2-VPC ) in each Region. This default VPC uses this CIDR block
```
172.31.0.0/16`
```

However, for real production systems, it is usually better to create a custom VPC. A custom VPC gives you better control over IP ranges, subnets, routing, gateways, and security

There are four important components
- Subnet
- Route table
- Internet gateway
- NAT gateway

---
**Subnet**  is a smaller network inside a VPC. You divide a VPC into subnets to organize resources.

**Route table** is a set of rules that tells network traffic where to go.

**Network gateway** is a connection point between networks. In AWS, gateways help your VPC connect to the internet or other networks.

**IPv4**  is the older and most common IP address system, using addresses like `192.168.1.1`.

**IPv6**  is a newer IP address system with a much larger address space.

**Primary CIDR block**  is the main IP address range assigned to a VPC when it is created.

**CIDR block**  is an IP address range used by a VPC or subnet.

**On-premises network**  is a company's own physical network  not in the cloud.
For example, your company has
Office building
├── Routes  
├── Switches  
├── Servers
└── Computers

**Amazon EC2**  is a service that lets you create and run virtual servers in AWS.

**EC2-Classic**  was the old AWS networking model.
In the past, when you created an EC2 server, it was not inside your own private VPC. Instead, many AWS customers' EC2 instances used a shared AWS network model

**EC2-VPC** is the current AWS networking model.
Now, when you create EC2 instances, they run inside a VPC. A VPC is your own isolated network are in AWS

**Flat network**  is a simple network without strong separation between different parts.

**Shared network**  is a network used by many customers or systems together.

**Internet Gateway**  is a VPC component that allows resources in public subnets to access the internet.

**Virtual Private Gateway / VGW** is a gateway used to connect a VPC to another private network, often an on-premises network, through VPN 

**NAT Gateway**  is a VPC component that allows private resources to access the internet without allowing the internet to directly access them.

**Subnet sizing** is choosing how large a subnet should be, usually by selecting the CIDR block size

**Exteral internet traffic** is traffic coming outside AWS, from the public internet

**Internet-bound traffic** is traffic that is going to the internet

**Network architecture**  is the overall design of how networks, subnets, gateways, and routes are organized.

**VPC component** is a networking part inside or attached to a VPC

**Private IP address** is an internal IP address used inside the VPC

**Public IP address** is an IP address that can be used on the public internet

**Elastic IP address** is an static public IP address that you can allocate in AWS and attach to resources
Unlike a normal public IP, it can stay the same

**Source IP** is the IP address where traffic comes from

**Network Address Translation / NAT** is changing one IP address into another IP address when traffic moves between networks 

**Outbound traffic** is traffic going out from your VPC to the internet

**Inbound traffic** is traffic comming from the internet into your VPC

**Data transfer rates** is the cost charged based on how much data moves in or out

**Bandwidth constraints** limits on how much network traffic can pass through

**NAT Instance** is an EC2 instance manually configured to perform NAT. You manage it yourself

**Protocol** means the communcation method
