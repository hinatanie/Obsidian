#flashcards
##### **What is a subnet?**
?  
+++  
#flashcards  
A `subnet` is a smaller network inside a `VPC`.  
You divide a VPC into subnets to organize your AWS resources.  
For example, your VPC may have this CIDR block:
```text
10.0.0.0/16
```
Then you can divide it into smaller subnets:
```text
10.0.1.0/24
10.0.2.0/24
10.0.3.0/24
```
The VPC is the big network.  
The subnets are smaller networks inside it.  
**Do subnets need to be inside the VPC CIDR block?**  
Yes.  
Subnets must be inside the VPC CIDR block.  
For example, if your VPC is:
```text
10.0.0.0/16
```
Then these subnets are valid:
```text
10.0.1.0/24
10.0.2.0/24
10.0.3.0/24
```
Because they are inside the `10.0.0.0/16` range.  
**Can you create a subnet outside the VPC range?**  
No.  
You cannot create a subnet outside the VPC CIDR block.  
For example, if your VPC is:
```text
10.0.0.0/16
```
Then this subnet is not valid:
```text
192.168.1.0/24
```
Because `192.168.1.0/24` is outside the VPC range.

##### **How many IP addresses does AWS reserve in a subnet?**
?  
+++  
#flashcards  
AWS reserves `5 IP addresses` in every subnet.  
These IP addresses are used by AWS for internal networking.  
So you cannot use all IP addresses in a subnet.  
**Example with `/28` subnet**  
A `/28` subnet has:
```text
16 total IP addresses
```
But AWS reserves:
```text
5 IP addresses
```
So you can only use:
```text
11 IP addresses
```
Formula:
```text
16 total IP addresses - 5 reserved IP addresses = 11 usable IP addresses
```

##### **Why can you not use all IP addresses in a subnet?**
?  
+++  
#flashcards  
You cannot use all IP addresses because AWS keeps some addresses for internal networking.  
AWS uses them for things like:
```text
Network address
VPC router
DNS
Future AWS use
Broadcast address
```
So when planning subnet size, always remember that AWS reserves 5 IP addresses.

##### **What decides if a subnet is public or private?**
?  
+++  
#flashcards  
A subnet type is decided by routing.  
A subnet becomes public or private because of its `route table`.  
The subnet itself is not automatically public or private.  
The route table decides what kind of network access the subnet has.  
?

##### **What is a public subnet?**
?  
+++  
#flashcards  
A `public subnet` is a subnet that has a route to an `Internet Gateway`.  
For example:
```text
Public subnet
Route table
0.0.0.0/0 → Internet Gateway
```
This means traffic from the subnet can go to the internet.  
It also means internet-facing resources can be placed in this subnet.  
?  
+++  
#flashcards
##### **What does `0.0.0.0/0 → Internet Gateway` mean?**
?  
+++  
#flashcards
```text
0.0.0.0/0 → Internet Gateway
```
`0.0.0.0/0` means all IPv4 internet traffic.  
So this route means:
```text
Send internet traffic to the Internet Gateway
```
If a subnet route table has this route, the subnet is usually considered public.  
?

##### **What resources usually go in a public subnet?**
?  
+++  
#flashcards  
A public subnet usually contains internet-facing resources.  
For example:
```text
Web server
Load balancer
Bastion host
```
These resources may need to receive traffic from the internet.

##### **What is a private subnet?**
?  
+++  
#flashcards  
A `private subnet` does not have a direct route to the `Internet Gateway`.  
For example:
```text
Private subnet
Route table
No route directly to Internet Gateway
```
This means the internet cannot directly reach resources in this subnet.  
?  
+++  
#flashcards
##### **What resources usually go in a private subnet?**
?  
+++  
#flashcards  
A private subnet usually contains internal resources.  
For example:
```text
Database
Backend server
Internal service
```
These resources should not be directly exposed to the public internet.  
**Can a private subnet access the internet?**  
Yes, but not directly through an Internet Gateway.  
A private subnet can access the internet through a `NAT Gateway`.  
Example:
```text
Private subnet → NAT Gateway → Internet Gateway → Internet
```
This allows private resources to download updates or call external APIs.  
But the internet cannot directly connect back to those private resources.

##### **What is an Availability Zone?**
?  
+++  
#flashcards  
`Availability Zone`, or `AZ`, is a separate data center area inside an AWS Region.  
For example, one AWS Region can have multiple AZs:
```text
ap-southeast-1a
ap-southeast-1b
ap-southeast-1c
```
Each AZ is separated from the others, so a problem in one AZ should not always affect the others.  
?  
+++  
#flashcards
##### **Why should you use multiple AZs?**
?  
+++  
#flashcards  
You should use multiple AZs so your app can keep running if one AZ has a problem.  
If everything is only in one AZ, then your app may stop when that AZ fails.  
Better design:
```text
Public subnet in AZ 1
Public subnet in AZ 2
Private subnet in AZ 1
Private subnet in AZ 2
```
This gives your app better availability.  
**Example multi-AZ subnet design**  
Example VPC:
```text
VPC: 10.0.0.0/16
├── AZ 1
│   ├── Public subnet: 10.0.1.0/24
│   └── Private subnet: 10.0.2.0/24
│
└── AZ 2
    ├── Public subnet: 10.0.3.0/24
    └── Private subnet: 10.0.4.0/24
```
This design spreads resources across two AZs.  
So if one AZ has a problem, the other AZ can still run part of the app.

##### **What are AWS resources?**
?  
+++  
#flashcards  
`AWS resources` are services or objects created in AWS.  
Examples:
```text
EC2 instances
RDS databases
Lambda functions
Load balancers
VPCs
Subnets
Security groups
```
These are the building blocks of your AWS infrastructure.  
**Simple idea**  
A `subnet` is a smaller network inside a VPC.  
Subnets must be inside the VPC CIDR block.  
AWS reserves 5 IP addresses in every subnet.  
A subnet is public or private because of its route table.  
A public subnet has a route to the Internet Gateway.  
A private subnet does not have a direct route to the Internet Gateway.  
Use multiple AZs so your app can survive problems in one AZ.
