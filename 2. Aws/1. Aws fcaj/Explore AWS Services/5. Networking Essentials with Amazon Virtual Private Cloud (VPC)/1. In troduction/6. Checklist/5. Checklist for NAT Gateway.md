##### **What is a `Public Subnet`?**
A `public subnet` is a `subnet` that can have a direct route to an `Internet Gateway`.
Example route table:
```text
Destination: 0.0.0.0/0
Target:      Internet Gateway
```
This means traffic going to the internet can go directly through the `Internet Gateway`.
A `public subnet` is commonly used for resources that need direct internet access, such as:
```text
Load Balancer
Bastion Host
Public EC2 instance
NAT Gateway
```
##### **What is a `Private Subnet`?**
A `private subnet` is a `subnet` that does not have a direct route to an `Internet Gateway`.
Example private subnet route table:
```text
Destination: 10.0.0.0/16
Target:      local
```
This means resources in the `private subnet` can communicate inside the `VPC`, but they do not have direct internet access.
A `private subnet` is usually used for backend resources, such as:
```text
Application server
Private EC2 instance
Database
Internal service
```
This is better for security because users from the internet cannot directly connect to those resources.
##### **What is a `NAT Gateway`?**
A `NAT Gateway` is a `VPC` component that allows private resources to access the internet without allowing the internet to directly access them.
Simple idea:
```text
Private EC2 → NAT Gateway → Internet
```
The private resource can start an outbound connection to the internet.
But users from the internet cannot start a new inbound connection directly to that private resource.
##### **Why does a private `EC2` need a `NAT Gateway`?**
Imagine you have an `EC2` instance in a `private subnet`.
Because it is private, internet users cannot directly connect to it.
That is good for security.
But sometimes, that private `EC2` still needs to go out to the internet.
For example, it may need to:
```text
Download security updates
Install packages
Call an external API
Connect to some AWS services
Pull Docker images
Send logs to external services
```
Without a `NAT Gateway`, the private `EC2` may not be able to access the internet.
**How does a private `EC2` access the internet through a `NAT Gateway`?**
The private `EC2` sends internet traffic to the `NAT Gateway`.
Example:
```text
Private EC2 → NAT Gateway → Ubuntu update server
```
The `NAT Gateway` then sends the traffic to the internet on behalf of the private `EC2`.
When the internet server replies, the response comes back through the same `NAT Gateway`.
```text
Ubuntu update server → NAT Gateway → Private EC2
```
This reply is allowed because the private `EC2` started the connection first.
##### **Why can the reply come back to the private `EC2`?**
The reply is allowed because it belongs to the same connection that the private `EC2` started.
Example:
```text
Private EC2 starts connection:
Private EC2 → NAT Gateway → Ubuntu update server
Reply comes back:
Ubuntu update server → NAT Gateway → Private EC2
```
The `NAT Gateway` remembers the outbound connection.
So when the reply comes back, it knows which private `EC2` should receive the response.
##### **Why can internet users not directly connect to private `EC2` through a `NAT Gateway`?**
A `NAT Gateway` allows outbound internet access from private resources.
It does not allow new inbound connections from the internet.
Wrong idea:
```text
Internet user → NAT Gateway → Private EC2
```
This is not how `NAT Gateway` is used.
Correct idea:
```text
Private EC2 → NAT Gateway → Internet
Internet reply → NAT Gateway → Private EC2
```
The private `EC2` must start the connection first.
##### **What is the difference between `Internet Gateway` and `NAT Gateway`?**
An `Internet Gateway` is used for direct internet access.
A `NAT Gateway` is used for private outbound internet access.
```text
Public subnet:
0.0.0.0/0 → Internet Gateway
Private subnet:
0.0.0.0/0 → NAT Gateway
```
Simple comparison:
```text
Internet Gateway = direct internet road
NAT Gateway      = private outbound internet road
```
A resource using an `Internet Gateway` usually needs a `Public IP` or `Elastic IP`.
A resource using a `NAT Gateway` does not need a public IP.
##### **What is a `NAT Instance`?**
A `NAT Instance` is an `EC2` instance manually configured to perform `NAT`.
Simple idea:
```text
NAT Instance = EC2 instance used as a NAT device
```
You manage the `NAT Instance` yourself.
That means you are responsible for:
```text
Operating system updates
Security patches
Instance size
High availability
Scaling
Security Group configuration
Route table configuration
Failure recovery
```
A `NAT Instance` can be cheaper for small learning projects, but it requires more manual work.
##### **What is the difference between `NAT Gateway` and `NAT Instance`?**
A `NAT Gateway` is managed by AWS.
A `NAT Instance` is managed by you.
```text
NAT Gateway:
Managed by AWS
Highly available inside one AZ
Easier to use
Costs more
NAT Instance:
Managed by you
Runs on EC2
More control
More manual maintenance
```
For learning or very small systems, a `NAT Instance` can be used to reduce cost.
For production systems, a `NAT Gateway` is usually preferred because it is easier and more reliable.
##### **Why is `NAT Gateway` not free?**
A `NAT Gateway` is not free.
AWS charges for it mainly in two ways:
```text
1. The time the NAT Gateway is running
2. The amount of data that goes through it
```
So even if your application is small, a running `NAT Gateway` can still create cost.

**How many `NAT Gateways` should a small system use?**
For a small system, you might use one `NAT Gateway` to reduce cost.
Example:
```text
VPC
├── Public Subnet
│   └── NAT Gateway
├── Private Subnet A
│   └── Route to NAT Gateway
└── Private Subnet B
    └── Route to NAT Gateway
```
This can work for learning or small projects.
But it is not the best design for high availability.
If the `Availability Zone` that contains the `NAT Gateway` has a problem, private resources depending on that `NAT Gateway` may lose outbound internet access.
**How many `NAT Gateways` should a production system use?**
For a production system that needs high reliability, you usually deploy `NAT Gateways` in multiple `Availability Zones`.
Example:
```text
VPC
├── AZ 1
│   ├── Public Subnet 1
│   │   └── NAT Gateway 1
│   └── Private Subnet 1
│       └── 0.0.0.0/0 → NAT Gateway 1
│
└── AZ 2
    ├── Public Subnet 2
    │   └── NAT Gateway 2
    └── Private Subnet 2
        └── 0.0.0.0/0 → NAT Gateway 2
```
The reason is high availability.
If one `Availability Zone` has a problem, resources in another `Availability Zone` can still use their own `NAT Gateway`.
##### **Why should each `Availability Zone` have its own `NAT Gateway` in production?**
Each `Availability Zone` should have its own `NAT Gateway` in production because it improves reliability.
Example:
```text
Private Subnet in AZ 1 → NAT Gateway in AZ 1
Private Subnet in AZ 2 → NAT Gateway in AZ 2
```
This design avoids depending on only one `NAT Gateway`.
It also avoids sending traffic across `Availability Zones` unnecessarily.
Simple idea:
```text
Small system:
One NAT Gateway may be enough to reduce cost
Production system:
One NAT Gateway per AZ is better for high availability
```
##### **What do you need to create a `NAT Gateway`?**
To create a `NAT Gateway`, you need three important things:
```text
1. Public subnet
2. Elastic IP address
3. Route table configuration
```
The `NAT Gateway` must be placed in a `public subnet`.
It also needs an `Elastic IP`.
Then private subnet route tables must send internet traffic to the `NAT Gateway`.
##### **Why must a `NAT Gateway` be placed in a public subnet?**
A `NAT Gateway` must be placed in a `public subnet` because it needs access to the internet.
The public subnet route table should have a route like this:
```text
Destination: 0.0.0.0/0
Target:      Internet Gateway
```
This allows the `NAT Gateway` to send traffic out to the internet.
Simple idea:
```text
Private EC2 → NAT Gateway in public subnet → Internet Gateway → Internet
```
The private `EC2` does not directly use the `Internet Gateway`.
The `NAT Gateway` uses the `Internet Gateway`.
##### **Why does a `NAT Gateway` need an `Elastic IP`?**
A `NAT Gateway` needs an `Elastic IP` because it needs a public IP address to send traffic to the internet on behalf of private resources.
Example:
```text
Private EC2 private IP: 10.0.2.10
NAT Gateway Elastic IP: 54.20.30.40
```
When the private `EC2` accesses the internet, the internet sees the `Elastic IP` of the `NAT Gateway`.
```text
Private EC2 → NAT Gateway → Internet
Internet sees source IP:
54.20.30.40
```
The private `EC2` itself still does not need a public IP.
##### **What is the route table configuration for a private subnet using `NAT Gateway`?**
Private subnets need a route like this:
```text
Destination: 0.0.0.0/0
Target:      NAT Gateway
```
This means:
```text
If traffic wants to go outside the VPC,
send it to the NAT Gateway.
```
A more complete private subnet route table looks like this:
```text
Destination    Target
10.0.0.0/16    local
0.0.0.0/0      NAT Gateway
```
The first route keeps internal `VPC` traffic inside the `VPC`.
The second route sends internet traffic to the `NAT Gateway`.
##### **What is the full route design for public and private subnets?**
Example:
```text
VPC: 10.0.0.0/16
Public Subnet Route Table:
10.0.0.0/16 → local
0.0.0.0/0   → Internet Gateway
Private Subnet Route Table:
10.0.0.0/16 → local
0.0.0.0/0   → NAT Gateway
```
The `public subnet` has direct access to the `Internet Gateway`.
The `private subnet` has no direct route to the `Internet Gateway`.
Instead, the `private subnet` sends internet traffic to the `NAT Gateway`.

Example:

```text
Private EC2: 10.0.2.10
NAT Gateway Elastic IP: 54.20.30.40
```
Outbound flow:
```text
Private EC2

```
More detailed version:
```text

→ NAT Gateway

```
The internet sees the `Elastic IP` of the `NAT Gateway`, not the private IP of the `EC2`.
##### **What happens when the internet server replies?**
Example connection:
```text
Private EC2 → NAT Gateway → Ubuntu update server
```
Reply:
```text
Ubuntu update server → NAT Gateway → Private EC2
```
The reply is allowed because it is part of the same connection started by the private `EC2`.
The `NAT Gateway` tracks the connection and sends the reply back to the correct private resource.
##### **What is an important detail about the `Elastic IP`?**
The `Elastic IP` used by a `NAT Gateway` must not already be attached to another resource.
For example, it must not already be attached to:
```text
EC2 instance
NAT Instance
Another NAT Gateway
```
If the `Elastic IP` is already attached to another resource, you must detach it first.
Then you can attach it to the `NAT Gateway`.

##### **Why does a private `EC2` not need a public IP when using `NAT Gateway`?**
A private `EC2` does not need a public IP because the `NAT Gateway` has the public IP.
Example:
```text
Private EC2:
Private IP only
NAT Gateway:

```
The private `EC2` sends traffic to the `NAT Gateway`.
The `NAT Gateway` sends that traffic to the internet using its own `Elastic IP`.
Simple idea:
```text
Private EC2 uses NAT Gateway's public IP to go out
```
**Can a `NAT Gateway` replace an `Internet Gateway`?**
No.
A `NAT Gateway` does not replace an `Internet Gateway`.
The `NAT Gateway` itself still needs a route to the internet through an `Internet Gateway`.
Correct design:
```text
Private EC2
→ NAT Gateway
→ Internet Gateway
→ Internet
```
The `NAT Gateway` is placed in a `public subnet`.
That public subnet must have this route:
```text
Destination: 0.0.0.0/0
Target:      Internet Gateway
```
Without the `Internet Gateway`, the `NAT Gateway` cannot send traffic to the internet.
**Can internet users connect directly to private `EC2` through `NAT Gateway`?**
No.
Internet users cannot directly connect to private `EC2` through a `NAT Gateway`.
This is blocked by design.
Correct allowed flow:
```text

Private EC2 → NAT Gateway → Internet
```
Correct reply flow:
```text
Internet server replies
Internet → NAT Gateway → Private EC2
```
Not allowed:
```text
Internet user starts new connection
Internet user → NAT Gateway → Private EC2
```
A `NAT Gateway` is for outbound access, not direct inbound access.
