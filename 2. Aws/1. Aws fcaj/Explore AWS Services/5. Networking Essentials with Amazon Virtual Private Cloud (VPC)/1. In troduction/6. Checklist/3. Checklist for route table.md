##### **What is a `Route Table`?**
?  
+++  
#flashcards  
A `Route Table` is a set of rules that controls where network traffic goes inside a `VPC`.  
A `Route Table` is connected to a `subnet`. When resources inside that `subnet` send traffic, AWS checks the `Route Table` to decide where the traffic should go.
```text
Destination    Target
10.0.0.0/16    local
0.0.0.0/0      Internet Gateway
```
The first part is `Destination`.  
The second part is `Target`.  
`Destination` means where the traffic wants to go.  
`Target` means which AWS component should receive and forward that traffic.

#flashcards
##### **What does `Destination` mean?**
?  
+++  
#flashcards  
`Destination` means the IP range that the traffic is trying to reach.  
Example:
```text
10.0.0.0/16
```
This means the traffic is going to an IP address inside the `VPC`.  
Another example:
```text
0.0.0.0/0
```
This means all other traffic, usually traffic going to the internet or outside the `VPC`.  
?  
+++  
#flashcards
##### **What does `Target` mean?**
?  
+++  
#flashcards  
`Target` means where AWS should send the traffic.  
Example:
```text
Destination: 10.0.0.0/16
Target:      local
```
Here, `local` means the traffic stays inside the same `VPC`.  
Another example:
```text
Destination: 0.0.0.0/0
Target:      Internet Gateway
```
Here, `Internet Gateway` means the traffic goes to the internet through the `Internet Gateway`.

##### **What is the `local` route?**
?  
+++  
#flashcards  
When you create a `VPC`, AWS automatically creates a `local` route.  
Example `VPC` CIDR block:
```text
10.0.0.0/16
```
AWS automatically creates this route:
```text
Destination: 10.0.0.0/16
Target:      local
```
This route allows resources inside the same `VPC` to communicate with each other.  
?

#flashcards
##### **Why does AWS create the `local` route automatically?**
?  
+++  
#flashcards  
AWS creates the `local` route so that all resources inside the same `VPC` can talk to each other.  
Example:
```text
VPC CIDR: 10.0.0.0/16
EC2 A: 10.0.1.10
EC2 B: 10.0.2.20
```
`EC2 A` and `EC2 B` are in the same `VPC`.  
Even if they are in different `subnets`, they can still communicate because of this route:
```text
Destination: 10.0.0.0/16
Target:      local
```
This means traffic between `10.0.1.10` and `10.0.2.20` stays inside the `VPC`.  
?  
+++  
#flashcards
##### **What does `local` mean?**
?  
+++  
#flashcards  
`local` means inside the same `VPC`.
```text
Destination: 10.0.0.0/16
Target:      local
```
This route tells AWS:
```text
If the destination IP is inside 10.0.0.0/16,
keep the traffic inside the VPC.
```
You do not need to create this route yourself.  
AWS creates it automatically.  
You also cannot delete or change the `local` route.

##### **How does a public subnet use a `Route Table`?**
?  
+++  
#flashcards  
A `public subnet` has a route to an `Internet Gateway`.  
Example:
```text
Destination: 10.0.0.0/16
Target:      local
Destination: 0.0.0.0/0
Target:      Internet Gateway
```
The first route allows traffic inside the `VPC`.  
The second route allows traffic to go outside the `VPC`, usually to the internet.  
Because the `public subnet` has this route:
```text
Destination: 0.0.0.0/0
Target:      Internet Gateway
```
It can be called a `public subnet`.  
?  
+++  
#flashcards
##### **What does `0.0.0.0/0` mean?**
?  
+++  
#flashcards  
`0.0.0.0/0` means everywhere else.
```text
Destination: 0.0.0.0/0
Target:      Internet Gateway
```
This usually means:
```text
Traffic that is not inside the VPC
goes to the Internet Gateway.
```
For example, if an `EC2` instance wants to access:
```text
google.com
github.com
docker.com
```
That traffic is outside the `VPC`, so it matches this route:
```text
0.0.0.0/0
```

##### **What is an `Internet Gateway`?**
?  
+++  
#flashcards  
An `Internet Gateway` is a `VPC` component that allows resources in a `public subnet` to access the internet.
```text
Public Subnet
Route Table:
10.0.0.0/16 → local
0.0.0.0/0   → Internet Gateway
```
The `Internet Gateway` works like an internet road for your `VPC`.  
Without an `Internet Gateway`, resources in the `VPC` cannot directly access the internet.  
?  
+++  
#flashcards
##### **Why is a subnet called public?**
?  
+++  
#flashcards  
A `subnet` is called public when its `Route Table` has a route to an `Internet Gateway`.
```text
Destination: 0.0.0.0/0
Target:      Internet Gateway
```
Simple idea:
```text
Public subnet = has direct internet road
```
However, for an `EC2` instance to actually be reachable from the internet, it also needs other things, such as:
```text
Public IP address
Security Group allowing traffic
Network ACL allowing traffic
Correct route table
```
So the `Route Table` is important, but it is not the only requirement.

##### **How does a private subnet use a `Route Table`?**
?  
+++  
#flashcards  
A `private subnet` does not have a direct route to an `Internet Gateway`.  
Basic private subnet example:
```text
Destination: 10.0.0.0/16
Target:      local
```
This means resources in the `private subnet` can talk to resources inside the same `VPC`.  
But they do not have direct internet access.

##### **What does a private subnet route look like with a `NAT Gateway`?**
?  
+++  
#flashcards  
If a private subnet needs to access the internet for updates or downloads, it can use a `NAT Gateway`.  
Example:
```text
Destination: 10.0.0.0/16
Target:      local
Destination: 0.0.0.0/0
Target:      NAT Gateway
```
This allows resources in the `private subnet` to go out to the internet.  
But the internet cannot directly start a connection back to those private resources.  
?  
+++  
#flashcards
##### **Why use a `NAT Gateway` for a private subnet?**
?  
+++  
#flashcards  
A `NAT Gateway` allows private resources to access the internet without making them directly public.  
Example use cases:
```text
EC2 in private subnet downloads package updates
Spring Boot backend connects to external API
Private server pulls Docker image
Private service sends logs to external service
```
The private resource can go out.  
But outside users cannot directly connect to it.

##### **What is the difference between `Internet Gateway` and `NAT Gateway`?**
?  
+++  
#flashcards  
An `Internet Gateway` is used by a `public subnet`.  
A `NAT Gateway` is usually used by a `private subnet`.
```text
Public Subnet:
0.0.0.0/0 → Internet Gateway
Private Subnet:
0.0.0.0/0 → NAT Gateway
```
Simple explanation:
```text
Internet Gateway = direct internet access
NAT Gateway      = private outbound internet access
```

##### **What route does AWS automatically create when you create a `VPC`?**
?  
+++  
#flashcards  
When you create a `VPC`, AWS automatically creates this route:
```text
Destination: 10.0.0.0/16
Target:      local
```
This route lets resources inside the `VPC` talk to each other.  
This works even when resources are in different `subnets`.  
For example:
```text
EC2 A in public subnet:  10.0.1.10
EC2 B in private subnet: 10.0.2.20
```
They can communicate through the `local` route, as long as `Security Group` and `Network ACL` rules allow it.  
**Can you delete the `local` route?**  
No.  
You cannot delete or change the AWS-created `local` route.
```text
Destination: 10.0.0.0/16
Target:      local
```
AWS keeps this route because it is required for communication inside the `VPC`.  
**Does every subnet need a `Route Table`?**  
Yes.  
Every `subnet` must use one `Route Table`.  
A `subnet` cannot exist without being associated with a `Route Table`.

##### **What happens if you do not choose a `Route Table` for a subnet?**
?  
+++  
#flashcards  
If you do not manually choose a `Route Table` for a `subnet`, AWS automatically connects that `subnet` to the `main route table`.
```text
Subnet without manual route table association
→ uses main route table
```
So the `main route table` is the default route table for subnets that do not have their own explicit route table association.  
?  
+++  
#flashcards
##### **What is the `main route table`?**
?  
+++  
#flashcards  
The `main route table` is the default `Route Table` of a `VPC`.  
When a new `VPC` is created, AWS creates a `main route table`.  
If a `subnet` is not manually associated with another `Route Table`, it uses the `main route table`.
```text
VPC
├── Main Route Table
├── Public Subnet  → custom public route table
└── Private Subnet → main route table if no custom table is selected
```
It is better to create separate route tables for public and private subnets so the design is clear.

##### **How to remember public and private subnet routes?**
?  
+++  
#flashcards  
Use this simple rule:
```text
Public subnet:
0.0.0.0/0 → Internet Gateway
Private subnet:
No direct route to Internet Gateway
Private subnet with outbound internet:
0.0.0.0/0 → NAT Gateway
```
So:
```text
Public subnet  = direct internet road
Private subnet = no direct internet road
NAT Gateway    = private subnet can go out, but internet cannot directly come in
```
**Simple idea**  
A `Route Table` tells AWS where network traffic should go.
```text
10.0.0.0/16 → local
```
This means traffic inside the `VPC` stays inside the `VPC`.
```text
0.0.0.0/0 → Internet Gateway
```
This means traffic goes directly to the internet.
```text
0.0.0.0/0 → NAT Gateway
```
This means private resources can go out to the internet without becoming directly public.  
The easiest way to remember it:
```text
Route Table = traffic map
Destination = where traffic wants to go
Target      = where AWS sends the traffic
local       = inside the VPC
IGW         = direct internet road
NAT Gateway = private outbound internet road
```
