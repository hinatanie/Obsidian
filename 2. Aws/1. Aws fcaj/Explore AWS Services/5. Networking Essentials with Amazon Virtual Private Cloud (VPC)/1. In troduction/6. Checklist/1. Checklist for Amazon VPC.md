##### **What is Amazon VPC?**
?  
+++  
#flashcards  
`Amazon VPC` means `Amazon Virtual Private Cloud`.
Amazon VPC lets you create your own private, controlled, and secure network inside AWS.  
Normally, if you run servers in a company data center, you need to design the network yourself.
For example:
```
IP addresses
Subnets
Routing
Gateways
Security
```
Amazon VPC gives you the same kind of control, but inside the AWS Cloud.
**Simple idea**  
A `VPC` is like your own private network inside AWS.  
Inside that network, you can run resources like:
```
EC2 servers
Databases
Load balancers
Containers
```
You control how those resources connect to each other and to the internet.  
?

#flashcards
##### **What is a VPC CIDR block?**
?  
+++  
#flashcards  
When you create a VPC, you choose an IP address range.  
For example:
```
10.0.0.0/16
```
This range is called a `CIDR block`.  
The CIDR block decides what private IP addresses can exist inside your VPC.  
?  
+++  
#flashcards
##### **What does `10.0.0.0/16` mean?**
?  
+++  
#flashcards
```
10.0.0.0/16
```
This means your VPC can use IP addresses from the `10.0.x.x` range.  
For example:
```
10.0.1.10
10.0.2.25
10.0.100.50
```
A `/16` CIDR block gives a large number of IP addresses.  
?  
+++  
#flashcards
##### **Can you change the main VPC CIDR block later?**
?  
+++  
#flashcards  
After you create the VPC, the main CIDR block cannot be changed.  
So you should choose it carefully.  
For example, if you create your VPC with:
```
10.0.0.0/16
```
That becomes the primary IP range for the VPC.  
?

#flashcards
##### **What is a subnet?**
?  
+++  
#flashcards  
A `subnet` is a smaller network inside a VPC.  
You divide a VPC into subnets to organize resources.  
For example, you may create:
```
Public subnet
Private subnet
```
A public subnet can be used for web servers.  
A private subnet can be used for databases.  
**Example VPC and subnet design**  
Your VPC may use:
```
10.0.0.0/16
```
Then you divide it into smaller subnets:
```
10.0.1.0/24    Public subnet
10.0.2.0/24    Private subnet
```
The VPC is the big network.  
The subnets are smaller parts inside that network.  
?  
+++  
#flashcards
##### **What is a public subnet?**
?  
+++  
#flashcards  
A `public subnet` is a subnet that can connect to the internet through an `Internet Gateway`.  
You usually put internet-facing resources here.  
For example:
```
Web server
Load balancer
Bastion host
```
?  
+++  
#flashcards
##### **What is a private subnet?**
?  
+++  
#flashcards  
A `private subnet` is a subnet that is not directly reachable from the public internet.  
You usually put internal resources here.  
For example:
```
Database
Private backend service
Internal application server
```
Private resources can still access the internet through a `NAT Gateway`, but the internet cannot directly access them.

##### **Does a VPC belong to one AWS Region?**
?  
+++  
#flashcards  
Yes.  
A VPC belongs to one AWS Region.  
For example, if you create a VPC in the Singapore Region, it exists only in that Region.  
You can create multiple VPCs in the same Region.

##### **What does CIDR block size mean?**
?  
+++  
#flashcards  
The CIDR block size controls how many IP addresses your VPC can have.  
For example:
```
/16 means 65,536 IP addresses
/28 means 16 IP addresses
```
A smaller number after `/` means a bigger network.  
A bigger number after `/` means a smaller network.  
?  
+++  
#flashcards
##### **Why should VPC CIDR blocks not overlap?**
?  
+++  
#flashcards  
Your VPC CIDR block should not overlap with other networks.  
This is very important when you connect your VPC to another network.  
For example:
```
Company office network
AWS VPC
VPN network
Another VPC
```
If the IP ranges overlap, routing becomes confusing.  
**Example of overlapping CIDR problem**  
Imagine your company network uses:
```
10.0.0.0/16
```
Then your AWS VPC should not also use:
```
10.0.0.0/16
```
Because when traffic wants to go to:
```
10.0.1.20
```
The system becomes confused.
```
Is 10.0.1.20 in the office network\?**
?
Or is 10.0.1.20 inside the AWS VPC\?**
?
```
So you should choose a different CIDR block for your VPC.  
For example:
```
10.10.0.0/16
```
or:
```
172.16.0.0/16
```

##### **What came before Amazon VPC?**
?  
+++  
#flashcards  
Amazon VPC came after Amazon EC2.  
In the past, AWS had two networking models:
```
EC2-Classic
EC2-VPC
```
?  
+++  
#flashcards
##### **What was EC2-Classic?**
?  
+++  
#flashcards  
`EC2-Classic` was the old AWS networking model.  
In this model, resources used a shared, flat network.  
That means EC2 instances were not running inside your own private VPC.  
Many AWS customers used the shared AWS network model.  
?  
+++  
#flashcards
##### **What is EC2-VPC?**
?  
+++  
#flashcards  
`EC2-VPC` is the current AWS networking model.  
In this model, resources run inside isolated virtual networks.  
That virtual network is your VPC.  
This is more secure and gives you more control.  
?  
+++  
#flashcards
##### **What is the default VPC?**
?  
+++  
#flashcards  
AWS creates a default VPC in each Region.  
The default VPC uses this CIDR block:
```
172.31.0.0/16
```
The default VPC is useful for learning and quick testing.  
**Should you use the default VPC for production?**  
?  
For real production systems, it is usually better to create a custom VPC.  
A custom VPC gives you better control over:
```
IP ranges
Subnets
Routing
Gateways
Security
Network architecture
```
**Important VPC components**  
There are four important VPC components:

```
Internet Gateway
NAT Gateway
```
These components help control how traffic moves inside and outside your VPC.

##### **What is a route table?**
?  
+++  
#flashcards  
A `route table` is a set of rules that tells network traffic where to go.  
For example, a route table can say:
```
Traffic to the internet → Internet Gateway
Traffic inside VPC → local route
Traffic to private network → VPN Gateway
```
Route tables control network paths.  
?  
+++  
#flashcards
##### **What is a gateway?**
?  
+++  
#flashcards  
A `gateway` is a connection point between networks.  
In AWS, gateways help your VPC connect to:
```
The internet
Another private network
An on-premises network
```
?  
+++  
#flashcards
##### **What is an Internet Gateway?**
?  
+++  
#flashcards  
An `Internet Gateway` is a VPC component that allows resources in public subnets to access the internet.  
It also allows internet traffic to reach public resources in your VPC.  
For example, a public EC2 web server needs an Internet Gateway to be reachable from the internet.  
?  
+++  
#flashcards
##### **What is a NAT Gateway?**
?  
+++  
#flashcards  
A `NAT Gateway` allows private resources to access the internet without allowing the internet to directly access them.  
For example, an EC2 instance in a private subnet may need to download software updates.  
It can use a NAT Gateway for outbound internet access.  
But people from the internet cannot directly connect to that private EC2 instance.  
?  
+++  
#flashcards
##### **What is a Virtual Private Gateway?**
?  
+++  
#flashcards  
`Virtual Private Gateway`, or `VGW`, is a gateway used to connect a VPC to another private network.  
It is often used with a VPN connection to connect AWS to an on-premises network.  
For example:
```
Company office network → VPN → Virtual Private Gateway → AWS VPC
```

?  
+++  
#flashcards

**Simple VPC example**  
A common VPC design looks like this:
```
VPC: 10.0.0.0/16
├── Public subnet: 10.0.1.0/24
│   ├── Web server
│   └── Load balancer
│
├── Private subnet: 10.0.2.0/24
│   ├── Backend server
│   └── Database
│
├── Internet Gateway
│   └── Allows public subnet to access the internet
│
└── NAT Gateway
    └── Allows private subnet to access the internet
```
**Simple idea**  
A `VPC` is your private network inside AWS.  
A `CIDR block` is the IP range of the VPC.  
A `subnet` is a smaller network inside the VPC.  
A `route table` controls where traffic goes.  
An `Internet Gateway` lets public resources connect to the internet.  
A `NAT Gateway` lets private resources access the internet safely.  
For production, you usually create a custom VPC instead of only using the default VPC.
