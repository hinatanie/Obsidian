
##### **What is Amazon VPC\?**
`Amazon VPC` means `Amazon Virtual Private Cloud`.  

Amazon VPC lets you create your own private, controlled, and secure network inside AWS.  
Normally, if you run servers in a company data center, you need to design the network yourself.
 
For example:
```text
IP addresses
Subnets
Routing
Gateways
Security
```
Amazon VPC gives you the same kind of control, but inside the AWS Cloud.
 
**Simple idea**  
A `VPC` is like your own private network inside AWS.  
Inside that network, you can run resources like:
```text
EC2 servers
Databases
Load balancers
Containers
```
You control how those resources connect to each other and to the internet.

##### **What is a VPC CIDR block\?**
When you create a VPC, you choose an IP address range.  
For example:
```text
10.0.0.0/16
```
This range is called a `CIDR block`.  
The CIDR block decides what private IP addresses can exist inside your VPC.


##### **What does `10.0.0.0/16` mean\?**
```text
10.0.0.0/16
```
This means your VPC can use IP addresses from the `10.0.x.x` range.  
For example:
```text
10.0.1.10
10.0.2.25
10.0.100.50
```
A `/16` CIDR block gives a large number of IP addresses.
##### **Can you change the main VPC CIDR block later\?**
After you create the VPC, the main CIDR block cannot be changed.  
So you should choose it carefully.  
For example, if you create your VPC with:
```text
10.0.0.0/16
```
That becomes the primary IP range for the VPC.
##### **What is a subnet\?**
A `subnet` is a smaller network inside a VPC.  
You divide a VPC into subnets to organize resources.  
For example, you may create:
```text
Public subnet
Private subnet
```
A public subnet can be used for web servers.  
A private subnet can be used for databases.
**Example VPC and subnet design**  
Your VPC may use:
```text
10.0.0.0/16
```
Then you divide it into smaller subnets:
```text
10.0.1.0/24    Public subnet
10.0.2.0/24    Private subnet
```
The VPC is the big network.  
The subnets are smaller parts inside that network.


##### **What is a public subnet\?**
A `public subnet` is a subnet that can connect to the internet through an `Internet Gateway`.  
You usually put internet-facing resources here.  
For example:
```text
Web server
Load balancer
Bastion host
```


##### **What is a private subnet\?**
A `private subnet` is a subnet that is not directly reachable from the public internet.  
You usually put internal resources here.  
For example:
```text
Database
Private backend service
Internal application server
```
Private resources can still access the internet through a `NAT Gateway`, but the internet cannot directly access them.
##### **Does a VPC belong to one AWS Region\?**
Yes.  
A VPC belongs to one AWS Region.  
For example, if you create a VPC in the Singapore Region, it exists only in that Region.  
You can create multiple VPCs in the same Region.
##### **What does CIDR block size mean\?**
The CIDR block size controls how many IP addresses your VPC can have.  
For example:
```text
/16 means 65,536 IP addresses
/28 means 16 IP addresses
```
A smaller number after `/` means a bigger network.  
A bigger number after `/` means a smaller network.



##### **Why should VPC CIDR blocks not overlap\?**
Your VPC CIDR block should not overlap with other networks.  
This is very important when you connect your VPC to another network.  
For example:
```text
Company office network
AWS VPC
VPN network
Another VPC
```
If the IP ranges overlap, routing becomes confusing.
**Example of overlapping CIDR problem**  
Imagine your company network uses:
```text
10.0.0.0/16
```
Then your AWS VPC should not also use:
```text
10.0.0.0/16
```
Because when traffic wants to go to:
```text
10.0.1.20
```
The system becomes confused.
```text
Is 10.0.1.20 in the office network\?**
?
Or is 10.0.1.20 inside the AWS VPC\?**
?
```
So you should choose a different CIDR block for your VPC.  
For example:
```text
10.10.0.0/16
```
or:
```text
172.16.0.0/16
```


##### **What came before Amazon VPC\?**
Amazon VPC came after Amazon EC2.  
In the past, AWS had two networking models:
```text
EC2-Classic
EC2-VPC
```


##### **What was EC2-Classic\?**
`EC2-Classic` was the old AWS networking model.  
In this model, resources used a shared, flat network.  
That means EC2 instances were not running inside your own private VPC.  
Many AWS customers used the shared AWS network model.


##### **What is EC2-VPC\?**
`EC2-VPC` is the current AWS networking model.  
In this model, resources run inside isolated virtual networks.  
That virtual network is your VPC.  
This is more secure and gives you more control.


##### **What is the default VPC\?**
AWS creates a default VPC in each Region.  
The default VPC uses this CIDR block:
```text
172.31.0.0/16
```
The default VPC is useful for learning and quick testing.
**Should you use the default VPC for production\?**
?  
For real production systems, it is usually better to create a custom VPC.  
A custom VPC gives you better control over:
```text
IP ranges
Subnets
Routing
Gateways
Security
Network architecture
```
**Important VPC components**  
There are four important VPC components:
```text
Subnet
Route table
Internet Gateway
NAT Gateway
```
These components help control how traffic moves inside and outside your VPC.

##### **What is a subnet\?**
A `subnet` is a smaller network inside a VPC.
You use subnets to organize resources.
For example:
```text
Public subnet for web servers
Private subnet for databases
```
##### **What is a route table\?**
A `route table` is a set of rules that tells network traffic where to go.  
For example, a route table can say:
```text
Traffic to the internet → Internet Gateway
Traffic inside VPC → local route
Traffic to private network → VPN Gateway
```
Route tables control network paths.


##### **What is a gateway\?**
A `gateway` is a connection point between networks.  
In AWS, gateways help your VPC connect to:
```text
The internet
Another private network
An on-premises network
```


##### **What is an Internet Gateway\?**
An `Internet Gateway` is a VPC component that allows resources in public subnets to access the internet.  
It also allows internet traffic to reach public resources in your VPC.  
For example, a public EC2 web server needs an Internet Gateway to be reachable from the internet.


##### **What is a NAT Gateway\?**
A `NAT Gateway` allows private resources to access the internet without allowing the internet to directly access them.  
For example, an EC2 instance in a private subnet may need to download software updates.  
It can use a NAT Gateway for outbound internet access.  
But people from the internet cannot directly connect to that private EC2 instance.

##### **What is a Virtual Private Gateway\?**
`Virtual Private Gateway`, or `VGW`, is a gateway used to connect a VPC to another private network.
It is often used with a VPN connection to connect AWS to an on-premises network.
For example:
```text
Company office network → VPN → Virtual Private Gateway → AWS VPC
```
##### **What is IPv4\?**
`IPv4` is the older and most common IP address system.  
Example IPv4 address:
```text
192.168.1.1
```
Most common private network ranges use IPv4.

##### **What is IPv6\?**
`IPv6` is a newer IP address system with a much larger address space.
IPv6 addresses are longer than IPv4 addresses.
##### **What is a primary CIDR block\?**
A `primary CIDR block` is the main IP address range assigned to a VPC when it is created.  
Example:
```text
10.0.0.0/16
```
This is the main private IP range for the VPC.

##### **What is a CIDR block\?**
A `CIDR block` is an IP address range.
It can be used by:
```text
VPC
Subnet
Network
```
Example:
```text
10.0.0.0/16
```
or:
```text
10.0.1.0/24
```

##### **What is an on-premises network\?**
An `on-premises network` is a company's own physical network outside the cloud.  
For example, your company may have:
```text
Office building
├── Routers
├── Switches
├── Servers
└── Computers
```
This network is managed by the company, not by AWS.


##### **What is Amazon EC2\?**
`Amazon EC2` is a service that lets you create and run virtual servers in AWS.  
An EC2 instance is like a server in the cloud.  
You can install applications, databases, or backend services on it.


##### **What is a flat network\?**
A `flat network` is a simple network without strong separation between different parts.  
In a flat network, many resources may exist in the same network area.  
This gives less control compared to a properly designed VPC with subnets and routing.

##### **What is a shared network\?**
A `shared network` is a network used by many customers or systems together.
EC2-Classic used a shared network model in the past.
VPC is better because it gives each customer isolated network control.
##### **What is subnet sizing\?**
`Subnet sizing` means choosing how large a subnet should be.  
You choose the subnet size by selecting a CIDR block.  
For example:
```text
10.0.1.0/24
```
A `/24` subnet gives 256 IP addresses.  
You should choose subnet sizes carefully so you have enough IP addresses for your resources.


##### **What is external internet traffic\?**
`External internet traffic` is traffic coming from outside AWS.  
For example:
```text
User browser → Internet → Your public web server in AWS
```
This is inbound traffic from the public internet.

##### **What is internet-bound traffic\?**
`Internet-bound traffic` is traffic going to the internet.
For example:
```text
Private EC2 instance → NAT Gateway → Internet
```
This is outbound traffic from your VPC to the internet.

##### **What is network architecture\?**
`Network architecture` is the overall design of how your network is organized.  
It includes:
```text
VPCs
Subnets
Route tables
Gateways
Security groups
CIDR blocks
Traffic flow
```
Good network architecture makes your system more secure and easier to manage.


##### **What is a VPC component\?**
A `VPC component` is a networking part inside or attached to a VPC.  
Examples:
```text
Subnet
Route table
Internet Gateway
NAT Gateway
Security group
Network ACL
```


##### **What is a private IP address\?**
A `private IP address` is an internal IP address used inside a private network.  
Example:
```text
10.0.1.20
```
Private IP addresses are used for communication inside the VPC.  
They are not directly reachable from the public internet.


##### **What is a public IP address\?**
A `public IP address` is an IP address that can be used on the public internet.  
If an EC2 instance has a public IP address and the correct routing/security settings, people from the internet can reach it.

##### **What is an Elastic IP address\?**
An `Elastic IP address` is a static public IP address that you can allocate in AWS and attach to resources.
Unlike a normal public IP address, an Elastic IP can stay the same.
For example, you can attach it to an EC2 instance or a NAT Gateway.

##### **What is source IP\?**
`Source IP` is the IP address where traffic comes from.  
For example:
```text
User IP → Web server
```
The user's IP address is the source IP.

##### **What is Network Address Translation\?**
`Network Address Translation`, or `NAT`, means changing one IP address into another IP address when traffic moves between networks.
For example, a private EC2 instance may use a NAT Gateway to access the internet.
The internet sees the NAT Gateway's public IP address, not the private EC2 instance's private IP address.
##### **What is outbound traffic\?**
`Outbound traffic` is traffic going out from your VPC to the internet or another network.
Example:
```text
EC2 instance → Internet
```
##### **What is inbound traffic\?**
`Inbound traffic` is traffic coming into your VPC from the internet or another network.  
Example:
```text
Internet user → Public web server
```


##### **What are data transfer rates\?**
`Data transfer rates` are costs charged based on how much data moves in or out.  
For example, AWS may charge for data transfer from your VPC to the internet.


##### **What are bandwidth constraints\?**
`Bandwidth constraints` are limits on how much network traffic can pass through.  
For example, some resources or network paths may have limits on traffic speed or volume.


##### **What is a NAT Instance\?**
A `NAT Instance` is an EC2 instance manually configured to perform NAT.  
You manage it yourself.  
Compared with a NAT Gateway, a NAT Instance gives more control but requires more maintenance.


##### **What is a protocol\?**
A `protocol` is a communication method.  
Examples:
```text
HTTP
HTTPS
TCP
UDP
ICMP
SSH
```
Protocols define how computers communicate with each other.
**Simple VPC example**  
A common VPC design looks like this:
```text
VPC: 10.0.0.0/16
├── Public subnet: 10.0.1.0/24
│   ├── Web server
│   └── Load balancer
│
├── Private subnet: 10.0.2.0/24
│   ├── Backend server
│   └── Database
│
├── Internet Gateway
│   └── Allows public subnet to access the internet
│
└── NAT Gateway
    └── Allows private subnet to access the internet
```
**Simple idea**  
A `VPC` is your private network inside AWS.  
A `CIDR block` is the IP range of the VPC.  
A `subnet` is a smaller network inside the VPC.  
A `route table` controls where traffic goes.  
An `Internet Gateway` lets public resources connect to the internet.  
A `NAT Gateway` lets private resources access the internet safely.  
For production, you usually create a custom VPC instead of only using the default VPC.
