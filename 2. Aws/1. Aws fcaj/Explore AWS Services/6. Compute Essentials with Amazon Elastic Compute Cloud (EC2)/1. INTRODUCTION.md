### Amazon Elastic Compute Cloud (EC2)
EC2 gives you computing power when you need it

For example, you can use EC2 to run
```
A website
A backend API
A database
An authentication service
A business application
A testing server
```

With EC2, you can control several important things
```
How many servers you want
How many CPU and memery they need
Which network they belong to
Which Security Group protects them
Which storage volumn they use
How users authenticate to connect
```
So EC2 is flexible like a normal server, but much faster to create and manage

---
A traditional server usually requires physical hardware
You may need to 
```
By the server
Wait for delivery
Install operating system
Configure networking
Maintain hardware
Replace broken parts
```
With EC2, AWS handles the physical infrastructure. You just choose the type of virtual server you want and lauch it
That is why EC2 can reducre hardware cost and speed up development

The EC2 instance is placed inside a **VPC**.

A VPC is like your private network in AWS

Inside the VPC, the EC2 instance runs in an Availability Zone

An Availability Zon is like a seperate data center area inside a Region

---
The EC2 instance is protected by Security Group

The Security Group works like a firewall for EC2
```
Allow SSH port 22 from your IP
Allow HTTP port 88 from everyone
Allow HTTPS port 443 from everyone
```
Without the correct Security Group rules, users may not be able to access your EC2 instance

The EC2 instance uses a key pair for authentication
For Linux EC2 instances, you usually connect with SSH
```
ssh -i my-key.pem ec2-user@pulic-ip
```
---
An EC2 instance usually has an EBS volume attached
You can think of EBS as the hard drive/dish of EC2 instance and EC2 is like a computer

The EBS volume stores things like
```
Operating system
Application files
Logs
Database files
Configuration files
```

EBS provides persistent storage
That means the data can remain even if EC2 instance stops or restarts

---
There are two important things when creating an EC2 instance: **Instance types** and **storage options**

**EC2 instance type** decides how powerful your virtual server is. For example, it controls how much CPU, RAM , storage performance, and network speed the server has 

You choose type based on your application
**C-family** instances are good when your application needs strong CPU power. This is usefult for batch processing or heavy calculations

**R-family** instances are good when your application needs a lot of memory. This is common for databases

**T and M families** are general-purpose. They are good when you need a balanced amount of CPU, RAM, and network performance

### Amazon Machine Images (AMI) and EC2 Storage Options
An AMI (Amazon Machine Image) is like a saved template for creating EC2 instance. It usually contains the operating system, installed software, configuration, permissions, and storage settings

For example, instead of installing Ubuntu, Java, Nginx, and your app manually every time, you can create an AMI. Then, every new EC2 instance launched from that AMI will already have those things prepared

There are three common AMI types
**AWS-provided AMIs**, such as basic Linux or Window images

**AWS Marketplace AMIS** which may already include software like databases, monitoring tools, or application servers

**Custom AMIs** which you create from your own EC2 instance

**EBS volumes** are persistent. This means your data remains even if the EC2 instance is stopped. **EBS** is safer choice for important data, such as databases, uploaded files, logs, or application data. 

**Instance store volumns** are temporary. They are physically attached to the host machine, so they can be fast, but they are not safe for long-term storage. If the instance is stopped or terminated, the data can be lost

Use EBS for important data.
Use instance store only for temporary data, cache, or data you can recreate

### Security and Access Management
**When you create an EC2 instance**, you need a safe way to connect to it and control traffic. AWS provides several tools for this

A **key pair** is used when you connect to an EC2 instance by SSH. 
For example, when you connect to a Linux EC2 server, 
AWS checks your private key to confirm that you are allowed to access the instance. 
The private key is very important, so you should never share it

A **security group** works like a firewall for an EC2 instance. It controls what traffic can enter and leave the instance.
For example, if you want users to access a website on EC2, you may allow inbound traffic on port 80 or 443

A **Network ACL** is also a firewall, but it works at the subnet level, not the instance level. The important difference is that Network ACLs are stateless. This means they check inbound and outbound separately

An **IAM role** is used to give permissions to applications running on EC2. For example, instead of storing AWS access keys inside your application, you can attach an IAM role to the EC2 instance. Then the application can access services like S3 or CloudWatch securely

**AWS Systems Manager Session Manager** is a safer way to access EC2 because you do not need to open SSH or RDP ports to the internet. You also do not need to distribute private key files

### Elastic Infrastructure
Elastic Infrastructure introduces the main features of EC2

**Elastic Infrastructure** means EC2 can grow or shrink based on demand. 
If your website has more users, **Auto Scaling** can add more EC2 instances. If traffic decreases, it can remove unnecessary instances to save cost

**Elastic Load Balancing** helps distribute traffic across many EC2 instances. This improves performance and availability because one instance does not have to handle all requests.

---
### Networking Capabilities
Networking Capabilities explains that EC2 runs inside a VPC, which is your private network in AWS. You can control IP ranges, subnets, routing, gateways, and security rules

An **Elastic IP Address** is a static public IPv4 address. It is useful when you need a fixed public IP address for an instance. However, AWS may charge you if the Elastic IP is not attached to a running instance, so you should release unused Elastic IPs

**Placement Groups** help control where instances are placed. This can improve performace or availability depending on your application needs

---
### High Availability Options
The high availability section explains how to make applications more reliable

Using **multiple Availability Zones** helps to protect your application if one data center has a problem.
For example, if your application runs in two Availability Zones, it may continue working even if one zone fails

**Local Zones** are useful when you need low latency near users in certain cities or population centers

**AWS Outposts** is for hybrid cloud. It lets you run AWS infrastructure inside your own data center

**Wavelength Zones** are designed for applications that need extremely low latency over 5G networks, such as real-time gaming, video processing, or IoT applications

---
### Resource Management
The **Resource Management** section explains how to organize EC2 resources

**Tags** are labels you attach to resources.
For example, you can tag an EC2 instance with `Project = HotelBooking` or `Environment = Production`. This helps with organization and billing

**Resource Groups**  help you manage related resources together

**CloudFormation** lets you define infrastructure using code. Instead of manually creating EC2, VPC, security groups, and load balacers, you can write a template and deploy the same setup many times

---
### Monitoring and Management
The **Monitoring and Management** introduces three important AWS services

**CloudWatch** monitors performance, such as CPU usage, memory, logs, and alarms

**CloudTrail** records AWS API calls. This is useful for security because you can see who did what in your AWS account

**Systems Manager** helps manage many EC2 instances at scale.
For example, you can run commands, patch systems, or access instances without SSH

**CPU** is Central Processing Unit. It handles general computing tasks and runs application logic

**GPU** is Graphics Processing Unit. It is useful for graphics, machine learning, video processing, and parallel computing workloads

**Memory/Ram** is Temporary working memory used by applications while they are running

**Volumn** is a storage unit that can be attached to an EC2 instance

**Amazon EBS** is Elastic Block Store. A persistent block storage service for EC2 instances

**Terminated** is the state when an EC2 instance is permanently deleted

**Instance store volumn** is temporary storage physically attached to the host machine running the EC2 instace

**Instance lifecycle** is the stages of an EC2 instance, such as lauching, running, stopped, and terminated

**Network-attached storage** is storage connected to an instance over the network rather than physically inside the same machine

**Amazon Machine Image, AMI** is a template used to lauch EC2 instance. It includes the OS, software, settings and the storage mapping

**Memory-optimized instance** is an EC2 instance family designed for tasks that need a large amount of RAM, such as databases

**Compute-optimized instance** is an EC2 instance family design for tasks that need strong CPU performance

**Instance type** is a predefined hardware configuration for an EC2 virtual server. It decides CPU, memory, storage, and network capacity

**Key pair** is a pair of cryptographic keys: one public key and one private key. 
In EC2, it is commonly used for SSH access

**Public key** is a key that can be shared and is placed on the EC2 instance

**Private key** is a secret key stored by the user. It is used to prove identity when connecting to an EC2 instance

**IAM role** is an AWS identity with permissions that can be attached to AWS services, such as EC2, so application can access other resources securely

**RDP** is Remote Desktop Protocol. A protocol used to remotely access Windows servers

**Permission** is the right to perform an action, such as reading an S3 bucket or writing to a database

**Elastic infrastructure** is an infrastructure that can automatically grow or shrink based on demand

**AWS Systems Manager Session Manager** is a service that allows secure access to EC2 instances without opening SSH or RDP ports

**Amazon EC2 Auto Scaling** is a service that automatically adds or removes EC2 instances based on demand

**Elastic Load Balancing** is a service that distributes traffic across multiple targets, such as EC2 instances

**Elastic IP Address** is a static public IPv4 address that can be associated with an AWS resource

**Static IP address** is an IP address that does not change automatically

**High Availability** is a design approach that keeps an application running even if some components fail

**Fault tolerance** is the ability of a system to continue working even when part of it fails

**Low latency** is a short delay between a request and a response

**AWS Outposts** is AWS infrastructure installed in your own data center for hybrid cloud use

**Hybrid deployment** is a setup that combines cloud infrastructure with on-premises infrastructure

**Wavelength Zone** is AWS infrastructure located at the edge of 5G networks for ultra-low latency applications

**Edge** is a location closer to users or devices, used to reduce latency

**Amazon CloudWatch** is a monitoring service for AWS resources and applications

**AWS CloudTrail** is a service that records AWS API calls for auditing, security, and troubleshooting

**API call** is a request made to an application or service to perform an action

**Infrastructure as Code / IaC** is a managing infrastructure using configuration files instead of manual setup
