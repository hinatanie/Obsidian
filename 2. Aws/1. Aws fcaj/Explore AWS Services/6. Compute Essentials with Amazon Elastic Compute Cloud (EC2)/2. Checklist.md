##### **What is `Amazon EC2`?**
`Amazon EC2`, also called `Amazon Elastic Compute Cloud`, is an `AWS` service that gives you computing power when you need it.
You can think of `EC2` as a virtual server in the cloud.
```text
EC2 can run:
A website
A backend API
A database
An authentication service
A business application
A testing server
```
This means you can use `EC2` to deploy many kinds of applications, such as a `Spring Boot` backend, a `Node.js` API, or a testing server.
With `EC2`, you can control many important server settings.
```text
You can control:
How many servers you want
How much CPU and memory they need
Which network they belong to
Which Security Group protects them
Which storage volume they use
How users authenticate to connect
```
So `EC2` is flexible like a normal physical server, but it is much faster to create, manage, stop, restart, or delete.
##### **Why use `EC2` instead of a traditional server?**
A traditional server usually requires physical hardware.
```text
Traditional server setup usually needs:
Buy the server
Wait for delivery
Install the operating system
Configure networking
Maintain hardware
Replace broken parts
```
With `EC2`, `AWS` handles the physical infrastructure for you.
You only choose the virtual server type, operating system, storage, and network settings.
This helps reduce hardware cost and speeds up development.
##### **What is the basic `EC2` structure?**
A basic `EC2` setup looks like this:
```text
AWS Region
   |
   v
Availability Zone
   |
   v
VPC
   |
   v
EC2 Instance
```
An `EC2 instance` is created inside a `VPC`.
A `VPC` is like your private network inside `AWS`.
Inside the `VPC`, the `EC2 instance` runs in an `Availability Zone`.
An `Availability Zone` is like a separate data center area inside an `AWS Region`.
##### **What is an `AWS Region`?**
An `AWS Region` is a geographic area where `AWS` has data centers.
For example:
```text
Singapore Region
Tokyo Region
Frankfurt Region
Northern Virginia Region
```
When you create an `EC2 instance`, you choose which `Region` it belongs to.
For users in Vietnam, you may choose a nearby `Region`, such as `Singapore`, to reduce latency.
##### **What is an `Availability Zone`?**
An `Availability Zone`, or `AZ`, is a separate data center area inside an `AWS Region`.
```text
Region
  |
  |-- Availability Zone A
  |-- Availability Zone B
  |-- Availability Zone C
```
Using multiple `Availability Zones` can improve high availability.
If one `Availability Zone` has a problem, your application may still work in another zone.
##### **What is a `VPC`?**
A `VPC`, or `Virtual Private Cloud`, is your private network inside `AWS`.
Your `EC2 instance` runs inside a `VPC`.
```text
VPC
 |
 |-- Public subnet
 |     |
 |     v
 |   EC2 instance
 |
 |-- Private subnet
       |
       v
     Database
```
A `VPC` lets you control IP ranges, `subnets`, route tables, gateways, and security rules.
For example, you can put your backend `EC2 instance` in a public `subnet`, and your `MySQL` database in a private `subnet`.
##### **What is a `subnet`?**
A `subnet` is a smaller network inside a `VPC`.
```text
VPC: 10.0.0.0/16
Public subnet:  10.0.1.0/24
Private subnet: 10.0.2.0/24
```
A public `subnet` can connect to the internet through an `Internet Gateway`.
A private `subnet` is usually used for internal resources, such as `RDS`, `MySQL`, or private services.
##### **What is a `Security Group`?**
A `Security Group` is a firewall for an `EC2 instance`.
It controls what traffic can enter and leave the instance.
```text
Allow SSH port 22 from your IP
Allow HTTP port 80 from everyone
Allow HTTPS port 443 from everyone
```

```text
Allow HTTP port 88 from everyone
```
For normal website traffic, the correct `HTTP` port is usually `80`, not `88`.
So the corrected version is:
```text
Allow HTTP port 80 from everyone
```
Without the correct `Security Group` rules, users may not be able to access your `EC2 instance`.
##### **What does `SSH port 22` mean?**
`SSH` is used to connect to a Linux server remotely.
The default `SSH` port is `22`.
```text
SSH port: 22
HTTP port: 80
HTTPS port: 443
```
For security, you should usually allow `SSH` only from your own IP address.
```text
Allow SSH port 22 from your IP only
```
Do not open `SSH` to everyone unless you really need it.
##### **How to connect to a Linux `EC2 instance`?**
A Linux `EC2 instance` usually uses a `key pair` for authentication.
You connect using `SSH`.
```bash
ssh -i my-key.pem ec2-user@public-ip
```
This command means:
```text
ssh              Connect using SSH
-i my-key.pem    Use this private key file
ec2-user         Linux username
public-ip        Public IP address of the EC2 instance
```
Your original note had `pulic-ip`.
The correct spelling is:
```text
public-ip
```
For `Amazon Linux`, the username is often `ec2-user`.
For `Ubuntu`, the username is often `ubuntu`.
```bash
ssh -i my-key.pem ubuntu@public-ip
```
##### **What is a `key pair`?**
A `key pair` is used to prove that you are allowed to access an `EC2 instance`.
It has two parts:
```text
Public key
Private key
```
The `public key` is placed on the `EC2 instance`.
The `private key` stays with you.
When you connect using `SSH`, `AWS` checks your private key.
You should never share your private key.
##### **What is `Amazon EBS`?**
`Amazon EBS`, or `Elastic Block Store`, is persistent block storage for `EC2`.
You can think of `EBS` as the hard drive of an `EC2 instance`.
```text
EC2 instance = computer
EBS volume   = hard drive
```
An `EBS volume` can store:
```text
Operating system
Application files
Logs
Database files
Configuration files
```
`EBS` provides persistent storage.
That means the data can remain even if the `EC2 instance` stops or restarts.
##### **What does `persistent storage` mean?**
`Persistent storage` means the data does not disappear when the server stops or restarts.
```text
Stop EC2 instance
Start EC2 instance again
Data in EBS still exists
```
This is important for application files, logs, uploaded files, and database files.
##### **What is an `EC2 instance type`?**
An `EC2 instance type` decides how powerful your virtual server is.
It controls things like:
```text
CPU
RAM
Storage performance
Network performance
```
You choose the instance type based on your application needs.
For example, a small testing server does not need the same power as a production database server.
##### **What are `C-family` instances?**
`C-family` instances are compute-optimized.
They are good for applications that need strong `CPU` power.
```text
Good for:
Batch processing
Heavy calculations
High-performance backend services
CPU-heavy workloads
```
Use `C-family` when your application needs more processing power.
##### **What are `R-family` instances?**
`R-family` instances are memory-optimized.
They are good for applications that need a lot of `RAM`.
```text
Good for:
Databases
In-memory caching
Big data processing
Memory-heavy applications
```
For example, a database server may need more memory than a normal backend API.
##### **What are `T-family` and `M-family` instances?**
`T-family` and `M-family` instances are general-purpose instance families.
They provide a balance of:
```text
CPU
Memory
Network performance
Cost
```
They are good for normal applications, small to medium backend APIs, testing servers, and development environments.
For learning `AWS`, `T-family` instances are commonly used because they are simple and cost-friendly.
##### **What is an `AMI`?**
An `AMI`, or `Amazon Machine Image`, is a template used to create an `EC2 instance`.
It usually includes:
```text
Operating system
Installed software
Configuration
Permissions
Storage settings
```
For example, instead of installing `Ubuntu`, `Java`, `Nginx`, and your application manually every time, you can create an `AMI`.
Then every new `EC2 instance` launched from that `AMI` will already have those things prepared.
##### **What are common `AMI` types?**
There are three common `AMI` types.
```text
AWS-provided AMIs
AWS Marketplace AMIs
Custom AMIs
```
`AWS-provided AMIs` are official basic images, such as `Amazon Linux`, `Ubuntu`, or `Windows Server`.
`AWS Marketplace AMIs` may already include software like databases, monitoring tools, or application servers.
`Custom AMIs` are created by you from your own configured `EC2 instance`.
##### **What is the difference between `EBS` and `instance store`?**
`EBS volumes` are persistent.
```text
EBS volume:
Data remains after stop/start
Good for important data
Can be attached to EC2
Common for production use
```
`Instance store volumes` are temporary.
```text
Instance store volume:
Physically attached to the host machine
Can be fast
Data can be lost if instance stops or terminates
Not safe for long-term storage
```
Use `EBS` for important data.
Use `instance store` only for temporary data, cache, or data you can recreate.
##### **What is a `Network ACL`?**
A `Network ACL`, or `NACL`, is a firewall at the `subnet` level.
A `Security Group` protects an `EC2 instance`.
A `Network ACL` protects a `subnet`.
```text
Security Group -> EC2 instance level
Network ACL    -> subnet level
```
A very important point is that `Network ACLs` are stateless.
This means they check inbound and outbound traffic separately.
```text
Inbound rule needed
Outbound rule also needed
```
With `NACL`, you must think about both directions of traffic.
##### **What is an `IAM role` for `EC2`?**
An `IAM role` gives permissions to applications running on an `EC2 instance`.
For example, instead of storing `AWS access keys` inside your application, you can attach an `IAM role` to the `EC2 instance`.
```text
EC2 instance
   |
   v
IAM role
   |
   v
Permission to access S3 or CloudWatch
```
This is safer than putting secret keys directly in your code or config files.
For example, your `Spring Boot` backend can upload files to `S3` using the `IAM role` attached to the `EC2 instance`.
##### **What is `AWS Systems Manager Session Manager`?**
`AWS Systems Manager Session Manager` is a safer way to access `EC2`.
With `Session Manager`, you do not need to open `SSH` or `RDP` ports to the internet.
```text
Traditional access:
Your computer -> SSH port 22 -> EC2
Session Manager access:
Your computer -> AWS Systems Manager -> EC2
```
This is safer because you do not need to distribute private key files.
It also helps with auditing and access control.
##### **What is `Elastic Infrastructure`?**
`Elastic Infrastructure` means your infrastructure can grow or shrink based on demand.
For example, if your website has more users, `Auto Scaling` can add more `EC2 instances`.
If traffic decreases, it can remove unnecessary instances to save cost.
```text
High traffic
   |
   v
Add more EC2 instances
Low traffic
   |
   v
Remove unnecessary EC2 instances
```
This is why `EC2` is called elastic.
##### **What is `Amazon EC2 Auto Scaling`?**
`Amazon EC2 Auto Scaling` automatically adds or removes `EC2 instances` based on demand.
```text
If CPU usage is high:
Add more EC2 instances
If CPU usage is low:
Remove unnecessary EC2 instances
```
This helps improve availability and reduce cost.
##### **What is `Elastic Load Balancing`?**
`Elastic Load Balancing`, or `ELB`, distributes traffic across multiple targets, such as `EC2 instances`.
```text
Users
  |
  v
Load Balancer
  |
  |-- EC2 instance 1
  |-- EC2 instance 2
  |-- EC2 instance 3
```
This improves performance because one `EC2 instance` does not need to handle all requests.
It also improves availability because traffic can be sent to healthy instances.
##### **What is an `Elastic IP Address`?**
An `Elastic IP Address` is a static public `IPv4` address.
It is useful when you need a fixed public IP address for an `EC2 instance`.
```text
EC2 instance public IP may change after stop/start
Elastic IP stays the same
```
However, `AWS` may charge you if an `Elastic IP` is not attached to a running resource.
So you should release unused `Elastic IPs`.
##### **What are `Placement Groups`?**
`Placement Groups` help control how `EC2 instances` are placed physically inside `AWS`.
They can improve performance or availability depending on your needs.
```text
Placement Groups can help with:
Low-latency communication
High network throughput
Better fault separation
```
They are useful for special workloads, such as high-performance computing or distributed systems.
##### **What is `High Availability`?**
`High Availability` means designing your application so it can keep running even if some parts fail.
For example, you can run your application in multiple `Availability Zones`.
```text
Availability Zone A -> EC2 instance 1
Availability Zone B -> EC2 instance 2
```
If one `Availability Zone` has a problem, the application may still continue working from another zone.
##### **What is `fault tolerance`?**
`Fault tolerance` is the ability of a system to continue working even when part of it fails.
```text
One EC2 instance fails
Another EC2 instance continues working
Application stays available
```
`Fault tolerance` is stronger than simple high availability because the system is designed to handle failures automatically.
##### **What are `Local Zones`?**
`Local Zones` are `AWS` infrastructure located closer to users in certain cities or population centers.
They are useful when your application needs low latency.
```text
User
 |
 v
Nearby Local Zone
 |
 v
Application
```
This can help reduce delay between user requests and application responses.
##### **What is `AWS Outposts`?**
`AWS Outposts` lets you run `AWS` infrastructure inside your own data center.
This is useful for hybrid cloud.
```text
Your data center
   |
   v
AWS Outposts
   |
   v
AWS services on-premises
```
It combines cloud infrastructure with on-premises infrastructure.
##### **What are `Wavelength Zones`?**
`Wavelength Zones` are `AWS` infrastructure located at the edge of `5G` networks.
They are designed for ultra-low latency applications.
```text
Good for:
Real-time gaming
Video processing
IoT applications
5G applications
```
They help applications respond faster by running closer to users or devices.
##### **What is `Resource Management` in `EC2`?**
`Resource Management` means organizing and managing your `AWS` resources clearly.
Important tools include:
```text
Tags
Resource Groups
CloudFormation
```
These tools help you manage many resources without confusion.
##### **What are `Tags`?**
`Tags` are key-value labels attached to `AWS` resources.
```text
Project = HotelBooking
Environment = Production
Owner = BackendTeam
```
Tags help with:
```text
Organization
Billing
Cost tracking
Management
Automation
```
For example, you can quickly find all resources that belong to one project.
##### **What are `Resource Groups`?**
`Resource Groups` help you manage related `AWS` resources together.
For example, one project may have:
```text
EC2 instance
VPC
Security Group
Load Balancer
RDS database
S3 bucket
```
A `Resource Group` helps you view and manage these related resources together.
##### **What is `CloudFormation`?**
`AWS CloudFormation` lets you define infrastructure using code.
This is called `Infrastructure as Code`, or `IaC`.
Instead of manually creating `EC2`, `VPC`, `Security Groups`, and load balancers, you can write a template.
```yaml
Resources:
  MyEC2Instance:
    Type: AWS::EC2::Instance
    Properties:
      ImageId: ami-xxxxxxxx
      InstanceType: t2.micro
```
This `YAML` example defines an `EC2 instance`.
With `CloudFormation`, you can deploy the same infrastructure many times in a consistent way.
##### **What is `Monitoring and Management` in `EC2`?**
Monitoring and management help you understand what is happening inside your infrastructure.
Important services include:
```text
CloudWatch
CloudTrail
Systems Manager
```
These services help with performance monitoring, security auditing, and operational troubleshooting.
##### **What is `Amazon CloudWatch`?**
`Amazon CloudWatch` is a monitoring service for `AWS` resources and applications.
It can monitor:
```text
CPU usage
Memory usage
Logs
Metrics
Alarms
Application behavior
```
For example, you can create an alarm when `CPU usage` is too high.
##### **What is `AWS CloudTrail`?**
`AWS CloudTrail` records `AWS API calls`.

```text
Who deleted this resource?
Who changed this Security Group?

```
This is useful for auditing, security, and troubleshooting.
##### **What is `Systems Manager`?**
`AWS Systems Manager` helps manage many `EC2 instances` at scale.
It can help you:
```text
Run commands
Patch systems
Access instances without SSH
Manage configuration
Collect operational data
```
For example, you can use `Systems Manager` to run commands on many servers without logging in to each one manually.

```text
CPU is important for:

Request processing
Batch jobs
```
A CPU-heavy application may need a compute-optimized `EC2 instance`.

##### **What does `Memory` or `RAM` mean?**
`Memory`, or `RAM`, is temporary working memory used by applications while they are running.
```text
Application starts
Application uses RAM
Application stops
RAM is cleared
```
Databases and caches often need more `RAM`.
##### **What does `volume` mean?**
A `volume` is a storage unit that can be attached to an `EC2 instance`.
```text
EC2 instance
   |
   v
EBS volume
```
A `volume` can store the operating system, application files, logs, and other data.
##### **What does `terminated` mean?**
`Terminated` means the `EC2 instance` is permanently deleted.
```text
Running -> Stopped -> Started again
Running -> Terminated -> Permanently deleted
```
Be careful with termination because the instance cannot simply be started again after it is terminated.
##### **What is the `EC2 instance lifecycle`?**
The `EC2 instance lifecycle` describes the stages of an `EC2 instance`.
```text
Pending
Running
Stopping
Stopped
Shutting down
Terminated
```
For example, when you launch an instance, it starts in `pending`, then becomes `running`.
When you stop it, it becomes `stopped`.
When you delete it permanently, it becomes `terminated`.
##### **What is `network-attached storage`?**
`Network-attached storage` is storage connected to an instance over the network.
It is not physically inside the same machine.
```text
EC2 instance
   |
   v
Network
   |
   v
Storage service
```
`EBS` behaves like block storage attached to `EC2`, but the storage is managed separately by `AWS`.
##### **What is `batch processing`?**

```text
Run scheduled jobs
```

```text
CPU-heavy tasks
```

`C-family` instances are common compute-optimized instances.
