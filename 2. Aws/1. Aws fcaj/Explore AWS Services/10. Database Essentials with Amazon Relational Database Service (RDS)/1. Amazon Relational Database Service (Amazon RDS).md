**Amazon RDS** is a service for running relational databases on AWS

A relational database stores data in tables. These tables can be connected to each other

Without RDS, you may need to create an EC2 server, install PostgreSQL or MySQL yourself, configure backups, update patches, monitor storage, and handle failures. That takes a lot of work

With Amazon RDS, AWS manages many of those tasks for you. You still use the database but AWS helps with operation such as backups, patching, scaling, and availability

Amazon RDS is designed mainly for OLTP, which means Online Transaction Processing . OLTP is used when an application needs to handle many normal business transactions

Amazon RDS supports many database engines such as MySQL, PostgreSQL, SQL Server, Oracle, MariaDB, and Amazon Aurora. This means you can choose the database engine that fits your application

**RDS** is a managed service. You do not have root access to the server underneath. This is different from installing a database directly on EC2. **AWS** controls the underlying server so it can manage the service safely and reliably

For storage, **RDS** gives you several options
**General Purpose SSD** is suitable for most application. It is a balanced choice between cost and performance

**Provisioned IOPS SSD** is used when your database needs very stable and high I/O performance.
For example, a busy banking system or high-traffic booking platform may need this

**Magnetic Storage** is an older option and is not recommended for new systems

---
With AZs, if the primary database fails. AWS can automatically switch to the standby database. This is called automatic failover

**Read Replicas** are different. A **Read Replica** is a copy of your database used mainly for read traffic

For example, imagine your application has many users searching hotel rooms. These search request are mostly read operations. Instead of sending all read requests to the main database, you can send some of them to read replicas

**Read Replica** is for read scaling
**Multi-AZ** is for high availability

**Global Databases** are useful when your users are in different parts of the world. Data can be replicated across **AWS Regions**, so users can read from a database closer to them. This improves performance and also helps with disaster recovery

For security, **RDS** supports several features
**Encryption at rest** protects data while it is stored. For example, your databases files, backups, snapshots, and replicas can be encrypted using AWS KMS keys

**SSL/TLS encryption** protects data while it is moving between your application and the database
```
Encryption at rest is protecting stored data
Encryption in transit is protecting moving data
```

**Network isolation** means you can place the **RDS database** inside a **VPC**. This helps prevent unwanted access from the public internet. In real projects, databases are usually placed in private subnets, not public subnets

**RDS** also supports **IAM policies** for resource-level permissions. This means you can control which AWS users or roles can create, modify, delete, or access RDS resources

For scaling, **RDS** allows you to increase storage without downtime. However, you generally cannot scale storage down. That means you should plan your storage carefully

For example, if you start with 100 GB, later you can increase it to 200 GB. But you cannot simply reduce it back to 50 GB in the same direct way

**Compute resources** such as CPU and memory, can also be changed. However, changing compute size may cause a short downtime because the database instance may need to restart or switch
