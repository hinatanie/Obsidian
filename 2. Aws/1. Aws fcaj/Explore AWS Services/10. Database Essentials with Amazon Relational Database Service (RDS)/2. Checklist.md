##### **What is `Amazon RDS`?**
`Amazon RDS`, or `Amazon Relational Database Service`, is an `AWS` service for running relational databases.
A relational database stores data in tables.
These tables can be connected to each other using relationships.
```text
Example relational database tables:
users
orders
order_items
products
payments
```
For example, in an auction app, you may have tables like this:
```text
users
wallets
auctions
bids
wallet_transactions
```
These tables are related to each other.
For example, one `user` can create many `auctions`, and one `auction` can have many `bids`.
##### **What is a relational database?**
A relational database stores data in rows and columns.
```text
users table
id | email              | full_name
1  | user1@gmail.com    | John
2  | user2@gmail.com    | Anna
```
Each table stores one type of data.
Tables can connect to other tables using keys.
```text
users table
   |
   v
orders table
   |
   v
order_items table
```
This structure is useful for business applications because the data is organized and connected.
##### **Why use `Amazon RDS`?**
Without `RDS`, you may need to manage the database server yourself.
For example, you may need to:
```text
Create an EC2 server
Install MySQL or PostgreSQL
Configure database users
Configure backups
Update database patches
Monitor storage
Handle failures
Configure replication
Secure the database server
```
That takes a lot of work.
With `Amazon RDS`, `AWS` manages many of those operational tasks for you.
```text
AWS helps manage:
Backups
Patching
Storage
Scaling
Availability
Monitoring
Failover
Database maintenance
```
You still use the database normally, but `AWS` helps with the heavy operation work.
##### **What does `managed service` mean in `RDS`?**
`RDS` is a managed service.
This means `AWS` manages the underlying database server for you.
You do not have root access to the server underneath.
```text
Using database on EC2:
You control the server
You install the database
You patch the OS
You manage failures
You have more control
You have more responsibility
Using Amazon RDS:
AWS controls the underlying server
AWS manages backups
AWS manages patching
AWS manages failover
AWS manages database maintenance
You have less server control
You have less operation work
```
This is different from installing `MySQL` or `PostgreSQL` directly on an `EC2 instance`.
With `RDS`, you focus more on using the database.
`AWS` focuses more on operating the database infrastructure safely and reliably.
##### **What database engines does `RDS` support?**
`Amazon RDS` supports many relational database engines.
```text
Amazon RDS supports:
MySQL
PostgreSQL
MariaDB
Oracle
SQL Server
Amazon Aurora
```
This means you can choose the database engine that fits your application.
For example:
```text
Spring Boot app        -> MySQL or PostgreSQL
Enterprise app         -> Oracle or SQL Server
Cloud-native workload  -> Amazon Aurora
```
For many backend projects, `MySQL` and `PostgreSQL` are common choices.
##### **What is `OLTP`?**
`OLTP` means `Online Transaction Processing`.
`Amazon RDS` is designed mainly for `OLTP` workloads.
`OLTP` is used when an application needs to handle many normal business transactions.
```text
Examples of OLTP operations:
Create user account
Login user
Place order
Place bid
Deposit money
Update wallet balance
Create booking
Process payment
```
These operations usually need fast reads and writes.
They also need data consistency.
For example, when a user places a bid, the database must save the correct bid amount and update related data safely.
##### **What is the difference between `OLTP` and analytics?**
`OLTP` is for normal application transactions.
Analytics is for reporting and large data analysis.
```text
OLTP:
Many small transactions
Fast insert/update/read
Used by applications
Example: place bid, create order, update wallet
Analytics:
Large queries
Reports and dashboards
Used by data teams
Example: monthly revenue report, user behavior analysis
```
`RDS` is mainly for `OLTP`.
For large analytics workloads, services like `Amazon Redshift`, `Athena`, or data warehouses may be more suitable.
##### **What storage options does `RDS` provide?**
`RDS` provides different storage options.
```text
Common RDS storage options:
General Purpose SSD
Provisioned IOPS SSD
Magnetic Storage
```
Each option is designed for different performance and cost needs.
##### **What is `General Purpose SSD` in `RDS`?**
`General Purpose SSD` is suitable for most applications.
It gives a balance between cost and performance.
```text
Good for:
Normal backend applications
Small to medium business systems
Development databases
Testing databases
Most production applications
```
For example, a normal `Spring Boot` application using `MySQL` can often start with `General Purpose SSD`.
##### **What is `Provisioned IOPS SSD` in `RDS`?**
`Provisioned IOPS SSD` is used when your database needs very stable and high I/O performance.
`IOPS` means input/output operations per second.
```text
Good for:
Busy banking systems
High-traffic booking platforms
Large e-commerce systems
Heavy transaction systems
Performance-sensitive databases
```
For example, a banking system may need stable database performance all the time.
In that case, `Provisioned IOPS SSD` can be a better choice.
##### **What is `Magnetic Storage` in `RDS`?**
`Magnetic Storage` is an older `RDS` storage option.
It is not recommended for new systems.
```text
Magnetic Storage:
Older option
Lower performance
Not recommended for new applications
```
For new projects, you should usually choose `General Purpose SSD` or `Provisioned IOPS SSD`.
##### **What is `Multi-AZ` in `RDS`?**
`Multi-AZ` means the database is deployed across multiple `Availability Zones`.
In a typical `Multi-AZ` setup, there is a primary database and a standby database.
```text
Availability Zone A
   |
   v
Primary RDS database
Availability Zone B
   |
   v
Standby RDS database
```
If the primary database fails, `AWS` can automatically switch to the standby database.
This is called automatic failover.
##### **What is automatic failover?**
Automatic failover means `AWS` automatically switches from the failed primary database to the standby database.
```text
Primary database fails
   |
   v
AWS detects failure
   |
   v
AWS switches to standby database
   |
   v
Application continues using database
```
This improves high availability.
You do not need to manually create a new database when the primary one fails.
##### **Why use `Multi-AZ`?**
Use `Multi-AZ` when your application needs high availability.
```text
Multi-AZ helps protect against:
Database instance failure
Availability Zone problem
Some infrastructure problems
Maintenance events
```
For production systems, `Multi-AZ` is often recommended because it reduces the risk of downtime.
For example, an auction app should avoid database downtime during active bidding.
##### **What is a `Read Replica`?**
A `Read Replica` is a copy of your database used mainly for read traffic.
```text
Main database
   |
   v
Read Replica
```
The main database handles writes.
The read replica can handle read queries.
```text
Main database:
Insert bid
Update wallet
Create order
Update auction status
Read Replica:
Search auctions
View product list
View hotel rooms
View public data
Generate read-heavy pages
```
Read replicas help reduce pressure on the main database.
##### **Why use `Read Replicas`?**
Use `Read Replicas` when your application has many read requests.
For example, imagine your application has many users searching hotel rooms.
Most search requests are read operations.
```text
Users search hotel rooms
   |
   v
Read requests
   |
   v
Read Replica
```
Instead of sending all read requests to the main database, you can send some read requests to read replicas.
This helps improve read performance.
##### **What is the difference between `Read Replica` and `Multi-AZ`?**
`Read Replica` and `Multi-AZ` are different.
```text
Read Replica:
Used for read scaling
Can serve read traffic
Helps reduce load on main database
Useful when there are many read queries
Multi-AZ:
Used for high availability
Has standby database
Used for failover
Not mainly for read scaling
```
Simple summary:
```text
Read Replica = read scaling
Multi-AZ = high availability
```
This is one of the most important `RDS` concepts.
##### **What are `Global Databases`?**
`Global Databases` are useful when users are in different parts of the world.
Data can be replicated across `AWS Regions`.
```text
Region 1
   |
   v
Primary database
Region 2
   |
   v
Secondary database
Region 3
   |
   v
Secondary database
```
Users can read data from a database closer to them.
This improves performance and also helps with disaster recovery.
##### **Why use `Global Databases`?**
Use `Global Databases` when your application is global.
```text
Good for:
Users in many countries
Low-latency global reads
Disaster recovery
Multi-region architecture
Large international applications
```
For example, if users are in Asia, Europe, and America, global database replication can help users read data faster from a nearby region.
##### **What security features does `RDS` support?**
`RDS` supports many security features.
```text
RDS security features:
Encryption at rest
SSL/TLS encryption
Network isolation inside VPC
IAM policies
Security Groups
Private subnets
Database authentication
KMS key integration
```
These features help protect your database from unauthorized access.
##### **What is `encryption at rest` in `RDS`?**
`Encryption at rest` protects data while it is stored.
In `RDS`, encryption can protect:
```text
Database files
Backups
Snapshots
Read replicas
Transaction logs
```
`RDS` can use `AWS KMS` keys to encrypt stored data.
```text
RDS database
   |
   v
Encrypted using AWS KMS key
```
This is important for sensitive data, such as users, payments, wallets, orders, and business records.
##### **What is `SSL/TLS encryption` in `RDS`?**
`SSL/TLS encryption` protects data while it is moving between your application and the database.
```text
Spring Boot application
   |
   | encrypted connection
   v
RDS MySQL database
```
This is also called encryption in transit.
```text
Encryption at rest = protecting stored data
Encryption in transit = protecting moving data
```
For example, when your backend sends a SQL query to the database, `SSL/TLS` can protect that communication.
##### **What is `network isolation` in `RDS`?**
`Network isolation` means placing your `RDS database` inside a controlled network, usually a `VPC`.
In real projects, databases are usually placed in private `subnets`.
```text
VPC
 |
 |-- Public subnet
 |     |
 |     v
 |   EC2 backend / Load Balancer
 |
 |-- Private subnet
       |
       v
     RDS database
```
This helps prevent unwanted access from the public internet.
A common production rule is:
```text
Backend can access database
Public internet cannot directly access database
```
##### **Why put `RDS` in a private subnet?**
You should put `RDS` in a private `subnet` because databases should not be directly exposed to the internet.
```text
Bad design:
Internet
   |
   v
Public RDS database
Better design:
Internet
   |
   v
Load Balancer / EC2 backend
   |
   v
Private RDS database
```
The backend application can connect to the database.
Normal users should not connect to the database directly.
##### **What are `IAM policies` for `RDS`?**
`RDS` supports `IAM policies` for resource-level permissions.
This means you can control which `AWS` users or roles can create, modify, delete, or access `RDS` resources.
```json
{
  "Effect": "Allow",
  "Action": [
    "rds:CreateDBInstance",
    "rds:ModifyDBInstance",
    "rds:DescribeDBInstances"
  ],
  "Resource": "*"
}
```
This example allows creating, modifying, and viewing `RDS` database instances.
It does not allow deleting unless `rds:DeleteDBInstance` is added.
##### **What is the difference between `IAM permission` and database user permission?**
`IAM permissions` control actions on `AWS RDS resources`.
Database user permissions control actions inside the database.
```text
IAM permission:
Create RDS instance
Delete RDS instance
Modify RDS storage
View RDS configuration
Database user permission:
SELECT data
INSERT data
UPDATE data
DELETE data
CREATE table
DROP table
```
For example, an `AWS IAM user` may have permission to create an `RDS instance`.
But inside `MySQL`, a database user still needs permission to read or write tables.
##### **How does `RDS` scaling work?**
`RDS` allows you to scale storage and compute resources.
```text
RDS scaling options:
Increase storage
Change instance class
Add Read Replicas
Use Multi-AZ for availability
Use Aurora for more advanced scaling
```
Scaling helps your database handle more data or more traffic.
##### **How does `RDS` storage scaling work?**
`RDS` allows you to increase storage.
For example:
```text
Start with 100 GB
Later increase to 200 GB
```
However, you generally cannot scale storage down directly.
For example:
```text
You can increase:
100 GB -> 200 GB
But you generally cannot directly decrease:
200 GB -> 50 GB
```
Because of this, you should plan your storage carefully.
##### **Why can storage increase but not easily decrease?**
Increasing storage is easier because `RDS` can add more available storage capacity.
Reducing storage is harder because the database may already have data, indexes, logs, and internal storage layout.
```text
Increasing storage:
Add more capacity
Usually easier
Decreasing storage:
Need to move or rebuild data
Riskier
Not supported directly in many cases
```
If you really need to reduce storage, you may need a migration approach, such as creating a smaller new database and restoring or copying data into it.
##### **How does `RDS` compute scaling work?**
`Compute resources` include `CPU` and memory.
You can change the `RDS instance class` to get more or less compute power.
```text
Smaller instance:
Less CPU
Less memory
Lower cost
Larger instance:
More CPU
More memory
Higher cost
Better performance
```
However, changing compute size may cause short downtime.
This is because the database instance may need to restart or switch.
##### **Why can changing `RDS` compute cause downtime?**
Changing compute size often means changing the database instance class.
The database may need to restart on new hardware or switch to another instance.
```text
Modify instance class
   |
   v
RDS applies change
   |
   v
Database may restart or fail over
   |
   v
Short downtime may happen
```
For production systems, you should schedule compute changes during a maintenance window or low-traffic time.
##### **What is a maintenance window in `RDS`?**
A maintenance window is a scheduled time when `AWS` can apply maintenance tasks.
```text
Maintenance tasks may include:
Database patches
Minor version updates
System maintenance
Instance changes
```
For production systems, choose a maintenance window during low-traffic hours.
For example, if your users are mostly active during the day, you may schedule maintenance at night.
##### **What is an `RDS backup`?**
An `RDS backup` is a saved copy of your database data.
Backups help you recover data if something goes wrong.
```text
Backups help when:
Someone deletes data by mistake
Application bug damages data
Database has a problem
You need to restore to an earlier time
```
`RDS` can manage automated backups for you.
This is one major benefit of using `RDS` instead of managing a database manually on `EC2`.
##### **What is an `RDS snapshot`?**
An `RDS snapshot` is a manual or automated backup of your database at a specific point in time.
```text
Snapshot example:
Database state at 2026-07-08 10:00
```
You can restore a snapshot to create a new database instance.
This is useful before big changes, migrations, or risky deployments.
##### **What is the difference between running database on `EC2` and using `RDS`?**
Running a database on `EC2` gives you more server control, but also more responsibility.
Using `RDS` gives you less server control, but much easier operation.
```text
Database on EC2:
You install database yourself
You manage OS patches
You configure backups
You handle failover
You have root access
More control
More responsibility
Database on RDS:
AWS manages infrastructure
AWS handles backups
AWS handles patching
AWS supports Multi-AZ
No root access to underlying server
Less control
Less operation work
```
For most normal business applications, `RDS` is easier and safer.
##### **How can a `Spring Boot` app use `RDS MySQL`?**
A `Spring Boot` backend can connect to `RDS MySQL` like a normal `MySQL` database.
```properties
spring.datasource.url=jdbc:mysql://mydb.xxxxxx.ap-southeast-1.rds.amazonaws.com:3306/auction_db
spring.datasource.username=admin
spring.datasource.password=your-password
spring.jpa.hibernate.ddl-auto=validate
spring.jpa.show-sql=true
```
This config tells `Spring Boot` how to connect to the `RDS MySQL` database.
The `RDS endpoint` is used as the database host.
In production, you should not hardcode the password directly in the file.
Use environment variables or `AWS Secrets Manager`.
##### **How to use environment variables for `RDS` config?**
Instead of hardcoding database credentials, you can use environment variables.
```properties
spring.datasource.url=${DB_URL}
spring.datasource.username=${DB_USERNAME}
spring.datasource.password=${DB_PASSWORD}
spring.jpa.hibernate.ddl-auto=validate
```
Then your server can provide the values.
```bash
export DB_URL="jdbc:mysql://mydb.xxxxxx.ap-southeast-1.rds.amazonaws.com:3306/auction_db"
export DB_USERNAME="admin"
export DB_PASSWORD="your-password"
```
This is safer than putting passwords directly inside source code.
##### **What is a common `RDS` architecture?**
A common production architecture uses `EC2` or a backend service in a public layer, and `RDS` in private `subnets`.
```text
Internet
   |
   v
Load Balancer
   |
   v
EC2 backend instances
   |
   v
Private RDS database
```
The database should usually not be directly accessible from the internet.
The backend application connects to the database privately inside the `VPC`.
##### **How to summarize `Amazon RDS` simply?**
`Amazon RDS` is a managed relational database service on `AWS`.
```text
RDS gives you:
Managed MySQL, PostgreSQL, MariaDB, SQL Server, Oracle, or Aurora
Automated backups
Patching
Monitoring
Storage scaling
Multi-AZ high availability
Read Replicas for read scaling
Encryption
Private networking inside VPC
```
Simple mental model:
```text
RDS = managed relational database
Table = structured data storage
OLTP = normal app transactions
Multi-AZ = high availability
Read Replica = read scaling
Global Database = multi-region database
Encryption at rest = protect stored data
Encryption in transit = protect moving data
Private subnet = database not exposed to internet
IAM policy = control AWS-level RDS permissions
Database user = control SQL-level permissions
```
Use `RDS` when your application needs a relational database but you do not want to manually manage the database server on `EC2`.
