##### **What is `Amazon S3`?**
`Amazon S3`, or `Amazon Simple Storage Service`, is an `object storage service`.
This means `S3` stores data as objects instead of traditional files and folders like on your computer.
An object can be many types of data.
```text
Examples of objects in S3:
Image
Video
PDF
Backup file
Log file
Website file
CSS file
JavaScript file
Any other type of data
```
Each object usually has three important parts.
```text
Object = data + key/name + metadata
```
The `data` is the actual file content.
The `key` is the object name or path.
The `metadata` is extra information about the object, such as content type, size, or custom information.
##### **What is `object storage`?**
`Object storage` is a storage model where data is stored as objects.
Each object usually includes:
```text
File data
Metadata
Unique key
```
For example:
```text
Bucket name: my-website-bucket
Object key: images/logo.png
Object data: the actual logo image
Metadata: content-type=image/png
```
In `S3`, you do not manage hard disks, partitions, or traditional server storage.
`AWS` manages the storage infrastructure for you.

##### **What are `S3 storage classes`?**
`S3` has different storage classes.
A `storage class` is like choosing the right type of storage based on how often you use the data.
```text
Frequently used data    -> S3 Standard
Rarely used data        -> S3 Standard-IA
Long-term archive data  -> S3 Glacier
Very old archive data   -> S3 Glacier Deep Archive
```
Choosing the correct `storage class` can help reduce cost.
##### **What is `S3 Standard`?**
`S3 Standard` is designed for frequently accessed data.
Use `S3 Standard` when your application needs fast access and high performance.
```text
Good for:
Website images
CSS files
JavaScript files
User-uploaded photos
Frequently downloaded files
Application assets
```
For example, if your website needs to load images every day, you should use `S3 Standard`.
##### **What is `S3 Standard-IA`?**
`S3 Standard-IA` means `S3 Standard-Infrequent Access`.
It is useful for data that is not used often, but still needs to be available quickly.
```text
Good for:
Old reports
Backup files
Rarely accessed documents
Disaster recovery files
```
The storage cost is usually lower than `S3 Standard`.
However, there may be retrieval costs when you access the data.
##### **What is `S3 Glacier`?**
`S3 Glacier` is used for long-term archive storage.
It is cheaper than frequently accessed storage classes, but retrieving data can take longer.
```text
Good for:
Old backups
Compliance archives
Long-term records
Data you rarely need to read
```
Use `S3 Glacier` when you want to keep data for a long time but do not need to access it often.
##### **What is `S3 Glacier Deep Archive`?**
`S3 Glacier Deep Archive` is one of the lowest-cost `S3` storage classes.
It is used for very old data that you almost never access.
```text
Good for:
Very old backups
Legal archives
Historical records
Long-term compliance data
```
It is cheaper, but retrieving data can take much longer compared with `S3 Standard`.

##### **What is `encryption in transit`?**
`Encryption in transit` means data is protected while moving across the internet.
For example, when a user uploads a file to `S3`, the data travels from the user to `AWS`.
```text
User computer
   |
   v
Internet
   |
   v
Amazon S3
```
Using `HTTPS` helps encrypt this communication.
This prevents attackers from easily reading the data while it is moving.
##### **What is `encryption at rest`?**
`Encryption at rest` means data is protected while stored inside `AWS`.
```text
File uploaded to S3
   |
   v
S3 stores encrypted data
```
Even after the file is saved, encryption helps protect the stored data.
This is important for sensitive files, backups, logs, and private user uploads.
##### **What are `IAM policies`?**
`IAM policies` control what `AWS` users, roles, or services can do.
For example, you can create an `IAM policy` that allows an `EC2` backend server to upload files to `S3`.
```json
{
  "Effect": "Allow",
  "Action": [
    "s3:PutObject",
    "s3:GetObject"
  ],
  "Resource": "arn:aws:s3:::my-app-bucket/*"
}
```
This policy allows uploading and reading objects inside `my-app-bucket`.
It does not automatically allow deleting objects unless you add `s3:DeleteObject`.
##### **What are `bucket policies`?**
A `bucket policy` is a permission policy attached directly to an `S3 bucket`.
It controls who can access the bucket and what actions they can perform.
```json
{
  "Effect": "Allow",
  "Principal": {
    "AWS": "arn:aws:iam::123456789012:role/MyBackendRole"
  },
  "Action": "s3:PutObject",
  "Resource": "arn:aws:s3:::my-app-bucket/uploads/*"
}
```
This example allows a specific backend role to upload objects into the `uploads/` path.
Bucket policies are useful for controlling access at the bucket level.
##### **What are `ACLs` in `S3`?**
`ACL` means `Access Control List`.
It is an older way to control access to buckets and objects.
```text
ACL can control:
Who owns the object
Who can read the object
Who can write the object
```
Today, for most modern `S3` setups, it is better to use `IAM policies`, `bucket policies`, and `Block Public Access`.
Use `ACLs` only when you have a specific reason.
##### **What is `Block Public Access`?**
`Block Public Access` is an `S3` security feature that helps prevent public access to buckets and objects.
```text
Block Public Access can stop:
Public bucket policies
Public object ACLs
Public bucket ACLs
Public access by mistake
```
This is very important for private files.
For example, user identity cards, private photos, logs, and backups should not be public.
##### **What is `S3 versioning`?**
`Versioning` allows `S3` to keep old versions of files.
This is useful if someone accidentally overwrites or deletes an object.
```text
logo.png version 1
logo.png version 2
logo.png version 3
```
If the latest version has a problem, you can restore an older version.
For example:
```text
User uploads wrong logo.png
S3 keeps older logo.png
Admin restores old version
```
Versioning helps protect against mistakes.
##### **What is `S3 Lifecycle Management`?**
`S3 Lifecycle Management` helps reduce cost automatically.
You can create rules to move objects to cheaper storage classes after a certain time.
```text
After 30 days, move object to Standard-IA
After 180 days, move object to Glacier
After 365 days, delete object
```
This helps you avoid paying high storage cost for old data that you do not use often.
##### **Wow does `S3 Lifecycle Management` reduce cost?**

##### **What is `HTTPS`?**
`HTTPS` means `Hypertext Transfer Protocol Secure`.
It is the secure version of `HTTP`.
```text
HTTP  = not encrypted
HTTPS = encrypted
```
`HTTPS` encrypts communication between users and websites.
This helps protect passwords, tokens, personal data, and uploaded files.
For modern websites, you should use `HTTPS`.
##### **What is a `Global CDN`?**
`Global CDN` means `Global Content Delivery Network`.
A `CDN` stores and delivers website content from servers around the world.
```text
User in Vietnam
   |
   v
Nearby CDN location
   |
   v
Website files
```
This reduces latency because users can download content from a location closer to them.
A `Global CDN` helps websites load faster for users in different countries.
##### **What is `Amazon CloudFront`?**
`Amazon CloudFront` is `AWS` content delivery network service.
It helps deliver content globally with low latency and high transfer speed.
```text
Users
  |
  v
CloudFront
  |
  v
S3 bucket or backend server
```
`CloudFront` is often used in front of `S3`, `EC2`, `Load Balancer`, or other origins.
It improves performance and can also add security features.
