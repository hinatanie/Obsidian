# Main Problem
To design the AWS architecture for your Pet Shop project, I first need to understand:
- What the application does.
- How the current code is structured.
- Which technologies it uses.
- Expected users and traffic.
- Security, availability, and cost requirements.
- What AWS resources already exist.
- What you want to learn or achieve by deploying it.
Without this information, I might recommend Lambda, EC2, ECS, RDS, DynamoDB, or another service for the wrong reasons. AWS also recommends selecting compute based on workload characteristics, rather than starting with a predetermined service. [AWS Compute Decision Guide](https://docs.aws.amazon.com/pdfs/decision-guides/latest/compute-on-aws-how-to-choose/compute-on-aws-how-to-choose.pdf?utm_source=chatgpt.com)

## Problem 2: What each document must contain
### 1. `01-project-overview.md`
Include:
- Purpose of the Pet Shop.
- Target users.
- Main technologies.
- Current development status.
- Features already implemented.
- Features planned but not implemented.
- Whether this is a learning, portfolio, or production project.
### 2. `02-functional-requirements.md`
List every use case, such as:
```
Customer registration
Customer login
Browse pets
Search and filter pets
View pet details
Add products to cart
Place an order
Make payment
Upload pet images
Manage inventory
Track an order
Cancel an order
Write reviews
Admin management
Email notifications
```
For each use case, include:
```
Use-case ID
Actor
Description
Preconditions
Main flow
Alternative flows
Business rules
API endpoint
Database tables
Current implementation status
```
### 3. `03-technical-architecture.md`
Include:
- Programming languages and versions.
- Backend framework.
- Frontend framework.
- Database technology.
- Cache or message broker.
- Docker configuration.
- Communication between components.
- REST, WebSocket, scheduled jobs, or event-driven processes.
- Existing architectural pattern, such as Clean Architecture.
### 4. `04-backend-structure.md`
Include:
- Backend directory tree.
- Application entry point.
- API routes.
- Services or use cases.
- Repositories.
- Database models.
- Authentication middleware.
- Background jobs.
- Environment variables, but not their secret values.
- Current Dockerfile.
- How the backend is started.
### 5. `05-frontend-structure.md`
Include:
- Frontend directory tree.
- Framework and version.
- Main pages and routes.
- How it calls the backend.
- Required environment variables.
- Static versus server-rendered behavior.
- Image-loading behavior.
- Authentication storage.
- Production build command and output directory.
### 6. `06-database-design.md`
Include:
- Database engine and version.
- Every table and column.
- Primary and foreign keys.
- Indexes.
- Unique constraints.
- Relationships.
- Migration tool.
- Seed-data process.
- Estimated data volume.
- Transactions and row-locking requirements.
- Whether the application requires MySQL specifically.
Do not include real database passwords or production data.
### 7. `07-file-and-image-requirements.md`
Include:
- Types of uploaded files.
- Pet and product image workflow.
- Maximum file size.
- Allowed formats.
- Who can upload.
- Whether images need resizing or thumbnails.
- Whether files must be private or public.
- Expected storage volume.
- Image deletion and retention rules.
This helps determine whether the architecture needs S3, CloudFront, presigned URLs, and image-processing Lambda functions.
### 10. `10-security-and-authentication.md`
Include:
- Registration and login flow.
- JWT, session, OAuth, or Cognito usage.
- User roles and permissions.
- Admin capabilities.
- Sensitive customer information.
- CORS requirements.
Never place API keys, passwords, tokens, private keys, or AWS credentials in this document.
### 13. `13-aws-requirements.md`
Include your preferences and constraints:
```
Preferred AWS region
Maximum monthly budget
Services you have already created
Services you want to learn
Services you do not want to use
Serverless, container, or EC2 preference
Infrastructure as Code preference
High availability requirement
Development-only or production deployment
```
Do not force Cursor to choose the final AWS architecture. It should document the requirements and possible constraints. I will compare the options afterward.
### 14. `14-environments-and-cicd.md`
Include:
- Required environments: local, development, staging, production.
- Git repository and branch strategy.
- Current CI/CD configuration.
- Test commands.
- Build commands.
- Database migration process.
- Rollback expectations.
- Whether deployments require approval.
### 15. `15-open-questions.md`
Cursor should record:
- Contradictions in the code or documentation.
- Missing requirements.
- Undecided technology choices.
- Features mentioned but not implemented.
- Security concerns.
- Deployment blockers.
- Assumptions requiring your approval.
### 16. `16-repository-tree.md`
Include a concise repository tree showing important files only:
```
backend/
frontend/
database/
docker/
scripts/
.github/
docs/
docker-compose.yml
```
Exclude:
```
node_modules
.venv
dist
build
coverage
.git
generated files
secret files
```
