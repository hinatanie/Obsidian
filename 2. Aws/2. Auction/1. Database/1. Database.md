For an auction app, I suggest this database structure:
```
users
auction_sessions
auction_session_rules
auction_items
bids
categories
item_images
```
The idea is:
```
Seller creates auction session
Auction session has rules
Auction session has many auction items
Bidder places bids on auction items
Winner is stored in auction_items
```
# 1. `users`
Stores all users: admin, seller, bidder.
```
CREATE TABLE users (
    id char(36) PRIMARY KEY,
    email VARCHAR(255) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    full_name VARCHAR(255) DEFAULT 'user',
    phone VARCHAR(30) NOT NULL,
    role ENUM('ADMIN','USER') NOT NULL DEFAULT 'USER',
    status ENUM('ACTIVE', 'BANNED') NOT NULL DEFAULT 'ACTIVE',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```
# 4. `auction_sessions`
This is a big auction event/session created by a seller.  
Example:
```
Session: "Luxury Watch Auction July 2026"
Seller: User A
Status: ACTIVE
```
```
CREATE TABLE auction_sessions (
    id char(36) PRIMARY KEY,
    seller_id char(36) NOT NULL,
    title VARCHAR(255) NOT NULL,
    description TEXT,
    start_time DATETIME NOT NULL,
    end_time DATETIME NOT NULL,
    status ENUM(
'SCHEDULED',
'ACTIVE',
'ENDED',
'CANCELLED'
    ) NOT NULL DEFAULT 'SCHEDULED',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
CONSTRAINT fk_auction_sessions_seller
FOREIGN KEY (seller_id) REFERENCES users(id)
);
```
Meaning:
```
SCHEDULED   auction will start later
ACTIVE      bidders can bid
ENDED       finished
CANCELLED   cancelled by seller/admin
```
# 5. `auction_session_rules`
Stores rules for each auction session.
```
CREATE TABLE auction_session_rules (
    id char(36) PRIMARY KEY,
    session_id char(36) NOT NULL UNIQUE,
    min_increment DECIMAL(18,2) NOT NULL DEFAULT 1.00,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
CONSTRAINT fk_auction_session_rules_session
FOREIGN KEY (session_id) REFERENCES auction_sessions(id)
ON DELETE CASCADE
);
```
Important fields:
```
min_increment        minimum bid increase
```
Example:
```
Current price = 1,000,000
min_increment = 50,000
Next bid must be at least 1,050,000
```
# 6. `categories`
Optional but useful.
```
CREATE TABLE categories (
    id char(36) PRIMARY KEY,
    name VARCHAR(150) NOT NULL,
    slug VARCHAR(150) NOT NULL UNIQUE,
    status ENUM('ACTIVE','INACTIVE') NOT NULL DEFAULT 'ACTIVE',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```
# 7. `auction_items`
This is the item being sold inside an auction session.
```
CREATE TABLE auction_items (
    id char(36) PRIMARY KEY,
    session_id char(36) NOT NULL,
	category_id char(36),
    title VARCHAR(255) NOT NULL,
    description TEXT,
    starting_price DECIMAL(18,2) NOT NULL,
    current_price DECIMAL(18,2) NOT NULL DEFAULT 0.00,
    status ENUM(
'SOLD',
'UNSOLD',
'CANCELLED'
    )NOT NULL DEFAULT 'UNSOLD',
    winner_user_id char(36),
    final_price DECIMAL(18,2),
    opened_at DATETIME,
    closed_at DATETIME,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
CONSTRAINT fk_auction_items_session
FOREIGN KEY (session_id) REFERENCES auction_sessions(id)
ON DELETE CASCADE,

CONSTRAINT fk_auction_items_category
FOREIGN KEY (category_id) REFERENCES categories(id),

CONSTRAINT fk_auction_items_winner
FOREIGN KEY (winner_user_id) REFERENCES users(id)

CONSTRAINT fk_auction_items_user FOREIGN KEY (user_id) REFERENCES users(id),
);
```
Meaning:
```
session_id       item belongs to which auction session
starting_price   first price
current_price    current highest bid
winner_user_id   winner bidder
final_price      final sold price
status           current item status
```
Important:
```
auction_sessions = the whole event
auction_items = products inside that event
```
Example:
```
Auction Session: Phone Auction July 2026
Item 1: iPhone 15
Item 2: Samsung S24
Item 3: Xiaomi 14
```
Ví dụ cho title và description
```jsx
title = 'iPhone 14 Pro Max 256GB'
description = 'Máy màu tím, dung lượng 256GB, pin 89%, ngoại hình đẹp, có trầy nhẹ ở viền. Bao gồm hộp và cáp sạc.'
```
# 8. `item_images`
Each auction item can have many images.
```
CREATE TABLE item_images (
    id char(36) PRIMARY KEY,
    item_id char(36) NOT NULL,
    image_url VARCHAR(500) NOT NULL,
    is_primary BOOLEAN NOT NULL DEFAULT FALSE,
    sort_order INT NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
CONSTRAINT fk_item_images_item
FOREIGN KEY (item_id) REFERENCES auction_items(id)
ON DELETE CASCADE
);
```
# 9. `bids`
Stores all bids.
```
CREATE TABLE bids (
    id char(36) PRIMARY KEY,
    item_id char(36) NOT NULL,
    session_id char(36) NOT NULL,
    bidder_id char(36) NOT NULL,
    amount DECIMAL(18,2) NOT NULL,
    status ENUM(
'WINNING',
'OUTBID',
    )NOT NULL DEFAULT 'OUTBID',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
CONSTRAINT fk_bids_item
FOREIGN KEY (item_id) REFERENCES auction_items(id),
CONSTRAINT fk_bids_session
FOREIGN KEY (session_id) REFERENCES auction_sessions(id),
CONSTRAINT fk_bids_bidder
FOREIGN KEY (bidder_id) REFERENCES users(id)
);
```
When a user places a new highest bid:
```
Old WINNING bid becomes OUTBID
New bid becomes WINNING
auction_items.current_price is updated
```
Example:
```
Item current_price = 1,000,000
min_increment = 50,000
User A bids 1,050,000
User B bids 1,100,000
User A bid status = OUTBID
User B bid status = WINNING
```

# 12. Important relationship summary
```
users 1 - N auction_sessions
users 1 - N wallets
users 1 - N bids
auction_sessions 1 - 1 auction_session_rules
auction_sessions 1 - N auction_items
auction_items 1 - N bids
auction_items 1 - N item_images
auction_items N - 1 users as winner_user_id
payments N - 1 users as payer
payments N - 1 users as seller
```
# 13. Main backend flow
## Seller creates auction session
```
1. Seller logs in
2. Seller creates auction session
3. Seller creates auction rules
4. Seller adds auction items
5. Seller uploads item images
6. Seller publishes session
```
Tables used:
```
auction_sessions
auction_session_rules
auction_items
item_images
```
## Bidder joins auction
```
1. Bidder logs in
2. Backend checks user status is ACTIVE
3. Backend checks wallet status is ACTIVE
4. Backend checks wallet has enough balance
5. Backend checks auction session is ACTIVE
6. Bidder can place bid
```
Tables used:
```
users
wallets
auction_sessions
auction_items
bids
```
## Bidder places bid
```
1. Backend locks auction item row
2. Backend reads current_price
3. Backend reads auction_session_rules
4. Backend checks bid amount >= current_price + min_increment
5. Backend checks bid amount <= current_price + max_increment if max_increment exists
6. Backend inserts new bid
7. Old winning bid becomes OUTBID
8. New bid becomes WINNING
9. auction_items.current_price is updated
10. Previous bidder money can be released
11. New bidder money can be locked
```
