# Pet Shop AWS — Document 1: Cost Control and Resource Cleanup
# Main Problem
While learning AWS, you can create Pet Shop resources and forget that they remain active. AWS can continue charging until resources are stopped or deleted.
This document must be completed before the infrastructure documents because it protects you from unexpected costs while practising.
A budget is a warning system, not a guaranteed spending limit:
```
AWS detects that a threshold was crossed
        ↓
AWS sends a notification
        ↓
You inspect Cost Explorer
        ↓
You stop or delete unnecessary resources
```
Standard budget notifications do not automatically stop EC2, RDS, Load Balancers, or NAT Gateways.
## Problem 1: Create the monthly budget
## Solution
Create one cost budget:
```
Budget name: pet-shop-learning-monthly-budget
Budget type: Cost budget
Period: Monthly
Renewal: Recurring
Amount: USD 5
Scope: All AWS services
```
Use the IAM administrator for normal work. Do not sign in as the root user only to create or view the budget unless account-level billing access must first be enabled.
Checklist:
```
[ ] Open Billing and Cost Management
[ ] Open Budgets
[ ] Choose Create budget
[ ] Select a monthly recurring cost budget
[ ] Enter USD 5
[ ] Include all AWS services
[ ] Create the budget
```
## Problem 2: Create the budget notifications
## Solution
Add these notifications:

|Threshold|Basis|Amount for USD 5|Required action|
|---|---|---|---|
|50%|Actual|USD 2.50|Early review|
|80%|Actual|USD 4.00|Inspect every active resource|
|100%|Actual|USD 5.00|Stop or delete unnecessary resources immediately|
|80%|Forecasted, optional|Predicted USD 4.00|AWS predicts the budget may be exceeded|
For every notification:
```
Threshold type: Percentage of budget
Email recipient: Your normal email address
```
Actual notifications are normally sent when the threshold is first crossed during the budget period. Do not rely on them as repeating reminders.
Checklist:
```
[ ] Add 50% actual
[ ] Add 80% actual
[ ] Add 100% actual
[ ] Optionally add 80% forecasted
[ ] Verify the email address on every notification
```
## Problem 3: Review spending correctly
## Solution
Open:
```
Billing and Cost Management
→ Cost Explorer
```
Configure:
```
Date range: Current month
Granularity: Daily
Group by: Service
```
Common Pet Shop cost categories include:

|   |   |
|---|---|
|Cost Explorer category|Possible source|
|Amazon EC2|EC2 instance compute|
|EC2 Other|EBS volumes and some related charges|
|Amazon VPC|Public IPv4 or NAT Gateway charges|
|Amazon RDS|MySQL compute, storage, and backups|
|Amazon S3|React files, images, versions, requests, and storage|
|Amazon CloudFront|Frontend and image delivery|
|Amazon CloudWatch|Logs, metrics, and alarms|
|Amazon Route 53|Hosted zones, domains, and health checks|
Cost information can be delayed. A newly generated charge may not appear immediately.
## Problem 4: Stop EC2 safely
## Solution
When you finish practising:
```
EC2
→ Instances
→ pet-shop-backend-ec2
→ Instance state
→ Stop instance
```
Use **Stop** when you want to reuse the server. Use **Terminate** only when the instance is no longer required.
A stopped instance can still generate charges for:
```
EBS volumes
EBS snapshots
Elastic IP addresses
Other public IPv4 allocation
CloudWatch logs and custom metrics
```
Before termination, confirm whether you need:
```
Spring Boot configuration
Nginx configuration
TLS configuration
Application logs
Deployment artifacts
Locally stored files
```
Important: a normal auto-assigned public IPv4 address can change after EC2 is stopped and started. An Elastic IP is stable but AWS charges for public IPv4 addresses, including Elastic IPs.
## Problem 5: Stop or delete RDS safely
## Solution
When supported by the selected RDS configuration:
```
RDS
→ Databases
→ pet-shop-mysql
→ Actions
→ Stop temporarily
```
Stopping RDS reduces database compute usage, but storage and backup charges can continue. A temporarily stopped DB instance can restart automatically after AWS's supported stop period.
When the database is no longer required:
```
Decide whether its data is required
        ↓
Create and verify a final snapshot if required
        ↓
Delete the RDS instance
        ↓
Review retained manual snapshots
```
Do not delete RDS until you have reviewed Pet Shop data such as users, products, inventory, carts, orders, payments, and product images.
## Problem 6: Avoid expensive services before they are required
## Solution
Do not create these in the learning architecture:
```
NAT Gateway
Application Load Balancer
Multi-AZ RDS
RDS Proxy
AWS WAF
```
Why:
```
NAT Gateway → hourly and data-processing charges
Load Balancer → continues charging independently of EC2
Multi-AZ RDS → additional database resources for availability
RDS Proxy → additional managed proxy cost
WAF → rules and request-related cost
```
Stopping EC2 does not stop or delete a Load Balancer or NAT Gateway.
If a NAT Gateway was created accidentally:
```
[ ] Delete the NAT Gateway
[ ] Remove or replace blackhole routes
[ ] Release its Elastic IP if no longer required
```
Deleting a public NAT Gateway does not automatically release its Elastic IP.
## Problem 7: Check leftover EC2 resources
## Solution
Check:
```
EC2 → Volumes
EC2 → Snapshots
EC2 → Elastic IP addresses
EC2 → Load Balancers
EC2 → Target groups
```
For an EBS volume in `Available` state:
```
It exists
AND
It is not attached
```
Delete it only after confirming its data is unnecessary.
Release an unused Elastic IP only after checking:
```
DNS records
React API configuration
Firewall allowlists
External integrations
```
After release, assume that you will not receive the same address again.
## Problem 8: Check S3 and CloudFront
## Solution
Check S3 for:
```
Unused React builds
Old product images
Incomplete multipart uploads
Old noncurrent versions
Old database exports
Abandoned uploads
```
If versioning is enabled, deleting the current object may create a delete marker while older versions remain billable.
Check CloudFront for unused distributions. A distribution normally must be disabled before deletion.
Do not delete a bucket or distribution until you confirm that the React frontend and product images no longer depend on it.
## Problem 9: Check Route 53 and domains
## Solution
Review:
```
Hosted zones
DNS records
Registered domains
Health checks
Automatic domain renewal
```
Deleting EC2, CloudFront, or S3 does not delete a Route 53 hosted zone or domain registration.
## Problem 10: Control CloudWatch costs
## Solution
Review:
```
Log groups
Retention settings
Custom metrics
Alarms
Dashboards
```
Use finite retention for learning logs:
```
Recommended: 7–14 days
```
Do not retain every development log forever.
## Problem 11: Tag resources consistently
## Solution
Where supported, add:
```
Project: pet-shop
Environment: learning
Owner: your-name
ManagedBy: manual
```
Tags help identify resources but do not replace careful verification before deletion.
