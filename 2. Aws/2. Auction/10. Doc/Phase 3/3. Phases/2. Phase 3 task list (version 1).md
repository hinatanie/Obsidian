# Document 3 Review
# Main Problem
Your Pet Shop application needs a private MySQL database and a continuously running Spring Boot backend.
The target architecture is:
```
React frontend
      ↓
HTTP or HTTPS
      ↓
Nginx on EC2
      ↓
Spring Boot on 127.0.0.1:8080
      ↓
Private VPC connection
      ↓
Amazon RDS MySQL
```
The main AWS responsibilities are:
```
EC2:
- Runs the Spring Boot backend
- Handles REST API requests
- Connects privately to RDS
- Runs Nginx
- Runs the Spring Boot application as a service
RDS:
- Runs MySQL
- Stores Pet Shop application data
- Remains inaccessible from the public internet
S3 and CloudFront, later:
- Host the React production build
- Deliver pet and product images
```
Complete the following tasks in order.

# Problem 10: Create database users for Spring Boot
## Solution
Do not use the RDS master user as the permanent Spring Boot application user.
For a simple learning setup, create:
```
pet_shop_app
```
Connect using the master user and run:
```
CREATE USER 'pet_shop_app'@'%'
IDENTIFIED BY 'REPLACE_WITH_A_STRONG_PASSWORD';
```
Grant application data permissions:
```
GRANT SELECT,
      INSERT,
      UPDATE,
      DELETE
ON pet_shop.*
TO 'pet_shop_app'@'%';
```
If Flyway will execute migrations automatically, create a separate migration user:
```
CREATE USER 'pet_shop_migration'@'%'
IDENTIFIED BY 'REPLACE_WITH_ANOTHER_STRONG_PASSWORD';
```
Grant schema-migration permissions:
```
GRANT SELECT,
      INSERT,
      UPDATE,
      DELETE,
      CREATE,
      ALTER,
      DROP,
      INDEX,
      REFERENCES
ON pet_shop.*
TO 'pet_shop_migration'@'%';
```
Modern MySQL applies `CREATE USER` and `GRANT` statements immediately. `FLUSH PRIVILEGES` is not required after these statements.
Checklist:
```
[ ] Create pet_shop_app
[ ] Give it a unique strong password
[ ] Grant access only to pet_shop
[ ] Grant only normal data permissions
[ ] Create pet_shop_migration if Flyway runs automatically
[ ] Give the migration user a different password
[ ] Do not use pet_shop_admin in Spring Boot permanently
[ ] Store all passwords securely
```
Separating these users gives the following result:
```
pet_shop_admin
└── RDS administration only
pet_shop_migration
└── Creates and changes tables through Flyway
pet_shop_app
└── Reads and changes application data
```

# Problem 12: Configure Spring Boot production variables
## Solution
Do not commit the production RDS credentials.
Create a production configuration that reads environment variables.
Example `application-prod.yml`:
```
spring:
  datasource:
    url: jdbc:mysql://${DB_HOST}:${DB_PORT:3306}/${DB_NAME}?useSSL=true&serverTimezone=UTC
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}
  jpa:
    hibernate:
      ddl-auto: validate
    open-in-view: false
  flyway:
    enabled: true
    user: ${DB_MIGRATION_USERNAME}
    password: ${DB_MIGRATION_PASSWORD}
server:
  address: ${SERVER_ADDRESS:127.0.0.1}
  port: ${SERVER_PORT:8080}
management:
  endpoints:
    web:
      exposure:
        include: health,info
  endpoint:
    health:
      show-details: never
```
Create a protected environment file on EC2:
```
SPRING_PROFILES_ACTIVE=prod
DB_HOST=pet-shop-mysql.xxxxxx.ap-southeast-1.rds.amazonaws.com
DB_PORT=3306
DB_NAME=pet_shop
DB_USERNAME=pet_shop_app
DB_PASSWORD=application-password
DB_MIGRATION_USERNAME=pet_shop_migration
DB_MIGRATION_PASSWORD=migration-password
SERVER_ADDRESS=127.0.0.1
SERVER_PORT=8080
```
Protect it:
```
chmod 600 /path/to/pet-shop.env
```
Do not commit this environment file.
Checklist:

# Problem 16: Run Spring Boot as a systemd service
## Solution

```
/etc/systemd/system/pet-shop-backend.service
```
Example:
```
[Unit]
Description=Pet Shop Spring Boot Backend
After=network-online.target
Wants=network-online.target
[Service]
User=ubuntu
Group=ubuntu
WorkingDirectory=/opt/pet-shop
EnvironmentFile=/etc/pet-shop/pet-shop.env
ExecStart=/usr/bin/java -jar /opt/pet-shop/pet-shop-backend.jar
SuccessExitStatus=143
Restart=on-failure
RestartSec=5
TimeoutStopSec=30

WantedBy=multi-user.target

sudo systemctl daemon-reload

# Problem 17: Configure Nginx for Spring Boot
## Solution
Nginx receives public requests and forwards them to Spring Boot.
Example:
```
server {
    listen 80;
    server_name your-domain-or-public-ip;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```
Test the configuration:
```
sudo nginx -t
```
Reload Nginx:
```
sudo systemctl reload nginx
```
Test:
```
curl http://YOUR_EC2_PUBLIC_IP/actuator/health
```

```

[ ] Keep only ports 80 and 443 public
[ ] Keep port 22 restricted to your IP

# Problem 18: Configure React to call the backend
## Solution
During local React development:
```
React: http://localhost:5173
Backend: http://EC2_PUBLIC_IP
```
Example React environment variable:
```
VITE_API_BASE_URL=http://EC2_PUBLIC_IP/api
```
Do not hard-code the API address throughout React source files. Read it through one configuration layer.
Spring Boot must allow only trusted frontend origins through CORS.
Development example:
```
http://localhost:5173
```
Later production example:
```
https://shop.example.com
```
Do not use unrestricted CORS with credentials:
```
Access-Control-Allow-Origin: *
Access-Control-Allow-Credentials: true
```
That combination is unsafe and browsers do not permit wildcard origins with credentialed requests.
Checklist:
