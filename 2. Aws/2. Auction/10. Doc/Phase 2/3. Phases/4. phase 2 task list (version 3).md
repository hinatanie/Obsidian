# Pet Shop AWS — Document 2: VPC and Network Foundation
# Main Problem
The Pet Shop application needs a secure AWS network before EC2 Spring Boot and RDS MySQL are created.
The approved learning architecture is:
```
Internet
   ↓
Public subnet
   └── EC2: Nginx + Spring Boot
Private subnets in two Availability Zones
   └── RDS MySQL
```
This stage intentionally avoids a NAT Gateway and Application Load Balancer.
## Problem 1: Create the VPC
## Solution
Create:
```
Name: pet-shop-vpc
Region: ap-southeast-1
IPv4 CIDR: 10.0.0.0/16
Tenancy: Default
```
Do not use the default VPC for this project.
Checklist:
```
[ ] Open VPC
[ ] Open Your VPCs
[ ] Select Create VPC
[ ] Choose VPC only
[ ] Enter pet-shop-vpc
[ ] Enter 10.0.0.0/16
[ ] Create the VPC
```
## Problem 2: Enable VPC DNS
## Solution
Enable:
```
DNS resolution
DNS hostnames
```
Spring Boot connects to RDS using a DNS endpoint, not a hard-coded database IP address.
Checklist:
```
[ ] Select pet-shop-vpc
[ ] Open Actions → Edit VPC settings
[ ] Enable DNS resolution
[ ] Enable DNS hostnames
```
## Problem 3: Create the public EC2 subnet
## Solution
Create:
```
Name: pet-shop-public-subnet-1
VPC: pet-shop-vpc
Availability Zone: ap-southeast-1a
IPv4 CIDR: 10.0.1.0/24
Auto-assign public IPv4: Enabled
```
This subnet will contain:
```
EC2
Java
Spring Boot
Nginx
Systems Manager Agent
```
A public route alone is insufficient for IPv4 internet access. The EC2 instance also needs a public IPv4 address or Elastic IP.
## Problem 4: Create the private RDS subnets
## Solution
Create:

|Name|Availability Zone|CIDR|Auto-assign public IPv4|
|---|---|---|---|
|pet-shop-private-subnet-1|ap-southeast-1a|10.0.2.0/24|Disabled|
|pet-shop-private-subnet-2|ap-southeast-1b|10.0.3.0/24|Disabled|
RDS DB subnet groups need subnet coverage across at least two Availability Zones.
Creating two private subnets does not automatically create a Multi-AZ RDS deployment. The initial database can still be Single-AZ.
Checklist:
```
[ ] Create pet-shop-private-subnet-1
[ ] Use ap-southeast-1a and 10.0.2.0/24
[ ] Disable automatic public IPv4
[ ] Create pet-shop-private-subnet-2
[ ] Use ap-southeast-1b and 10.0.3.0/24
[ ] Disable automatic public IPv4
```
## Problem 5: Create and attach the Internet Gateway
## Solution
Create:
```
Name: pet-shop-igw
```
Attach it to:
```
pet-shop-vpc
```
Creating and attaching it does not make a subnet public. The public subnet also needs a route to it.
## Problem 6: Create the public route table
## Solution
Create:
```
Name: pet-shop-public-rt
VPC: pet-shop-vpc
```
Routes:
```
10.0.0.0/16 → local
0.0.0.0/0   → pet-shop-igw
```
Associate it with:
```
pet-shop-public-subnet-1
```
Checklist:
```
[ ] Create pet-shop-public-rt
[ ] Add 0.0.0.0/0 → pet-shop-igw
[ ] Associate the public subnet explicitly
```
## Problem 7: Create the private route table
## Solution
Create:
```
Name: pet-shop-private-rt
VPC: pet-shop-vpc
```
Initial routes:
```
10.0.0.0/16 → local
```
Associate it with:
```
pet-shop-private-subnet-1
pet-shop-private-subnet-2
```
Do not add:
```
0.0.0.0/0 → Internet Gateway
0.0.0.0/0 → NAT Gateway
```
RDS does not need general outbound internet access.
## Problem 8: Create the backend security group
## Solution
Create:
```
Name: pet-shop-backend-sg
Description: Security group for Pet Shop Spring Boot EC2 backend
VPC: pet-shop-vpc
```
Preferred inbound rules after Systems Manager works:

|   |   |   |   |
|---|---|---|---|
|Type|Port|Source|Purpose|
|HTTP|80|0.0.0.0/0|HTTP and certificate validation; later redirect to HTTPS|
|HTTPS|443|0.0.0.0/0|Public API traffic|
Do not open:
```
Spring Boot 8080 from 0.0.0.0/0
MySQL 3306
All traffic
```
If Systems Manager is not ready, temporarily add:
```
SSH TCP 22 from your-current-public-IP/32
```
Remove SSH after Systems Manager succeeds.
Spring Boot must eventually listen only on:
```
127.0.0.1:8080
```
Final request path:
```
Internet 443
    ↓
Nginx
    ↓
127.0.0.1:8080
    ↓
Spring Boot
```
## Problem 9: Create the RDS security group
## Solution
Create:
```
Name: pet-shop-rds-sg
Description: Security group for Pet Shop RDS MySQL
VPC: pet-shop-vpc
```
Inbound:
```
Type: MySQL/Aurora
Protocol: TCP
Port: 3306
Source: pet-shop-backend-sg
```
Do not allow:
```
3306 from 0.0.0.0/0
3306 from your laptop IP
```
The security-group relationship allows network traffic, but Spring Boot still needs valid MySQL credentials.
## Problem 10: Create the RDS DB subnet group
## Solution
Create:
```
Name: pet-shop-db-subnet-group
Description: Private subnets for Pet Shop RDS
VPC: pet-shop-vpc
```
Add:
```
pet-shop-private-subnet-1 → ap-southeast-1a
pet-shop-private-subnet-2 → ap-southeast-1b
```
When RDS is created later, use:
```
DB subnet group: pet-shop-db-subnet-group
Public access: No
Security group: pet-shop-rds-sg
```
## Problem 11: Configure the EC2 IAM role and Session Manager
## Solution
Create:
```
Role: pet-shop-backend-ec2-role
Trusted service: EC2
```
Attach initially:
```
AmazonSSMManagedInstanceCore
```
Later attach only narrowly scoped policies for:
```
Product-image S3 access
CloudWatch Agent
Parameter Store parameters
```
Do not attach AdministratorAccess or AmazonS3FullAccess.
Session Manager requires:
```
SSM Agent running
The EC2 IAM role attached
Outbound access to Systems Manager service endpoints
Permission for your administrator identity to start a session
```
Because the learning EC2 instance is public and has an Internet Gateway route, it can reach the public Systems Manager endpoints without a NAT Gateway.
## Problem 12: Decide on the S3 Gateway Endpoint
## Solution
An S3 Gateway Endpoint is optional during initial networking.
It can later route EC2-to-S3 traffic through the AWS network without a NAT Gateway and has no additional endpoint charge.
Add it when S3 integration begins:
```
Service: S3 Gateway Endpoint
VPC: pet-shop-vpc
Route table: pet-shop-public-rt
Endpoint policy: Restrict where practical
```
Do not confuse a Gateway Endpoint with an Interface Endpoint; their pricing and behavior differ.
## Problem 13: Do not enable VPC Flow Logs without a reason
## Solution
Enable Flow Logs later when diagnosing or monitoring:
```
EC2-to-RDS timeouts
Rejected network traffic
Unexpected connection attempts
Routing problems
```
Flow Logs can generate log-ingestion and storage costs. Set finite retention.

# Expected architecture
```
pet-shop-vpc 10.0.0.0/16
│
├── pet-shop-public-subnet-1 10.0.1.0/24, ap-southeast-1a
│   ├── pet-shop-public-rt → pet-shop-igw
│   └── Future EC2: Nginx + Spring Boot
│
├── pet-shop-private-subnet-1 10.0.2.0/24, ap-southeast-1a
│   └── pet-shop-private-rt → local only
│
└── pet-shop-private-subnet-2 10.0.3.0/24, ap-southeast-1b
    └── pet-shop-private-rt → local only
pet-shop-rds-sg
└── MySQL 3306 from pet-shop-backend-sg only
```
# Acceptance criteria
```
[ ] The public subnet has an Internet Gateway route
[ ] The private subnets do not have a direct internet route
[ ] RDS subnet coverage includes two Availability Zones
[ ] RDS port 3306 is not public
[ ] Spring Boot port 8080 is not public
[ ] SSH is absent or restricted to one current IP temporarily
[ ] No NAT Gateway or Load Balancer was created
```
