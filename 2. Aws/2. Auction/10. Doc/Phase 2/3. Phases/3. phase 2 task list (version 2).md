# Document 2 Review
# Main Problem
Your Pet Shop application needs a secure AWS network before you create the EC2 Spring Boot backend and the RDS MySQL database.
The target application is:
```
Frontend: React
Backend: Spring Boot
Database: MySQL
```
The initial AWS network will be:
```
pet-shop-vpc
├── Public subnet
│   └── EC2 Spring Boot backend
└── Private subnets
    └── RDS MySQL
```
The EC2 instance will later run:
```
Java
Spring Boot
Embedded Tomcat
Nginx
```
The React frontend can initially run locally. Later, you can deploy it through:
```
Amazon S3
    ↓
Amazon CloudFront
```
Complete the following tasks in order.
# Problem 1: Create the Pet Shop VPC
## Solution
Create a dedicated VPC for the Pet Shop application.
```
Name: pet-shop-vpc
IPv4 CIDR: 10.0.0.0/16
IPv6 CIDR: None
Tenancy: Default
```
In the AWS Console:
1. Open:
```
VPC
```
2. Select:
```
Your VPCs
```
3. Select:
```
Create VPC
```
4. Choose:
```
VPC only
```
5. Enter the configuration shown above.
Checklist:
```
[ ] Open the VPC Console
[ ] Select Your VPCs
[ ] Select Create VPC
[ ] Choose VPC only
[ ] Enter pet-shop-vpc
[ ] Enter 10.0.0.0/16
[ ] Keep default tenancy
[ ] Create the VPC
```
Do not use the default VPC for this project. A dedicated VPC makes the Pet Shop network easier to understand and manage.
# Problem 2: Enable VPC DNS settings
## Solution
Spring Boot will connect to RDS using an RDS DNS endpoint similar to:
```
pet-shop-mysql.xxxxxxxxx.ap-southeast-1.rds.amazonaws.com
```
Therefore, DNS resolution must work inside the VPC.
After creating the VPC:
1. Select:
```
pet-shop-vpc
```
2. Open:
```
Actions
→ Edit VPC settings
```
3. Confirm that these settings are enabled:
```
DNS resolution: Enabled
DNS hostnames: Enabled
```
Checklist:
```
[ ] Enable DNS resolution
[ ] Enable DNS hostnames
```
Do not put a hard-coded RDS IP address in Spring Boot. RDS IP addresses can change.
Use the RDS endpoint in your Spring Boot configuration:
```
spring.datasource.url=jdbc:mysql://RDS_ENDPOINT:3306/pet_shop
```
# Problem 3: Create the public subnet
## Solution
This subnet will contain the EC2 instance running:
```
Java
Spring Boot
Embedded Tomcat
Nginx
Pet Shop backend API
```
Create:
```
Name: pet-shop-public-subnet-1
VPC: pet-shop-vpc
Availability Zone: ap-southeast-1a
IPv4 CIDR: 10.0.1.0/24
```
Checklist:
```
[ ] Open Subnets
[ ] Select Create subnet
[ ] Select pet-shop-vpc
[ ] Create pet-shop-public-subnet-1
[ ] Use 10.0.1.0/24
[ ] Use ap-southeast-1a
[ ] Enable auto-assign public IPv4
```
The future EC2 instance will be created in this subnet.
The subnet needs both of the following before EC2 can access the internet:
```
Route to an Internet Gateway
AND
Public IPv4 address on EC2
```
A route to an Internet Gateway alone is not enough. AWS requires an instance in a public subnet to have a public IPv4 address or Elastic IP address for IPv4 internet communication. [AWS Internet Gateway documentation](https://docs.aws.amazon.com/vpc/latest/userguide/VPC_Internet_Gateway.html?utm_source=chatgpt.com)

# Problem 5: Create the second private subnet
## Solution
An RDS DB subnet group must cover at least two different Availability Zones. [Amazon RDS VPC documentation](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/USER_VPC.WorkingWithRDSInstanceinaVPC.html?utm_source=chatgpt.com)
Create:
```
Name: pet-shop-private-subnet-2
VPC: pet-shop-vpc
Availability Zone: ap-southeast-1b
IPv4 CIDR: 10.0.3.0/24
```
Checklist:
```
[ ] Create pet-shop-private-subnet-2
[ ] Use 10.0.3.0/24
[ ] Use ap-southeast-1b
[ ] Keep auto-assign public IPv4 disabled
```
The result will be:
```
pet-shop-private-subnet-1
├── CIDR: 10.0.2.0/24
└── AZ: ap-southeast-1a
pet-shop-private-subnet-2
├── CIDR: 10.0.3.0/24
└── AZ: ap-southeast-1b
```
Creating two private subnets does not automatically mean that you are creating a Multi-AZ RDS deployment. It only gives RDS the required subnet coverage and allows you to choose Single-AZ or Multi-AZ later.
For a low-cost learning environment, you can initially choose a Single-AZ RDS DB instance.

Create:

```
Name: pet-shop-igw
```
Checklist:

# Problem 7: Create the public route table
## Solution
Create:
```
Name: pet-shop-public-rt
VPC: pet-shop-vpc
```
Add this route:
```
Destination: 0.0.0.0/0
Target: pet-shop-igw
```
The route table will already contain the local route:
```
10.0.0.0/16 → local
```
Associate the route table with:
```
pet-shop-public-subnet-1
```
Checklist:
```
[ ] Create pet-shop-public-rt
[ ] Select pet-shop-vpc
[ ] Add 0.0.0.0/0 → pet-shop-igw
[ ] Associate it with pet-shop-public-subnet-1
```
The completed route table will look like:
```
10.0.0.0/16 → local
0.0.0.0/0   → pet-shop-igw
```
A subnet is considered public when its route table has a direct route to an Internet Gateway. [AWS subnet documentation](https://docs.aws.amazon.com/vpc/latest/userguide/configure-subnets.html?utm_source=chatgpt.com)

```

```

Do not add:
```
0.0.0.0/0 → pet-shop-igw
```
Associate the private route table with:
```
pet-shop-private-subnet-1
pet-shop-private-subnet-2
```
Checklist:
```
[ ] Create pet-shop-private-rt
[ ] Confirm it contains the local route
[ ] Do not add an Internet Gateway route
[ ] Associate it with pet-shop-private-subnet-1
[ ] Associate it with pet-shop-private-subnet-2
```
The local route allows resources in the VPC to communicate through their private IP addresses when their security groups and network rules allow it.
The expected private route table is:
```
10.0.0.0/16 → local
```
This means that RDS can communicate with the Spring Boot EC2 instance, but RDS does not have a direct route to the public internet.
# Problem 9: Create the Spring Boot backend security group
## Solution
This security group protects the EC2 instance running the Spring Boot backend.
Create:
```
Name: pet-shop-backend-sg
Description: Security group for Pet Shop Spring Boot backend
VPC: pet-shop-vpc
```
## HTTP rule
Add:
```
Type: HTTP
Protocol: TCP
Port: 80
Source: 0.0.0.0/0
```
Nginx will receive HTTP requests on port `80`.
## HTTPS rule
Add:
```
Type: HTTPS
Protocol: TCP
Port: 443
Source: 0.0.0.0/0
```
Nginx will receive HTTPS requests on port `443` after HTTPS is configured.
Opening port `443` does not automatically enable HTTPS. You must later configure:
```
Domain name
DNS record
TLS certificate
Nginx HTTPS configuration
```
## SSH rule
Add:
```
Type: SSH
Protocol: TCP
Port: 22
Source: My IP
```
Do not use:
```
Port: 22
Source: 0.0.0.0/0
```
Your public IP address may change. If SSH stops working later, check whether the security-group source still matches your current public IP.
## Temporary Spring Boot testing rule
Spring Boot commonly runs its embedded server on port `8080`.
For temporary testing, you may add:
```
Type: Custom TCP
Protocol: TCP
Port: 8080
Source: My IP
```
Do not use:
```
Port: 8080
Source: 0.0.0.0/0
```
That would expose Spring Boot directly to everyone and bypass Nginx.
For temporary testing, Spring Boot must listen on an interface accessible from outside EC2:
```
server.address=0.0.0.0
server.port=8080
```
The temporary request flow is:
```
Your computer
    ↓
EC2 public IPv4:8080
    ↓
Spring Boot embedded server
```
After Nginx is working:
```
[ ] Remove the temporary port 8080 inbound rule
[ ] Do not expose port 8080 publicly
[ ] Let Nginx forward requests internally
```
The final request flow will be:
```
Internet
    ↓
Port 80 or 443
    ↓
Nginx
    ↓
127.0.0.1:8080
    ↓
Spring Boot
```
For the final configuration, Spring Boot can listen only on:
```
server.address=127.0.0.1
server.port=8080
```
Example Nginx upstream:
```
location / {
    proxy_pass http://127.0.0.1:8080;
}
```
Do not expose Spring Boot Actuator endpoints such as these to the public internet:
```
/actuator/env
/actuator/configprops
/actuator/beans
/actuator/heapdump
```
Backend security-group checklist:
```
[ ] Create pet-shop-backend-sg
[ ] Allow HTTP port 80 from anywhere
[ ] Allow HTTPS port 443 from anywhere
[ ] Allow SSH port 22 from your IP only
[ ] Optionally allow port 8080 from your IP temporarily
[ ] Do not expose port 8080 to 0.0.0.0/0
[ ] Remove the port 8080 rule after Nginx works
[ ] Do not expose sensitive Actuator endpoints
```
# Problem 10: Create the RDS security group
## Solution
Create:
```
Name: pet-shop-rds-sg
Description: Security group for Pet Shop RDS MySQL
VPC: pet-shop-vpc
```
Add this inbound rule:
```
Type: MySQL/Aurora
Protocol: TCP
Port: 3306
Source: pet-shop-backend-sg
```
Do not use:
```
Source: 0.0.0.0/0
```
Do not use your laptop IP as the permanent source.
The connection path will be:
```
Spring Boot EC2
pet-shop-backend-sg
        ↓
Private VPC network
        ↓
MySQL port 3306
        ↓
RDS MySQL
pet-shop-rds-sg
```
Using the backend security group as the source means that resources associated with that security group can send traffic to MySQL, subject to the applicable networking rules.
It does not mean:
```
Every EC2 instance can access RDS
```
It means:
```
A resource attached to pet-shop-backend-sg
can attempt to connect to port 3306
```
MySQL authentication is still required:
```
Database username
Database password
Database name
```
Checklist:
```
[ ] Create pet-shop-rds-sg
[ ] Allow MySQL port 3306
[ ] Set the source to pet-shop-backend-sg
[ ] Do not allow port 3306 from the internet
[ ] Do not make RDS publicly accessible
[ ] Do not add your laptop IP as the permanent source
```

# Problem 12: Do not create a NAT Gateway yet
## Solution
Do not create a NAT Gateway during the initial Pet Shop deployment.
The current architecture is:
```
Spring Boot EC2 → Public subnet
RDS MySQL       → Private subnets
```
RDS does not need general internet access.
The EC2 instance can access the internet through:
```
Public IPv4 address
        +
pet-shop-public-rt
        +
pet-shop-igw
```
Checklist:
```
[ ] Do not create a NAT Gateway
[ ] Create one only if a future private resource needs outbound internet access
```
This avoids unnecessary AWS charges.
# Problem 13: Decide whether to create an S3 Gateway Endpoint
## Solution
An S3 Gateway Endpoint is not required for the first network setup because the EC2 instance in the public subnet can reach S3 through the Internet Gateway.
The initial upload flow could be:
```
React
    ↓
Spring Boot API
    ↓
Amazon S3
```
A better direct-upload flow can later use a presigned URL:
```
React requests presigned URL
    ↓
Spring Boot authorizes the request
    ↓
Spring Boot returns presigned URL
    ↓
React uploads directly to S3
```
An S3 Gateway Endpoint provides private routing from the VPC to S3 and has no additional endpoint charge. Standard S3 and data-related charges can still apply. [AWS S3 Gateway Endpoint documentation](https://docs.aws.amazon.com/vpc/latest/privatelink/vpc-endpoints-s3.html?utm_source=chatgpt.com)
For your initial setup:
```
[ ] Do not create it until EC2 and RDS networking works
[ ] Add it later when configuring S3
```
This is a sequencing decision, not a cost warning.
# Problem 14: Enable VPC Flow Logs only when needed
## Solution
VPC Flow Logs can help diagnose questions such as:
```
Why can EC2 not connect to RDS?
Why is a connection being rejected?
Is unexpected traffic reaching the backend?
Is a security-group or network rule blocking traffic?
```
They are not required for the first working deployment.
Flow Logs can send data to:
```
CloudWatch Logs
Amazon S3
Amazon Data Firehose
```
Logs can generate storage and ingestion costs.
Checklist:
```
[ ] Complete basic EC2 and RDS networking first
[ ] Enable Flow Logs later for troubleshooting or monitoring
[ ] Set an appropriate log-retention period
[ ] Delete unused log groups after testing
```
