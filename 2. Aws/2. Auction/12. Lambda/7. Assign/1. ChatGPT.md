# Main Problem
You currently have a FastAPI backend running continuously on EC2. You are wondering:
> “How do I create a Lambda function that performs backend work?”
The important point is:
**Lambda does not need to replace your whole FastAPI backend.**
For your Auction application, the recommended architecture is:

| Backend responsibility                         | Runs on        |
| ---------------------------------------------- | -------------- |
| Register, login, create auction, place bid     | FastAPI on EC2 |
| REST API responses                             | FastAPI on EC2 |
| Current WebSocket connections and viewer count | FastAPI on EC2 |
| Automatically start scheduled auctions         | Lambda         |
| Automatically end expired auctions             | Lambda         |
| Select the winning bidder                      | Lambda         |
| Send notifications asynchronously              | Lambda later   |
AWS Lambda runs code only when something triggers it. You create a handler, connect it to a trigger, and AWS runs it without requiring you to manage another server. [AWS Lambda documentation](https://docs.aws.amazon.com/lambda/latest/dg/welcome.html?utm_source=chatgpt.com)

## Problem 1: Understand the Lambda execution flow
A Lambda function needs three main things:
```
Trigger
   ↓
Lambda handler
   ↓
Auction business logic
   ↓
MySQL database
```
For automatically ending auctions:
```
EventBridge Scheduler
        ↓ every minute
End Expired Auctions Lambda
        ↓
Find ACTIVE sessions where end_time <= now
        ↓
Select winners and close items
        ↓
Change auction session to ENDED
```
EventBridge Scheduler can invoke Lambda using recurring schedules or one-time schedules. [AWS EventBridge Scheduler documentation](https://docs.aws.amazon.com/lambda/latest/dg/with-eventbridge-scheduler.html?utm_source=chatgpt.com)
## Problem 2: Choose your first Lambda function
Do not begin by moving your complete FastAPI application into Lambda.
Start with one small background operation:
```
Function name:
auction-end-expired-sessions
```
Its responsibility should be:
1. Find auction sessions where:
```
status = ACTIVE
end_time <= current time
```
2. For every open auction item:
```
Find the current WINNING bid
```
3. If a winning bid exists:
```
item.status = SOLD
item.winner_user_id = winning bidder
item.final_price = winning bid amount
```
4. If no winning bid exists:
```
item.status = UNSOLD
```
5. Close the item:
```
item.closed_at = current time
```
6. End the session:
```
session.status = ENDED
```
This is a good Lambda operation because nobody needs to send an HTTP request to make it happen.

## Problem 9: Prevent duplicate processing
Event-driven systems can retry work. Your Lambda must therefore be **idempotent**.
That means running it twice must not end or charge the same auction twice.
Use conditions such as:
```
Only process session when status = ACTIVE
Only process item when status = OPEN
```
Inside the database transaction:
```
Lock the session
Recheck its status
Process its items
Update the session
Commit everything together
```
Expected behaviour:
```
Invocation 1 → ACTIVE becomes ENDED
Invocation 2 → sees ENDED and skips it
```
This is especially important before creating invoices, payments, emails or notifications.
