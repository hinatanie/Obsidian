For **LAM-003.7**, create one shared error system so every Lambda gets the same HTTP error behavior.
Use this file:
```
backend/app/shared/http/errors.py
```
Put this inside:
```
from dataclasses import dataclass
from app.shared.http.response import json_response
@dataclass
class AppError(Exception):
    status_code: int
    code: str
    message: str
class BadRequestError(AppError):
    def __init__(self, message: str = "Bad request"):
        super().__init__(
            status_code=400,
            code="BAD_REQUEST",
            message=message,
        )
class UnauthorizedError(AppError):
    def __init__(self, message: str = "Authentication required"):
        super().__init__(
            status_code=401,
            code="UNAUTHORIZED",
            message=message,
        )
class ForbiddenError(AppError):
    def __init__(self, message: str = "Forbidden"):
        super().__init__(
            status_code=403,
            code="FORBIDDEN",
            message=message,
        )
class NotFoundError(AppError):
    def __init__(self, message: str = "Resource not found"):
        super().__init__(
            status_code=404,
            code="NOT_FOUND",
            message=message,
        )
class ConflictError(AppError):
    def __init__(self, message: str = "Conflict"):
        super().__init__(
            status_code=409,
            code="CONFLICT",
            message=message,
        )
class ValidationError(AppError):
    def __init__(self, message: str = "Validation failed"):
        super().__init__(
            status_code=422,
            code="VALIDATION_ERROR",
            message=message,
        )
def map_exception_to_response(
    exc: Exception,
    request_id: str | None = None,
    origin: str | None = None,
) -> dict:
    if isinstance(exc, AppError):
        return json_response(
            status_code=exc.status_code,
            data={
                "error": {
                    "code": exc.code,
                    "message": exc.message,
                }
            },
            request_id=request_id,
            origin=origin,
        )
    return json_response(
        status_code=500,
        data={
            "error": {
                "code": "INTERNAL_SERVER_ERROR",
                "message": "An unexpected error occurred.",
            }
        },
        request_id=request_id,
        origin=origin,
    )
```
The important idea is:
```
business/shared code
      ↓
raises an exception
      ↓
map_exception_to_response()
      ↓
standard HTTP response
```
So instead of every Lambda doing this:
```
try:
    ...
except SomeError:
    return {
        "statusCode": 404,
        ...
    }
except AnotherError:
    ...
```
you want one shared mapper.
## Reuse your invalid JSON error
Right now in `request.py`, you probably have:
```
class InvalidJsonError(ValueError):
    pass
```
Move toward using your shared error system.
Change it to:
```
from app.shared.http.errors import BadRequestError
class InvalidJsonError(BadRequestError):
    def __init__(self, message: str = "Request body contains invalid JSON."):
        super().__init__(message)
```
Then malformed JSON automatically behaves like a `400`.
For example:
```
raise InvalidJsonError()
```
will eventually become:
```
{
  "error": {
    "code": "BAD_REQUEST",
    "message": "Request body contains invalid JSON."
  }
}
```
with HTTP:
```
400
```

## How a Lambda will use this later
A handler will become much cleaner:
```
from app.shared.http.context import build_request_context
from app.shared.http.errors import map_exception_to_response
from app.shared.http.response import json_response
def lambda_handler(event, context):
    request_context = build_request_context(event)
    try:
        # parse request
        # validate
        # call use case
        return json_response(
            status_code=200,
            data={"message": "OK"},
            request_id=request_context.request_id,
        )
    except Exception as exc:
        return map_exception_to_response(
            exc,
            request_id=request_context.request_id,
        )
```
Later in **LAM-003.19**, even this `try/except` can be centralized so every handler does not repeat it.
For now, your acceptance check is:
```
[ ] AppError exists
[ ] 400 error type exists
[ ] 401 error type exists
[ ] 403 error type exists
[ ] 404 error type exists
[ ] 409 error type exists
[ ] 422 error type exists
[ ] unknown exception becomes 500
[ ] all errors use json_response()
[ ] request ID is included
[ ] internal exception details are not exposed
[ ] one mapper controls HTTP error behavior
```
That completes **LAM-003.7**.
