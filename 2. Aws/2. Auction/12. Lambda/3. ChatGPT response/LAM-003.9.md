For **LAM-003.9**, create one shared settings module that reads configuration from environment variables.
The goal is:
```
Lambda environment variables
        ↓
app/shared/config/settings.py
        ↓
shared Settings object
        ↓
all Lambdas reuse it
```
Your assignment requires configuration like `APP_ENV`, `AWS_REGION`, `DATABASE_SECRET_ARN`, `RDS_PROXY_HOST`, `DB_NAME`, JWT algorithm, and JWT expiration settings to come from configuration rather than hardcoded production values.
Create:
```
backend/app/shared/config/settings.py
```
Use:
```
import os
from dataclasses import dataclass
from functools import lru_cache
@dataclass(frozen=True)
class Settings:
    app_env: str
    aws_region: str
    database_secret_arn: str
    rds_proxy_host: str
    db_name: str
    jwt_algorithm: str
    access_token_expire_minutes: int
def _require_env(name: str) -> str:
    value = os.getenv(name)
    if value is None or value.strip() == "":
        raise RuntimeError(
            f"Required environment variable '{name}' is not configured."
        )
    return value.strip()
def _get_int_env(
    name: str,
    default: int,
) -> int:
    raw_value = os.getenv(name)
    if raw_value is None or raw_value.strip() == "":
        return default
    try:
        return int(raw_value)
    except ValueError as exc:
        raise RuntimeError(
            f"Environment variable '{name}' must be an integer."
        ) from exc
@lru_cache(maxsize=1)
def get_settings() -> Settings:
    return Settings(
        app_env=os.getenv("APP_ENV", "dev"),
        aws_region=os.getenv(
            "AWS_REGION",
            "ap-southeast-1",
        ),
        database_secret_arn=_require_env(
            "DATABASE_SECRET_ARN"
        ),
        rds_proxy_host=_require_env(
            "RDS_PROXY_HOST"
        ),
        db_name=_require_env(
            "DB_NAME"
        ),
        jwt_algorithm=os.getenv(
            "JWT_ALGORITHM",
            "HS256",
        ),
        access_token_expire_minutes=_get_int_env(
            "ACCESS_TOKEN_EXPIRE_MINUTES",
            30,
        ),
    )
```
A few details matter here.
`APP_ENV` can safely default to:
```
dev
```
because that is not a credential.
Likewise:
```
AWS_REGION=ap-southeast-1
JWT_ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=30
```
are configuration values, not secrets.
But these should normally be required:
```
DATABASE_SECRET_ARN
RDS_PROXY_HOST
DB_NAME
```
because silently connecting to some guessed database would be dangerous.
Do **not** add things like:
```
DB_PASSWORD = "mypassword"
JWT_SECRET = "super-secret"
AWS_ACCESS_KEY_ID = "AKIA..."
AWS_SECRET_ACCESS_KEY = "..."
```
Those do not belong here.
The actual secret value will be retrieved from Secrets Manager in **LAM-003.10**.
## Add the environment variables to SAM
Open:
```
backend/template.yaml
```
You already have:
```
Globals:
  Function:
    Runtime: python3.11
    Timeout: 30
    MemorySize: 256
    Environment:
      Variables:
        APP_ENV: !Ref Environment
```
Add **non-secret configuration parameters**.
For example:
```
Parameters:
  Environment:
    Type: String
    AllowedValues:
      - dev
      - prod
    Default: dev
  DatabaseSecretArn:
    Type: String
  RdsProxyHost:
    Type: String
  DbName:
    Type: String
  JwtAlgorithm:
    Type: String
    Default: HS256
  AccessTokenExpireMinutes:
    Type: Number
    Default: 30
```
Then update:
```
Globals:
  Function:
    Runtime: python3.11
    Timeout: 30
    MemorySize: 256
    Environment:
      Variables:
        APP_ENV: !Ref Environment
        DATABASE_SECRET_ARN: !Ref DatabaseSecretArn
        RDS_PROXY_HOST: !Ref RdsProxyHost
        DB_NAME: !Ref DbName
        JWT_ALGORITHM: !Ref JwtAlgorithm
        ACCESS_TOKEN_EXPIRE_MINUTES: !Ref AccessTokenExpireMinutes
```
You generally do **not** need to set `AWS_REGION` yourself in SAM. Lambda already provides the AWS region environment at runtime.
Your Python settings code can still read:
```
os.getenv("AWS_REGION")
```

## Test missing required configuration
Remove one:
```
Remove-Item Env:RDS_PROXY_HOST
```
Then run:
```
python -c "from app.shared.config.settings import get_settings; print(get_settings())"
```
You should receive a controlled configuration error similar to:
```
RuntimeError:
Required environment variable 'RDS_PROXY_HOST' is not configured.
```
Because `get_settings()` uses:
```
@lru_cache(maxsize=1)
```
restart the Python command/process between tests, which you're already doing with `python -c`.
That cache is useful for Lambda:
```
cold start
   ↓
read settings
   ↓
cache Settings
   ↓
warm invocation
   ↓
reuse immutable Settings
```
This is safe because configuration is not request-specific.
## One important distinction
These are okay in environment variables:
```
APP_ENV
RDS_PROXY_HOST
DB_NAME
DATABASE_SECRET_ARN
JWT_ALGORITHM
```
But:
```
DATABASE_SECRET_ARN
```
is only a **pointer** to a secret.
It does **not** contain:
```
database password
JWT signing secret
```
The next task, **LAM-003.10**, will do:
```
DATABASE_SECRET_ARN
        ↓
Secrets Manager
        ↓
actual credentials
```
