Your `template.yaml` is valid. The build is failing because SAM is trying to package `greenlet==3.5.3`, which is a compiled dependency. On Windows, the normal build can have trouble resolving a Lambda-compatible Linux wheel. AWS specifically recommends `--use-container` for dependencies with native compiled code.
Do this next from `backend`:
```
docker version
```
Make sure Docker Desktop is running. Then run:
```
sam build --use-container
```
SAM will build inside a Linux container similar to the actual Lambda environment instead of using your Windows environment directly.
If it succeeds, you should get:
```
Build Succeeded
Built Artifacts  : .aws-sam/build
Built Template   : .aws-sam/build/template.yaml
```
Then check:
```
tree .aws-sam\build /F
```
### Why `greenlet` is appearing
Your current `backend/requirements.txt` likely contains:
```
greenlet==3.5.3
```
or SQLAlchemy pulls it in. Because every SAM function currently has:
```
CodeUri: .
```
SAM sees the root `requirements.txt` and tries to package those dependencies for every function.
That means this:
```
backend/
├── requirements.txt
├── app/
├── lambdas/
└── template.yaml
```
with:
```
CodeUri: .
```
causes roughly:
```
AuthApiFunction
    ↓
backend/
    ↓
requirements.txt
    ↓
greenlet
SQLAlchemy
...
```
So the error isn't caused by your minimal handlers.
