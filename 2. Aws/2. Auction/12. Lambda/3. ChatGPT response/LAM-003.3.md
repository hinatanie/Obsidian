For **LAM-003.3**, create one reusable CORS module and make your response helper use it.
Create:
```
backend/app/shared/http/cors.py
```
Put this inside:
```
import os
DEV_ORIGIN = "http://localhost:5173"
PROD_ORIGIN = os.getenv(
    "FRONTEND_ORIGIN",
    "https://your-production-frontend.example",
)
ALLOWED_ORIGINS = {
    DEV_ORIGIN,
    PROD_ORIGIN,
}
ALLOWED_METHODS = "GET,POST,PATCH,DELETE,OPTIONS"
ALLOWED_HEADERS = "Authorization,Content-Type,X-Request-Id"
def get_cors_headers(origin: str | None) -> dict[str, str]:
    headers = {
        "Access-Control-Allow-Methods": ALLOWED_METHODS,
        "Access-Control-Allow-Headers": ALLOWED_HEADERS,
    }
    if origin in ALLOWED_ORIGINS:
        headers["Access-Control-Allow-Origin"] = origin
        headers["Vary"] = "Origin"
    return headers
```
The important idea is:
```
request Origin
     ↓
get_cors_headers(origin)
     ↓
is origin allowed?
   ↙       ↘
 yes       no
 ↓          ↓
return      do not return
Access-     Allow-Origin
Control-
Allow-Origin
```
For development:
```
Origin: http://localhost:5173
```
will produce:
```
Access-Control-Allow-Origin: http://localhost:5173
```
For production, later set:
```
FRONTEND_ORIGIN=https://your-real-frontend-domain.com
```
Do not hardcode a real production domain until you know it.
Now update:
```
app/shared/http/response.py
```
so it can use the CORS helper.
For example:
```
import json
from typing import Any
from app.shared.http.cors import get_cors_headers
def json_response(
    status_code: int,
    data: Any,
    request_id: str | None = None,
    origin: str | None = None,
    headers: dict[str, str] | None = None,
) -> dict:
    response_headers = {
        "Content-Type": "application/json",
        **get_cors_headers(origin),
    }
    if request_id:
        response_headers["X-Request-Id"] = request_id
    if headers:
        response_headers.update(headers)
    return {
        "statusCode": status_code,
        "headers": response_headers,
        "body": json.dumps(data, default=str),
    }
```
Now create a helper for preflight `OPTIONS` requests in `cors.py`:
```
def cors_preflight_response(origin: str | None) -> dict:
    return {
        "statusCode": 204,
        "headers": get_cors_headers(origin),
        "body": "",
    }
```
So the complete `cors.py` can be:
```
import os
DEV_ORIGIN = "http://localhost:5173"
PROD_ORIGIN = os.getenv(
    "FRONTEND_ORIGIN",
    "https://your-production-frontend.example",
)
ALLOWED_ORIGINS = {
    DEV_ORIGIN,
    PROD_ORIGIN,
}
ALLOWED_METHODS = "GET,POST,PATCH,DELETE,OPTIONS"
ALLOWED_HEADERS = "Authorization,Content-Type,X-Request-Id"
def get_cors_headers(origin: str | None) -> dict[str, str]:
    headers = {
        "Access-Control-Allow-Methods": ALLOWED_METHODS,
        "Access-Control-Allow-Headers": ALLOWED_HEADERS,
    }
    if origin in ALLOWED_ORIGINS:
        headers["Access-Control-Allow-Origin"] = origin
        headers["Vary"] = "Origin"
    return headers
def cors_preflight_response(origin: str | None) -> dict:
    return {
        "statusCode": 204,
        "headers": get_cors_headers(origin),
        "body": "",
    }
```

```
python -c "from app.shared.http.cors import get_cors_headers; print(get_cors_headers('http://localhost:5173'))"
```
Expected roughly:
```
{
  'Access-Control-Allow-Methods': 'GET,POST,PATCH,DELETE,OPTIONS',
  'Access-Control-Allow-Headers': 'Authorization,Content-Type,X-Request-Id',

  'Vary': 'Origin'
}
```
Test a bad origin:
```
python -c "from app.shared.http.cors import get_cors_headers; print(get_cors_headers('https://evil.example'))"
```
It should **not** include:
```
Access-Control-Allow-Origin
```

```
python -c "from app.shared.http.cors import cors_preflight_response; print(cors_preflight_response('http://localhost:5173'))"
```
Expected:
```
statusCode: 204
body: ""
```
with CORS headers.
Your acceptance checklist is:
```
[ ] cors.py exists
[ ] localhost:5173 is allowed for development
[ ] production origin comes from configuration
[ ] unknown origins are not allowed
[ ] OPTIONS/preflight response exists
[ ] allowed methods are centralized
[ ] allowed headers are centralized
[ ] response.py reuses the CORS helper
[ ] no Lambda handler contains its own CORS dictionary
```
One important rule: do not use:
```
Access-Control-Allow-Origin: *
```
if your frontend will send authenticated requests with credentials/tokens. A specific allowed origin is safer and matches the architecture you’re building.
