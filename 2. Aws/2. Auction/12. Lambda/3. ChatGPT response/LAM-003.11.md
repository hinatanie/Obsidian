For **LAM-003.11**, create one shared JWT verifier that every HTTP Lambda can reuse. This task is only about **verifying an incoming token**, not issuing tokens yet.
Your existing Auction contract already uses JWT with user identity in `sub`, plus claims like email and role, so the verifier should treat the verified token as the source of identity rather than trusting request-body fields.
Create:
```
backend/app/shared/auth/jwt.py
```
Use this structure:
```
from dataclasses import dataclass
from typing import Any
import jwt
from jwt import ExpiredSignatureError
from jwt import InvalidAlgorithmError
from jwt import InvalidSignatureError
from jwt import InvalidTokenError
from app.shared.http.errors import UnauthorizedError
@dataclass(frozen=True)
class AuthClaims:
    user_id: str
    email: str | None
    role: str | None
    claims: dict[str, Any]
def verify_access_token(
    token: str,
    *,
    secret: str,
    algorithm: str,
) -> AuthClaims:
    if not token or token.strip() == "":
        raise UnauthorizedError("Access token is required.")
    try:
        payload = jwt.decode(
            token,
            secret,
            algorithms=[algorithm],
            options={
                "require": [
                    "sub",
                    "exp",
                    "iat",
                ]
            },
        )
    except ExpiredSignatureError as exc:
        raise UnauthorizedError(
            "Access token has expired."
        ) from exc
    except InvalidSignatureError as exc:
        raise UnauthorizedError(
            "Access token signature is invalid."
        ) from exc
    except InvalidAlgorithmError as exc:
        raise UnauthorizedError(
            "Access token algorithm is invalid."
        ) from exc
    except InvalidTokenError as exc:
        raise UnauthorizedError(
            "Access token is invalid."
        ) from exc
    user_id = payload.get("sub")
    if not isinstance(user_id, str) or not user_id.strip():
        raise UnauthorizedError(
            "Access token subject is invalid."
        )
    email = payload.get("email")
    role = payload.get("role")
    return AuthClaims(
        user_id=user_id,
        email=email if isinstance(email, str) else None,
        role=role if isinstance(role, str) else None,
        claims=payload,
    )
```
The important part is:
```
algorithms=[algorithm]
```
Do **not** decode using an algorithm supplied by the client. Your server configuration decides which algorithm is allowed.
The flow should be:
```
Bearer JWT
   ↓
verify_access_token()
   ↓
check signature
   ↓
check allowed algorithm
   ↓
check expiration
   ↓
check required claims
   ↓
extract sub
   ↓
AuthClaims
```
For your current token contract, these required claims are a good minimum:
```
sub
iat
exp
```
`sub` is the authenticated user ID.
So later, if the request body says:
```
{
  "userId": "someone-else",
  "role": "ADMIN"
}
```
you must **not** use those values for authentication.
Use:
```
claims.user_id
claims.role
```
from the verified token.
Even better, for sensitive authorization later, load the current user from the database using:
```
claims.user_id
```
and check the database user's current role/status. That prevents an old JWT from permanently preserving a role or ACTIVE status that has since changed.
## Where does `secret` come from?
Do not write:
```
secret = "my-super-secret"
```
Instead, it should eventually come from your LAM-003.10 Secrets Manager adapter.
Conceptually:
```
Secrets Manager
      ↓
JWT secret
      ↓
verify_access_token()
```
You may create a separate model such as:
```
@dataclass(frozen=True)
class JwtSecret:
    signing_key: str
```
and retrieve it through shared configuration.
## Test it locally
You can temporarily generate a JWT only for testing.
Create:
```
backend/test_jwt_manual.py
```
Use:
```
from datetime import datetime, timedelta, timezone
import jwt
from app.shared.auth.jwt import verify_access_token
TEST_SECRET = "local-test-secret"
ALGORITHM = "HS256"
now = datetime.now(timezone.utc)
token = jwt.encode(
    {
        "sub": "user-123",
        "email": "user@example.com",
        "role": "USER",
        "iat": now,
        "exp": now + timedelta(minutes=30),
    },
    TEST_SECRET,
    algorithm=ALGORITHM,
)
print("TOKEN CREATED")
claims = verify_access_token(
    token,
    secret=TEST_SECRET,
    algorithm=ALGORITHM,
)
print(claims)
```
Run:
```
python test_jwt_manual.py
```
Expected roughly:
```
TOKEN CREATED
AuthClaims(
    user_id='user-123',
    email='user@example.com',
    role='USER',
    ...
)
```
Do **not** print real production JWTs later. This is only a local fake-token test.

```
claims = verify_access_token(
    token,

```
Expected:

```

```

## Test wrong algorithm
For example, if your server expects:
```
HS256
```
a token using some other algorithm must not be accepted.
The verifier should always use the configured value:
```
algorithm=settings.jwt_algorithm
```
not something from the request.
## One improvement I recommend
Keep JWT verification and HTTP `Authorization` parsing separate.
LAM-003.11 should do:
```
JWT string
→ verify token
```
LAM-003.12 should do:
```
Authorization: Bearer abc...
→ extract token
→ call verify_access_token()
→ resolve current user
```
That separation makes testing much easier.
Your **LAM-003.11 checklist** is:
```
[ ] jwt.py exists
[ ] verify_access_token() exists
[ ] signature is verified
[ ] only configured algorithm is accepted
[ ] expiration is verified
[ ] sub is required
[ ] iat is required
[ ] exp is required
[ ] missing/invalid subject becomes 401
[ ] expired token becomes 401
[ ] invalid signature becomes 401
[ ] malformed token becomes 401
[ ] user identity comes from verified sub
[ ] request-body userId is never trusted
[ ] request-body role is never trusted
[ ] request-body email is never trusted
[ ] JWT secret is not hardcoded
```
Once those tests pass, **LAM-003.11 is complete**. The next step, **LAM-003.12**, will extract the Bearer token from the HTTP request and resolve the reusable authenticated current-user context.
