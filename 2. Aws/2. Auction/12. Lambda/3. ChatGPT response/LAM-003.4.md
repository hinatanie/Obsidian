For **LAM-003.4**, create one helper that gives every request a correlation ID.
The goal is:
```
API Gateway request
        ↓
requestId exists?
   ↙            ↘
 yes             no
 ↓               ↓
use it         generate UUID
        ↓
same request ID used in
logs + responses + errors
```
Create:
```
backend/app/shared/http/context.py
```
Put this inside:
```
from dataclasses import dataclass
from uuid import uuid4
@dataclass(frozen=True)
class RequestContext:
    request_id: str
def get_request_id(event: dict) -> str:
    request_context = event.get("requestContext") or {}
    request_id = request_context.get("requestId")
    if request_id:
        return request_id
    return str(uuid4())
def build_request_context(event: dict) -> RequestContext:
    return RequestContext(
        request_id=get_request_id(event),
    )
```
Why this structure?
`get_request_id()` does only one job:
```
find API Gateway request ID
or
generate one
```
`RequestContext` gives you a reusable object that can later contain more request-scoped information if needed.
For now:
```
RequestContext(
    request_id="abc-123"
)
```
## Test 1 — API Gateway already provides a request ID
From your `backend` folder:
```
python -c "from app.shared.http.context import get_request_id; print(get_request_id({'requestContext': {'requestId': 'api-123'}}))"
```
Expected:
```
api-123
```
That proves you preserve the AWS request ID instead of replacing it.
## Test 2 — No request ID exists
Run:
```
python -c "from app.shared.http.context import get_request_id; print(get_request_id({}))"
```
You should get something like:
```
2b70ee59-83d1-4ca4-818c-e57546157fa5
```
Your exact UUID will be different.
Run it twice:
```
python -c "from app.shared.http.context import get_request_id; print(get_request_id({}))"
python -c "from app.shared.http.context import get_request_id; print(get_request_id({}))"
```
You should get two different values.
## Test 3 — Test the complete context object
Run:
```
python -c "from app.shared.http.context import build_request_context; print(build_request_context({'requestContext': {'requestId': 'req-456'}}))"
```
Expected:
```
RequestContext(request_id='req-456')
```
## Use it with your response helper
You already created:
```
app/shared/http/response.py
```
Later a Lambda can do:
```
from app.shared.http.context import build_request_context
from app.shared.http.response import json_response
def lambda_handler(event, context):
    request_context = build_request_context(event)
    return json_response(
        status_code=200,
        data={
            "message": "OK",
        },
        request_id=request_context.request_id,
    )
```
If API Gateway sends:
```
{
    "requestContext": {
        "requestId": "abc-123"
    }
}
```
your response can contain:
```
X-Request-Id: abc-123
```
Then if the frontend reports:
```
Request failed.
Request ID: abc-123
```
you can search CloudWatch logs for:
```
abc-123
```
and find the same request.
That is what **correlation** means here.
## Later, use it in logs too
For example:
```
print(
    {
        "requestId": request_context.request_id,
        "message": "processing request",
    }
)
```
Then all activity for that request uses the same ID.
Do not do this:
```
response_request_id = str(uuid4())
log_request_id = str(uuid4())
error_request_id = str(uuid4())
```
because you would get:
```
response = ID-A
logs     = ID-B
error    = ID-C
```
and they could not be correlated.
You want:
```
API request
     ↓
req-123
 ┌────┼────────┐
 ↓    ↓        ↓
log response error
 ↓    ↓        ↓
req-123
```
### LAM-003.4 checklist
```
[ ] context.py exists
[ ] API Gateway requestContext.requestId is used when available
[ ] Missing request ID generates a UUID
[ ] RequestContext contains request_id
[ ] Same request ID can be passed to json_response()
[ ] Same request ID can be included in logs
[ ] Request-scoped ID is not stored as global mutable state
```
That last point matters for Lambda: don't create something like this at module level:
```
REQUEST_ID = str(uuid4())  # wrong
```
A warm Lambda could then reuse the same ID across multiple requests. Generate/build the context **inside each invocation**.
