Do only this small task now: create `backend/template.yaml` and define **one Lambda first** (`AuthApiFunction`). Don’t add all functions yet.
From your project root:
```
cd C:\Users\ADMIN\Documents\dhsg\projects\Live-Auction\backend
```
Create the file:
```
notepad template.yaml
```
Paste this exact content:
```
AWSTemplateFormatVersion: '2010-09-09'
Transform: AWS::Serverless-2016-10-31
Description: Auction Lambda backend
Parameters:
  Environment:
    Type: String
    AllowedValues:
      - dev
      - prod
    Default: dev
Globals:
  Function:
    Runtime: python3.11
    Timeout: 30
    MemorySize: 256
    Environment:
      Variables:
        APP_ENV: !Ref Environment
Resources:
  AuthApiFunction:
    Type: AWS::Serverless::Function
    Properties:
      FunctionName: !Sub auction-auth-api-${Environment}
      CodeUri: .
      Handler: lambdas.auth_api.handler.lambda_handler
```
Save the file.
Now your structure should include:
```
backend/
├── app/
├── lambdas/
│   └── auth_api/
│       └── handler.py
└── template.yaml
```
### What each part means
This:
```
Transform: AWS::Serverless-2016-10-31
```
means:
```
This CloudFormation template uses AWS SAM resources.
```
This:
```
Parameters:
  Environment:
```
lets us choose:
```
dev
or
prod
```
So later the same template can create:
```
auction-auth-api-dev
```
or:
```
auction-auth-api-prod
```
This:
```
Globals:
  Function:
    Runtime: python3.11
    Timeout: 30
    MemorySize: 256
```
means all Lambda functions will use these defaults unless we override them.
This:
```
APP_ENV: !Ref Environment
```
means inside Python later we can know whether Lambda is running as:
```
dev
```
or:
```
prod
```
without hardcoding it.
The most important part is:
```
Handler: lambdas.auth_api.handler.lambda_handler
```
It maps to:
```
lambdas/
└── auth_api/
    └── handler.py
          ↓
      lambda_handler()
```
So if `handler.py` contains:
```
def lambda_handler(event, context):
    return {
        "statusCode": 200,
        "body": "auth-api foundation ready",
    }
```
then SAM knows which Python function Lambda should execute.
### Check the file
Run:
```
Get-Content template.yaml
```
You should see the YAML you just created.
Then check that the handler exists:
```
Get-Content lambdas\auth_api\handler.py
```
You should see:
```
def lambda_handler(event, context):
```
### Important rule
Do **not** put things like this in `template.yaml`:
```
DB_PASSWORD: abc123
JWT_SECRET: my-secret
AWS_ACCESS_KEY_ID: ...
AWS_SECRET_ACCESS_KEY: ...
```
LAM-002 specifically requires the template to contain no credentials.
For now, stop when these two commands work:
```
Get-Content template.yaml
python -c "from lambdas.auth_api.handler import lambda_handler; print(lambda_handler({}, None))"
```
The second command should return something like:
```
{'statusCode': 200, 'body': 'auth-api foundation ready'}
```
