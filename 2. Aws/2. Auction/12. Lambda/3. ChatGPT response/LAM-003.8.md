For **LAM-003.8**, create one helper that takes a Python payload and a Pydantic model, then returns either a validated model or raises your shared `422` error.
Use:
```
backend/app/shared/http/validation.py
```
Put this inside:
```
from typing import TypeVar
from pydantic import BaseModel
from pydantic import ValidationError as PydanticValidationError
from app.shared.http.errors import ValidationError
T = TypeVar("T", bound=BaseModel)
def validate_payload(
    model_class: type[T],
    payload: dict,
) -> T:
    try:
        return model_class.model_validate(payload)
    except PydanticValidationError as exc:
        errors = []
        for error in exc.errors():
            location = ".".join(str(part) for part in error.get("loc", []))
            errors.append(
                {
                    "field": location,
                    "message": error.get("msg", "Invalid value"),
                    "type": error.get("type", "validation_error"),
                }
            )
        raise ValidationError(
            message="Request validation failed.",
            details=errors,
        ) from exc
```
There is one change needed first: your current shared `ValidationError` from **LAM-003.7** only contains a message. We want it to also support validation details.
Update:
```
app/shared/http/errors.py
```
Change your base `AppError` to:
```
from dataclasses import dataclass
from typing import Any
@dataclass
class AppError(Exception):
    status_code: int
    code: str
    message: str
    details: Any | None = None
```
Then change your shared validation error:
```
class ValidationError(AppError):
    def __init__(
        self,
        message: str = "Validation failed",
        details: list[dict] | None = None,
    ):
        super().__init__(
            status_code=422,
            code="VALIDATION_ERROR",
            message=message,
            details=details,
        )
```
Then update `map_exception_to_response()` so it includes details when they exist:
```
def map_exception_to_response(
    exc: Exception,
    request_id: str | None = None,
    origin: str | None = None,
) -> dict:
    if isinstance(exc, AppError):
        error_body = {
            "code": exc.code,
            "message": exc.message,
        }
        if exc.details is not None:
            error_body["details"] = exc.details
        return json_response(
            status_code=exc.status_code,
            data={
                "error": error_body,
            },
            request_id=request_id,
            origin=origin,
        )
    return json_response(
        status_code=500,
        data={
            "error": {
                "code": "INTERNAL_SERVER_ERROR",
                "message": "An unexpected error occurred.",
            }
        },
        request_id=request_id,
        origin=origin,
    )
```
Now the flow is:
```
JSON body
   ↓
parse_json_body()
   ↓
dict
   ↓
validate_payload()
   ↓
Pydantic model
```
or:
```
invalid data
   ↓
Pydantic ValidationError
   ↓
shared ValidationError
   ↓
error mapper
   ↓
HTTP 422
```

## Example for your real Auction request later
Suppose you eventually have:
```
from pydantic import BaseModel, EmailStr
class RegisterRequest(BaseModel):
    email: EmailStr
    password: str
    fullName: str
```
Your Lambda should do:
```
payload = parse_json_body(
    request.body,
    is_base64_encoded=request.is_base64_encoded,
)
validated = validate_payload(
    RegisterRequest,
    payload,
)
```
Then your use case receives:
```
validated.email
validated.password
validated.fullName
```
instead of manually doing:
```
email = payload["email"]
password = payload["password"]
```
That gives you centralized validation behavior.
### Important
Do not do this in every Lambda:
```
try:
    request = RegisterRequest(**payload)
except PydanticValidationError:
    return {
        "statusCode": 422,
        ...
    }
```
That would duplicate infrastructure.
You want:
```
all HTTP Lambdas
      ↓
validate_payload()
      ↓
shared error mapper
```
Your **LAM-003.8 checklist** is:
```
[ ] validation.py exists
[ ] validate_payload() accepts a Pydantic model
[ ] valid data returns the validated model
[ ] invalid data becomes shared ValidationError
[ ] HTTP status becomes 422
[ ] validation details are structured
[ ] raw Pydantic exceptions do not reach the frontend
[ ] Lambda handlers do not duplicate Pydantic try/except code
```
Once those tests work, **LAM-003.8 is complete**.
