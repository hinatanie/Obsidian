For **LAM-002.9**, you are not adding anything complicated. You are mainly checking that `template.yaml` has **no real secrets**.
Your assignment requires that the SAM template contain no credentials.
Open the file:
```
notepad template.yaml
```
Now look for anything like:
```
DB_PASSWORD: mypassword123
JWT_SECRET: abc123
AWS_ACCESS_KEY_ID: AKIA...
AWS_SECRET_ACCESS_KEY: ...
DATABASE_URL: mysql://user:password@...
```
If you see real values like that, remove them.
A safe `template.yaml` can contain non-secret parameters such as:
```
Parameters:
  Environment:
    Type: String
    AllowedValues:
      - dev
      - prod
    Default: dev
```
Later, when you connect Lambda to your database, you can use a reference like:
```
Parameters:
  DatabaseSecretArn:
    Type: String
```
This is safe because it stores only the **ARN/reference**, not the actual password.
For example:
```
DatabaseSecretArn
        ↓
points to Secrets Manager
        ↓
Secrets Manager contains
username/password
```
The secret itself should not be written in:
```
template.yaml
handler.py
Git repository
```
Now run this PowerShell check from `backend`:
```
Get-Content template.yaml | Select-String -Pattern "password|secret_access_key|access_key_id|jwt_secret|db_password"
```
If everything is clean, ideally you get no output.
You can also search the whole Lambda folder:
```
Get-ChildItem .\lambdas -Recurse -File |
    Select-String -Pattern "password|secret_access_key|access_key_id|jwt_secret|db_password"
```
