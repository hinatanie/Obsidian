For **LAM-003.12**, create one helper that turns the HTTP `Authorization` header into a trusted authenticated-user context.
The flow should be:
```
Authorization header
      ↓
require "Bearer <token>"
      ↓
verify_access_token()
      ↓
get user_id from verified sub claim
      ↓
load current user from database
      ↓
return AuthContext
```
This task should **reuse LAM-003.11** rather than decoding JWT again.
## 1. Create the authentication helper
Create:
```
backend/app/shared/auth/authentication.py
```
Put this inside:
```
from dataclasses import dataclass
from typing import Protocol
from app.shared.auth.jwt import verify_access_token
from app.shared.http.errors import UnauthorizedError
@dataclass(frozen=True)
class AuthenticatedUser:
    id: str
    email: str
    role: str
    status: str
@dataclass(frozen=True)
class AuthContext:
    user: AuthenticatedUser
class UserLoader(Protocol):
    def get_user_by_id(self, user_id: str):
        ...
def extract_bearer_token(
    authorization_header: str | None,
) -> str:
    if not authorization_header:
        raise UnauthorizedError(
            "Authorization header is required."
        )
    parts = authorization_header.strip().split()
    if len(parts) != 2:
        raise UnauthorizedError(
            "Authorization header is invalid."
        )
    scheme, token = parts
    if scheme.lower() != "bearer":
        raise UnauthorizedError(
            "Bearer authentication is required."
        )
    if not token:
        raise UnauthorizedError(
            "Access token is required."
        )
    return token
```
For now this gives you a reusable Bearer-token parser.

## 2. Add the current-user resolver
Continue in the same file:
```
def authenticate_user(
    *,
    authorization_header: str | None,
    jwt_secret: str,
    jwt_algorithm: str,
    user_loader: UserLoader,
) -> AuthContext:
    token = extract_bearer_token(
        authorization_header
    )
    claims = verify_access_token(
        token,
        secret=jwt_secret,
        algorithm=jwt_algorithm,
    )
    user = user_loader.get_user_by_id(
        claims.user_id
    )
    if user is None:
        raise UnauthorizedError(
            "Authenticated user no longer exists."
        )
    authenticated_user = AuthenticatedUser(
        id=str(user.id),
        email=str(user.email),
        role=str(user.role),
        status=str(user.status),
    )
    return AuthContext(
        user=authenticated_user
    )
```
The important part is:
```
claims.user_id
```
comes from the verified JWT:
```
JWT
 ↓
signature verified
 ↓
sub claim
 ↓
user ID
```
You are **not** doing:
```
user_id = request_body["userId"]
```
That would be insecure.

# 3. Why load the user from the database?
Suppose the JWT was created yesterday with:
```
{
  "sub": "user-123",
  "role": "ADMIN"
}
```
Today you change that database user to:
```
role = USER
status = BANNED
```
If you trust only the old JWT:
```
JWT says ADMIN
→ still treated as ADMIN ❌
```
Instead:
```
verified JWT
    ↓
sub=user-123
    ↓
query users table
    ↓
current database state
    ↓
role=USER
status=BANNED
```
This is much safer for the authorization work you will do in LAM-003.13 and LAM-003.14.

---
# 4. Your `UserLoader` is intentionally abstract
You may be wondering about this:
```
class UserLoader(Protocol):
    def get_user_by_id(self, user_id: str):
        ...
```
That means authentication does not need to know:
```
SQLAlchemy query details
repository implementation
MySQL details
RDS Proxy details
```
It only asks:
```
give me user with this ID
```
Later your actual user repository can satisfy that interface.
Conceptually:
```
authentication.py
      ↓
UserLoader
      ↓
UserRepository
      ↓
SQLAlchemy
      ↓
RDS Proxy
      ↓
MySQL
```
This keeps your shared authentication code cleaner.

# 12. Expired and invalid tokens require no new code
Because `authenticate_user()` calls:
```
verify_access_token(...)
```
LAM-003.11 already handles:
```
expired JWT
→ 401
bad signature
→ 401
missing sub
→ 401
malformed JWT
→ 401
```
That is exactly why we reuse the shared JWT verifier.
You should **not** repeat those checks in `authentication.py`.

---
# 13. Keep ACTIVE/ADMIN checks out of this task
LAM-003.12 should establish:
```
Who is this user?
```
It should not yet decide:
```
Is this ACTIVE?
Is this ADMIN?
```
Those belong to:
```
LAM-003.13 → ACTIVE authorization
LAM-003.14 → ADMIN authorization
```
So this is allowed:
```
AuthContext(
    user=AuthenticatedUser(
        status="BANNED"
    )
)
```
Authentication succeeded because the JWT is valid and the user exists.
Then LAM-003.13 will reject the banned account with:
```
403
```
That separation is useful:
```
Authentication
"Who are you?"
       ↓
Authorization
"Are you allowed?"
```

## Final structure
You should now have:
```
app/shared/auth/
├── __init__.py
├── jwt.py
├── authentication.py
└── authorization.py
```
And the flow becomes:
```
API Gateway
      ↓
Authorization header
      ↓
extract_bearer_token()
      ↓
verify_access_token()
      ↓
verified sub
      ↓
user repository
      ↓
current database user
      ↓
AuthContext
```
### LAM-003.12 checklist
```
[ ] authentication.py exists
[ ] Authorization header is read
[ ] Missing Authorization → UnauthorizedError
[ ] Bearer scheme is required
[ ] Malformed header → UnauthorizedError
[ ] Token is passed to shared verify_access_token()
[ ] Expired token → 401
[ ] Bad token → 401
[ ] Verified JWT sub supplies user ID
[ ] Current user is loaded using that ID
[ ] Missing database user → 401
[ ] AuthContext is returned
[ ] Request body userId is not trusted
[ ] Request body role is not trusted
[ ] JWT verification code is not duplicated
[ ] ACTIVE/ADMIN authorization is not implemented here
```
Once this works, **LAM-003.12 is complete**. The next task, LAM-003.13, can be very small because it only needs to take this `AuthContext` and enforce `status == ACTIVE`.
