## Problem 6: I need to know your asynchronous work requirements
Lambda is useful when work should happen outside the normal HTTP request.
Possible auction jobs include:
```
Automatically start an auction
Automatically end an auction
Select the winner
Send winner and loser notifications
Generate image thumbnails
Process uploaded images
Send email
Create invoices
Expire unpaid orders
Clean old WebSocket presence records
Write audit events
Process bid events
```
## Solution
Create:
```
docs/lambda-requirements.md
```
Answer these questions:
```
# Lambda Goals
Which operation do I want Lambda to perform first?
# Possible Choices
- Automatically start scheduled auctions
- Automatically end expired auctions
- Select the winning bidder
- Send email notifications
- Process uploaded auction images
- Create thumbnails
- Process bid events
- Create auction reports
- Clean expired data
- Other:
# Trigger
How should Lambda start?
- API Gateway request
- EventBridge schedule
- SQS message
- SNS notification
- S3 file upload
- DynamoDB stream
- Manual invocation
- FastAPI calling Lambda
# Expected Frequency
How often will it run?
# Expected Workload
How many auction sessions, items, bids, or images?
# Failure Behavior
What should happen if Lambda fails?
# Retry Behavior
Should AWS retry automatically?
# User Experience
Should the frontend wait for the result, or should processing happen in the background?
```
This is the most important document because it defines the actual purpose of Lambda.
