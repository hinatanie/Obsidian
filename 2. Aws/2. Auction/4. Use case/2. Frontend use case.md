### UC01 - Register User

**Goal:** Create a new account.  
**Page:**
```
/register
```
**UI fields:**
```
Email
Password
Full name
Register button
```

```
{

  "password": "123456",

```

### UC02 - Login User

**Page:**
```
/login
```
**UI fields:**
```
Email
Password
Login button
```
#### Request body
```
{
  "email": "seller@gmail.com",
  "password": "123456"
}
```
**Flow:**
```
1. User opens Login page.
2. User enters email and password.
3. User clicks Login.
4. Frontend calls POST /api/v1/auth/login.
5. Backend validates email and password.
6. Backend creates accessToken and refreshToken.
7. Backend sends refreshToken in HttpOnly cookie.
8. Frontend stores accessToken only in memory/state.
9. Redirect user to Home page.
10. If login fails, show error message.
```
##### Success response
```
{
  "status": 200,
  "code": 1000,
  "message": "Login successfully",
  "data": {
    "accessToken": "jwt-token",
    "tokenType": "Bearer",
    "user": {
      "id": "user-uuid",
      "email": "seller@gmail.com",
      "fullName": "Nguyen Van A",
      "role": "USER",
      "status": "ACTIVE"
    }
  }
}
```
### UC03 - View Auction List
**Actor:** User / Guest  
**Goal:** View available auction items.  
**Page:**
```
/auctions
```
#### Api request
#### Default load
When user opens page:
```
GET /api/v1/auctions?page=0&size=10&sort=endTime,asc
```
#### Filter by status
#### Active auctions
```
GET /api/v1/auctions?status=ACTIVE&page=0&size=10&sort=endTime,asc
```
#### Upcoming auctions
```
GET /api/v1/auctions?status=UPCOMING&page=0&size=10&sort=startTime,asc
```
#### Ended auctions
```
GET /api/v1/auctions?status=ENDED&page=0&size=10&sort=endTime,desc
```
#### Search by title
User searches:
```
iphone
```
Frontend calls:
```
GET /api/v1/auctions?title=iphone&page=0&size=10
```
#### Filter by category
```
GET /api/v1/auctions?categoryId=category-uuid
```
Recommended:
```
Use categoryId internally
Use slug for SEO URLs
```
#### Combined filter example
```
GET /api/v1/auctions?
status=ACTIVE
&categoryId=category-uuid
&title=iphone
&page=0
&size=10
&sort=endTime,asc
```

```
Search input
Status tabs:
- UPCOMING AUCTION
- ACTIVE AUCTION
- ENDED AUCTION
Category filter
Sort dropdown
Auction cards
Pagination
```
#### Auction Card Displays
Each auction card shows:
```
Primary image
Title
Categories
Starting price
Current price
Start time
End time
Status badge
View detail button
```
If auction status is ENDED:
```
Final price
Winner full name
```

```
1. User opens Auction List page.
2. Frontend calls API to get auction list:
   GET /api/v1/auctions?status=ACTIVE&page=0&size=10&sort=endTime,asc

3. Frontend sends query params if user select ACTIVE

3.1. Frontend sends query params if user select UPCOMING

12. If auction list is empty:
    - Show message: "No auctions found."

### UC04 - View Auction Detail
**Actor:** User / Guest  
**Goal:** View item detail and bid history.
**Page:**
```
/auctions/:id
```
**Flow:**
```
1. User opens Auction Detail page.
2. Frontend gets auctionId from URL.
3. Frontend calls API:
   GET /api/v1/auctions/{auctionId}
4. Backend returns auction detail.
5. Frontend displays infor of table auction_items
   - title
   - description
   - images from table item_images
   - starting price
   - current price
   - minimum bid increment
   - start time
   - end time
   - status
   - seller info from table users with (email, fullname, phone). This seller field can hit to /api/v1/users/{userId}
6. Frontend calls API to get bid history:
   GET /api/v1/auctions/{auctionId}/bids?sort=createdAt,desc
7. Frontend displays bid history.
8. Frontend checks user login status.
9. If user is not logged in
   - Hide bid input
   - Hide Place bid button
   - Show "Login to bid" button
10. If user is logged in:
    - Show bid input
    - Show Place bid button
11. Frontend checks auction status.
12. If auction status is ACTIVE:
    - Allow user to enter bid amount
13. If auction status is SCHEDULED:
    - Disable bid input
    - Show message "Auction has not started yet."
14. If auction status is ENDED:
    - Disable bid input
    - Show message "Auction has ended."
15. If auction status is CANCELLED:
    - Disable bid input
    - Show message "Auction was cancelled."
16. User clicks Back to list:
    - Redirect to /auctions
```
#### API request
```
GET /api/v1/auction-items/{itemId}
```

#### UC05 - Place Bid
**Actor:** Logged-in User  
**Goal:** Bid on an auction item.  
**Page:**
```
/auctions/:id
```
#### API request
```
POST /api/v1/auction-items/{itemId}/bids
```
##### Headers
```
Authorization: Bearer <accessToken>
Content-Type: application/json
```
##### Request body
```
{
  "amount": 13000000
}
```
#### Expected success response
```
{
  "status":201,
  "code":1000,
  "message":"Place bid successfully",
  "data": {
    "id":"bid-uuid",
    "auctionId":"1cf82699-6631-40e0-8149-7bc8d8999b1d",
    "bidderName":"Nguyen Van B",
    "amount":13000000,
    "createdAt":"2026-07-03T10:45:00"
  }
}
```
**UI fields:**
```
Bid amount input
Place bid button
Minimum valid bid text
Current price
Wallet balance
Error message
Success message
```
**Flow:**
```
1. User opens Auction Detail page /auctions/:id
2. Frontend loads auction detail:
   GET /api/v1/auctions/{auctionId}
3. Frontend checks auction status.
4. If status is ACTIVE:
   - Enable bid input
   - Enable Place bid button
5. If status is not ACTIVE:
   - Disable bid input
   - Disable Place bid button
6. User enters bid amount.
7. Frontend validates bid amount.
8. Frontend checks:
   - bid amount is not empty
   - bid amount is a number
   - bid amount > 0
   - bid amount >= currentPrice + minimumBidIncrement
   - user is logged in
   - user is not the seller
   - auction status is ACTIVE
9. User clicks Place bid.
10. Frontend sends request:
    POST /api/v1/auctions/{auctionId}/bids
11. Frontend includes accessToken in Authorization header:
    Authorization: Bearer <accessToken>
12. Backend validates bid.
13. If success:
    - Frontend clears bid input
    - Frontend updates current price
    - Frontend reloads bid history
    - Frontend shows success message
14. If failed:
    - Frontend shows error message from backend
```
### UC10 - View My Bids
**Actor:** Allow logged-in users to view all auctions where they have placed bids.  
Users can use this page to:
```
- Track auctions they are bidding on
- See their bid amount
- Check current highest bid
- Know whether they are currently winning or losing
- View auction status
- Open auction detail page
```
**Page:**
```
/my-bids
```
###### 1. UI Display
```
- Auction image
- Auction title
- My bid amount
- Current highest bid
- Bid status
- Auction status
- End time
- Bid time
- View detail button
```
###### 2. API Request - Get My Bids
**Endpoint:**
```
GET /api/v1/bids/my
```
**Headers:**
```
Authorization: Bearer <accessToken>
Content-Type: application/json
```
**Request body:**
```
No request body
```
###### 3. Expected Success Response
```
{
  "status":200,
  "code":1000,
  "message":"Get my bids successfully",
  "data": [
    {
      "bidId":"bid-uuid",
      "auctionId":"auction-uuid",
      "auctionTitle":"iPhone 15 Pro Max",
      "auctionImageUrl":"<https://example.com/images/iphone15.jpg>",
      "myBidAmount":13000000,
      "currentHighestBid":15000000,
      "currency":"VND",
      "bidStatus":"OUTBID",
      "auctionStatus":"ACTIVE",
      "bidTime":"2026-07-03T14:30:00",
      "auctionEndTime":"2026-07-10T20:00:00"
    }
  ]
}
```
###### 4. Main Flow
```
1. User opens /my-bids.
2. Frontend calls GET /api/v1/bids/my.
3. If accessToken exists in memory:
   - Frontend sends Authorization: Bearer <accessToken>.
4. If accessToken is missing or expired:
   - Backend returns 401.
   - Frontend calls POST /api/v1/auth/refresh-token.
   - Browser automatically sends refreshToken HttpOnly cookie.
   - Backend validates refreshToken.
   - Backend returns new accessToken.
   - Frontend stores new accessToken in memory only.
   - Frontend retries GET /api/v1/bids/my.
5. Backend gets current userId from JWT accessToken.
6. Backend finds all bids where bidderId = current userId.
7. Backend joins auction information:
   - auction title
   - imageUrl
   - current highest bid
   - auction status
   - auction end time
8. Backend calculates bid status:
   - WINNING
   - OUTBID
9. Backend sorts bid history by bidTime descending.
   - Newest bid appears first.
10. Backend returns bid list.
11. Frontend displays bid history.
12. User clicks View Detail.
13. Frontend redirects user to:
    /auctions/:auctionId
```

#### Image upload rule
```
First uploaded image = primary image
Primary image is shown on:
- Auction list page
- Auction detail page header
Other images are shown in:
- Auction detail gallery
```
#### Status rule
```
If startTime > current time:
status = UPCOMING
If startTime <= current time and endTime > current time:
status = ACTIVE
If endTime <= current time:
not allowed to create
```
Recommended:
```
Most create auctions should start as UPCOMING.
