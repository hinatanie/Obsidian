##### **What is this `docker-compose.yml` file for?**
This is a `docker-compose.yml` file using `Docker Compose`.
Instead of installing `MySQL` directly on your computer, `Docker` will run `MySQL` inside a `container`.
```
version: "3.9"

services:
  mysql:
    image: mysql:8.0
    restart: always
    env_file:
      - ./.env.dev
    environment:
      MYSQL_DATABASE: ${DB_NAME}
      MYSQL_USER: ${DB_USER}
      MYSQL_PASSWORD: ${DB_PASSWORD}
      MYSQL_ROOT_PASSWORD: rootpassword
    ports:
      - "${DB_PORT}:3306"
    volumes:
      - mysql_data:/var/lib/mysql
      - ./../init.sql:/docker-entrypoint-initdb.d/init.sql:ro

volumes:
  mysql_data:
```
##### **What does `services` mean?**
```
services:
  mysql:
    image: mysql:8.0
    restart: always
    env_file:
      - ./.env.dev
    environment:
      MYSQL_DATABASE: ${DB_NAME}
      MYSQL_USER: ${DB_USER}
      MYSQL_PASSWORD: ${DB_PASSWORD}
      MYSQL_ROOT_PASSWORD: rootpassword
    ports:
      - "${DB_PORT}:3306"
    volumes:
      - mysql_data:/var/lib/mysql
      - ./../init.sql:/docker-entrypoint-initdb.d/init.sql:ro
```
`services` defines the containers you want `Docker Compose` to run.
Examples of services:
```
MySQL container
Django container
Redis container
```
In this file, you only have one service:
```
mysql:
```
That means `Docker Compose` will create one `MySQL container`.
Later, you can run commands like:
```
docker compose logs mysql
```
or:
```
docker compose exec mysql bash
```
##### **What does `mysql` mean?**
```
mysql:
```
`mysql` is the service name.
It is the name you use when you want to run commands for this container.
For example:

```
docker compose logs mysql
```
means show logs for the `mysql` service.
```
docker compose exec mysql bash
```
means go inside the `mysql` container.
##### **What does `image: mysql:8.0` mean?**
```
image: mysql:8.0
```
`Docker` will download the official `MySQL 8.0` image and run it inside a `container`.
An `image` is like a template.
A `container` is the running version of that image.
##### **What does `restart: always` mean?**
```
restart: always
```
This tells `Docker` to restart the `MySQL container` automatically if it stops.
For example:
```
server reboot
container crashes
Docker daemon restarts
```
So if the `MySQL container` stops, `Docker` will try to start it again.
##### **What does `env_file` mean?**
```
env_file:
  - ./.env.dev
```
This loads environment variables from the file `.env.dev`.
For example, your `.env.dev` file may contain:
```
DB_NAME=app_db
DB_USER=backend_user
DB_PASSWORD=backend_password
DB_PORT=3307
```
Then `Docker Compose` can use these values inside `docker-compose.yml`.
##### **What does `environment` mean?**
```
environment:
  MYSQL_DATABASE: ${DB_NAME}
  MYSQL_USER: ${DB_USER}
  MYSQL_PASSWORD: ${DB_PASSWORD}
  MYSQL_ROOT_PASSWORD: rootpassword
```
This passes environment variables into the `MySQL container`.
These variables are used by the official `MySQL` image when the container starts for the first time.
##### **What does `MYSQL_DATABASE` mean?**
```
MYSQL_DATABASE: ${DB_NAME}
```
This creates a database automatically when the `MySQL container` starts for the first time.
For example, if `.env.dev` has:
```
DB_NAME=app_db
```
Then `MySQL` creates this database:
```
app_db
```
##### **What does `MYSQL_USER` mean?**
```
MYSQL_USER: ${DB_USER}
```
This creates a normal `MySQL user`.
For example, if `.env.dev` has:
```
DB_USER=backend_user
```
Then `MySQL` creates this user:
```
backend_user
```
This user is usually used by your backend app.
##### **What does `MYSQL_PASSWORD` mean?**
```
MYSQL_PASSWORD: ${DB_PASSWORD}
```
This sets the password for the normal `MySQL user`.
For example, if `.env.dev` has:
```
DB_PASSWORD=backend_password
```
Then the user `backend_user` can log in using:
```
backend_password
```
##### **What does `MYSQL_ROOT_PASSWORD` mean?**
```
MYSQL_ROOT_PASSWORD: rootpassword
```
This sets the password for the `root` user.
`root` is the main `MySQL admin user`.
For local development, this is okay.
For real production, you should use a stronger password and keep it in an environment file instead of writing it directly in `docker-compose.yml`.
##### **What does `ports` mean?**
```
ports:
  - "${DB_PORT}:3306"
```
This maps a port on your computer to a port inside the container.
`MySQL` inside the container always runs on port:
```
3306
```
But your computer can expose it on another port.
For example, if `.env.dev` has:
```
DB_PORT=3307
```
Then this:
```
ports:
  - "${DB_PORT}:3306"
```
becomes:
```
ports:
  - "3307:3306"
```
That means:
```
your computer port 3307 → container port 3306
```
So from `DBeaver` or your backend running on your computer, you connect using:
```
host: localhost
port: 3307
```
##### **What does `volumes` mean inside the `mysql` service?**
```
volumes:
  - mysql_data:/var/lib/mysql
  - ./../init.sql:/docker-entrypoint-initdb.d/init.sql:ro
```
This mounts storage and files into the container.
In this example, you use volumes for two things:
```
Keep MySQL database data
Run init.sql when MySQL starts for the first time
```
##### **What does `mysql_data:/var/lib/mysql` mean?**
```
- mysql_data:/var/lib/mysql
```
This creates a named Docker volume called:
```
mysql_data
```
It is mounted to this path inside the `MySQL container`:
```
/var/lib/mysql
```
Inside the `MySQL container`, `/var/lib/mysql` is where `MySQL` stores database files.
Without this `volume`, your database data may disappear when the container is removed.
With this `volume`, your database data stays even if you recreate the container.
##### **What does `./../init.sql:/docker-entrypoint-initdb.d/init.sql:ro` mean?**
```
- ./../init.sql:/docker-entrypoint-initdb.d/init.sql:ro
```
This mounts your local `init.sql` file into the `MySQL container`.
Your local file is:
```
./../init.sql
```
Inside the container, it becomes:
```
/docker-entrypoint-initdb.d/init.sql
```
The `ro` at the end means:
```
read-only
```
So the container can read the file, but cannot modify it.
##### **What is `/docker-entrypoint-initdb.d`?**
```
/docker-entrypoint-initdb.d
```
The official `MySQL` image automatically runs `.sql` files placed inside this folder.
So this file:
```
/docker-entrypoint-initdb.d/init.sql
```
will run when the database is initialized for the first time.
This is useful for creating tables or inserting default data.

##### ##### **How does `init.sql` not run again?**
`init.sql` only runs when `MySQL` is initialized for the first time.
If the `mysql_data` volume already has database data, `MySQL` will not initialize again.
So `init.sql` will not run again.

**How to make `init.sql` run again**
To make `init.sql` run again, you usually need to remove the volume.
```
docker compose down -v
docker compose up -d
```
Be careful.
```
docker compose down -v
```
deletes the database data stored in the volume.
So after running this, `MySQL` starts like a fresh new database.
##### **What does the bottom `volumes` section mean?**
```
volumes:
  mysql_data:
```
This defines named volumes used by your services.
Here, it declares the named volume:
```
mysql_data
```
This volume is used here:
```
- mysql_data:/var/lib/mysql
```
So the full idea is:
```
Create a Docker volume called mysql_data
Mount it into the MySQL container at /var/lib/mysql
Use it to keep database files
```
