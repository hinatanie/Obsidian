##### **How to stop and remove `containers` and `networks` but it keeps `volumes`**
```
docker compose down
```
So after this, when you run
```
docker compose up -d
```
Your database still exists
##### **How to stop and remove `containers`, `networks`, `volumes`**
```
docker compose down -v
```
`-v` means remove `volumes`

So after this, when you run
```
docker compose up -d
```
`MySQL` starts like a fresh new database
Also, your `init.sql` runs again because `MySQL` is initialized from zero
##### **How to start the containers, but keeps logs attached in your terminal**
```
docker compose up
```
##### **How to start containers in the background**
```
docker compose up -d
```

`-d` means `detached mode`
##### **How to show the `Docker Compose configuration` after `Docker` reads and resolve everything**
```
docker compose config
```
##### **How to print the logs/output of container in terminal**
```
docker logs backend-mysql-1
```
##### **How to run `MySQL` in a docker `MySQL` **
```
docker compose exec -it backend-mysql-1 mysql -u root -p
```

```
docker compose exec
```
means going inside the `running MySQL container` from `Docker Compose` 

```
-it
```
means `interactive terminal mode`
It allows you to type commands

```
backend-mysql-1
```
This is the container name you want to enter

```
mysql
```
Run `MySQL client program` inside the container

```
-u root
```
Login with `MySQL` user root

```
-p
```
Ask for password
