##### **Why does `MySQL` have users?**
`MySQL` has users because different programs may need different permissions.
For example, your backend app may need permission to read and write data, but it should not be able to control the whole `MySQL server`.
##### **What is `root` in `MySQL`?**
`root` is the main `MySQL admin user`.
It can do almost everything, such as creating databases, deleting databases, creating users, and giving permissions.
```sql
CREATE DATABASE app_db;
DROP DATABASE app_db;
CREATE USER 'backend_user'@'%';
GRANT ALL PRIVILEGES ON app_db.* TO 'backend_user'@'%';
SHOW DATABASES;
```
For local development, using `root` is okay.
For real production, it is safer not to let your app use `root`.
##### **Why should the backend not use `root` in production?**
Because `root` can control the whole `MySQL server`.
If your backend app has a bug or gets hacked, the attacker may be able to delete databases, create users, or change permissions.

So in production, the backend should use a normal `MySQL` user with limited permissions.
##### **How to give a normal user permission on only one database**
```
GRANT SELECT, INSERT, UPDATE, DELETE ON mydb.* TO 'normaluser'@'%';
```
This means `normal user` can work with `mydb`, but cannot control the whole `MySQL server`.
##### **What permissions does a normal backend user usually need?**
A normal backend user usually only needs permission on one database.
Common operations are:
```
SELECT * FROM users;
INSERT INTO users ...;
UPDATE users ...;
DELETE FROM users ...;
```
These allow the backend to read, create, update, and delete application data.
