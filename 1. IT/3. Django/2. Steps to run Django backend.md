##### **How to start MySQL server**
Before running the Django project, you need to start `MySQL`.
If you use `XAMPP`, open `XAMPP` and start `MySQL`.
If you use `MySQL Workbench`, start the `MySQL service`.
If you use terminal, start the `MySQL service`.
##### **How to create the database manually**
Open a `MySQL` tool, for example:
```
phpMyAdmin
MySQL Workbench
DBeaver
DataGrip
Terminal
```
Run this `SQL`:
```
CREATE DATABASE buocchancoi_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```
This creates an empty database named:
```
buocchancoi_db
```
The Django project will use this database.
##### **How to run MySQL using Docker**
You can use `Docker` to run `MySQL`.
Instead of installing `MySQL` directly on your computer, `Docker` runs `MySQL` inside a container.
Inside your backend folder, create this file:
```
docker-compose.yml
```
Put this inside:
```
services:
  mysql:
    image: mysql:8.0
    container_name: buocchancoi_mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: rootpassword
      MYSQL_DATABASE: buocchancoi_db
    ports:
      - "3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql

volumes:
  mysql_data:
```
This will automatically create the database:
```
buocchancoi_db
```
So you do not need to manually run:
```
CREATE DATABASE buocchancoi_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```
##### **How to start the MySQL Docker container**
Run:
```
docker compose up -d
```
`-d` means `detached mode`.
It starts the container in the background.
##### **How to check if MySQL container is running**
Run:
```
docker ps
```
You should see a container like:
```
buocchancoi_mysql
```
or something similar.
##### **What to put in Django `.env` file**
In your Django `.env` file, use:
```
DB_NAME=buocchancoi_db
DB_USER=root
DB_PASSWORD=rootpassword
DB_HOST=127.0.0.1
DB_PORT=3306
SECRET_KEY=your_long_random_secret_key
DEBUG=True
ALLOWED_HOSTS=localhost,127.0.0.1
CLOUDINARY_URL=cloudinary://API_KEY:API_SECRET@your_cloud_name
```
This file stores environment variables for the Django project.
##### **How Django reads values from `.env`**
The project reads values from `.env` using:
```
os.getenv("SECRET_KEY")
```
For example:
```
os.getenv("DB_NAME")
os.getenv("DB_USER")
os.getenv("DB_PASSWORD")
os.getenv("DB_HOST")
os.getenv("DB_PORT")
```
This lets you keep secret or changeable config outside your source code.
##### **What is `SECRET_KEY` in Django?**
```
SECRET_KEY=your_long_random_secret_key
```
In Django, `SECRET_KEY` is used for security features.
For example:
```
Signing cookies
Sessions
Password reset tokens
CSRF protection
```
You should generate a long random secret.
Do not share your production `SECRET_KEY`.
##### **What does `DEBUG=True` mean?**
```
DEBUG=True
```
This means the app shows detailed error messages.
This is useful during development.
But in production, `DEBUG` must be:
```
DEBUG=False
```
Because debug errors can leak sensitive information.
##### **What does `ALLOWED_HOSTS` mean?**
```
ALLOWED_HOSTS=localhost,127.0.0.1
```
This tells Django which domains or hosts are allowed to access the app.
For local development, use:
```
ALLOWED_HOSTS=localhost,127.0.0.1
```
For production, use your real domain:
```
ALLOWED_HOSTS=example.com,www.example.com
```
##### **What does `DB_NAME` mean?**
```
DB_NAME=buocchancoi_db
```
This is the database name.
Your Django app will connect to a database named:
```
buocchancoi_db
```
##### **What does `DB_USER` mean?**
```
DB_USER=root
```
This is the database username.
For local development, using `root` is okay.
For production, it is better to create a separate normal database user instead of using `root`.
##### **What does `DB_PASSWORD` mean?**
```
DB_PASSWORD=rootpassword
```
This is the password for the database user.
In the Docker example, this matches:
```
MYSQL_ROOT_PASSWORD: rootpassword
```
So Django can connect to MySQL using:
```
user: root
password: rootpassword
```
##### **What does `DB_HOST` mean?**
```
DB_HOST=127.0.0.1
```
This is the database host.
If your Django app runs outside Docker, use:
```
DB_HOST=127.0.0.1
```
or:
```
DB_HOST=localhost
```
If your Django app runs inside `Docker Compose`, and your MySQL service name is `mysql`, use:
```
DB_HOST=mysql
```
That is because containers inside the same `Docker Compose` network can connect using the service name.
##### **What does `DB_PORT` mean?**
```
DB_PORT=3306
```
This is the MySQL port.
If your Docker Compose file has:
```
ports:
  - "3306:3306"
```
Then your app running on your computer connects to:
```
host: 127.0.0.1
port: 3306
```
##### **What does `CLOUDINARY_URL` mean?**
```
CLOUDINARY_URL=cloudinary://API_KEY:API_SECRET@your_cloud_name
```
This is the Cloudinary connection URL.
Cloudinary is commonly used to upload and store images or videos.

##### **How to stop the MySQL container**
Run:
```
docker compose down
```
This stops and removes the container and network.
It keeps the Docker volume, so your database data still exists.
##### **What if port `3306` is already being used?**
If your computer already has `MySQL` running on port `3306`, Docker may fail.
In that case, change this:
```
ports:
  - "3306:3306"
```
to:
```
ports:
  - "3307:3306"
```
This means:
```
your computer port 3307 → container port 3306
```
Then update your Django `.env`:
```
DB_PORT=3307
```
Now your Django app connects to MySQL using:
```
host: 127.0.0.1
port: 3307
```
