## 3. What a "Good Incident Report" Contains
Once the investigation is done, the AI agent or engineer must compile a post-mortem or incident report. A high-quality incident report avoids vague guessing and relies entirely on hard data:
- **The Impact:** Exactly who was affected, what services went down, and for how long.
- **The Timeline:** A precise sequence of events (e.g., `14:02` Code Deploy → `14:03` DB CPU spikes → `14:05` Payment Service timeout errors).
- **The Root Cause:** The specific underlying trigger (e.g., "An unindexed SQL query in the new deployment clogged the connection pool").
- **The Mitigation & Preventative Actions:** How the system was temporarily restored, and what code/infrastructure changes will be made to ensure it never happens again.
