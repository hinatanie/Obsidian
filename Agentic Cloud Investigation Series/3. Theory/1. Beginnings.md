### 1. Cloud fundamentals
You need enough AWS/Kubernetes knowledge to understand what the Agent is inspecting.
Learn:
- AWS Region / Availability Zone
- VPC, subnet, route table, Internet Gateway
- Security Group / NACL
- EC2
- IAM
- S3
- RDS
- Load Balancer
- CloudWatch
- basic Kubernetes: Pod, Deployment, Service, Namespace
Your goal is not “master AWS”. Your goal is:
> When you see a cloud resource, understand **what it is, what it connects to, and what could go wrong**.

### 4. Cloud environment review and risk analysis
This prepares you for both Day 01 and Day 03.
Learn how to inspect an unknown system.
You should practice answering:
- What resources exist?
- How are they connected?
- Which resources are public?
- Where does traffic enter?
- Where is the database?
- What identities exist?
- Which permissions are dangerous?
- What is the highest-risk configuration?
- What evidence proves each conclusion?
Important concepts:
- Environment Map
- attack surface
- exposed resources
- overly permissive IAM
- public database
- open security groups
- misconfigured storage
- missing monitoring/logging
- single point of failure
- risk severity
- likelihood vs impact
- risk prioritization
Example:
```text
Internet
   │
   ▼
┌───────────────┐
│ Load Balancer │
└───────┬───────┘
        │
        ▼
┌───────────────┐
│ EC2 App       │
└───────┬───────┘
        │
        ▼
┌───────────────┐
│ RDS Database  │
└───────────────┘
```
Then investigate:
```text
What is public?
What ports are open?
Who can access RDS?
What IAM role does EC2 have?
Where are the logs?
```

### 5. Incident investigation
This is the core of **Day 02**.
You need to learn how to go from:
```text
Something is wrong
```
to:
```text
Evidence → hypothesis → test → root cause
```
Learn:
- incident
- symptom
- signal
- hypothesis
- competing hypotheses
- evidence
- root cause
- contributing factor
- timeline
- correlation vs causation
A very important investigation structure is:
```text
Signal
  │
  ▼
Possible cause A
Possible cause B
Possible cause C
  │
  ▼
Collect evidence
  │
  ▼
Reject A
Reject C
  │
  ▼
B remains
  │
  ▼
Find causal evidence
  │
  ▼
Root cause
```
You should deliberately practice **not trusting the Agent's first answer**.
For example:
```text
Agent:
"The outage was caused by high CPU."
You:
"What evidence proves that?"
Agent:
"CPU reached 95%."
You:
"Did high CPU occur before or after the outage?"
```
That last question is exactly the mindset this workshop is teaching.

### 6. Logs, metrics, timestamps, and evidence
The phrase **“Evidence over confidence”** is the heart of the workshop.
Learn:
- logs
- metrics
- traces
- events
- timestamps
- CloudWatch Logs
- CloudWatch Metrics
- Kubernetes events/logs
- audit logs
- source attribution
- evidence quality
Learn to build an **Evidence Table** like this:

|Time|Evidence|Source|Meaning|
|---|---|---|---|
|10:02|CPU = 92%|CloudWatch|app under load|
|10:04|DB connections = max|RDS metrics|DB saturation|
|10:05|API 5xx increased|ALB logs|user impact begins|
|10:07|app timeout errors|application logs|DB calls failing|
This is much stronger than saying:
> “I think the DB caused it.”
Instead:
> “RDS connections hit the configured maximum at 10:04, followed by API 5xx errors at 10:05 and DB timeout errors at 10:07.”

### 7. Causal reasoning
This is slightly different from normal troubleshooting and is probably something worth studying separately.
Learn:
- causal chain
- causal graph
- necessary cause
- contributing cause
- downstream symptom
- upstream cause
- temporal ordering
- counterfactual reasoning
Example:
```text
Bad deployment
      │
      ▼
DB query becomes expensive
      │
      ▼
DB CPU rises
      │
      ▼
Connection pool fills
      │
      ▼
API requests timeout
      │
      ▼
5xx errors
```
Notice:
```text
5xx errors ≠ root cause
CPU high ≠ automatically root cause
```
They may simply be symptoms.

### What I would prioritize for you
Because you already have some AWS/VPC experience, I wouldn't restart all AWS from zero. Focus most heavily on:
**Priority 1:** IAM and permissions  
**Priority 2:** Cloud environment mapping  
**Priority 3:** Logs / metrics / evidence  
**Priority 4:** Incident investigation  
**Priority 5:** Causal reasoning  
**Priority 6:** Agent governance  
**Priority 7:** Kubernetes basics
If your goal is specifically to perform well in **Prove It Arena**, the biggest skill is not memorizing AWS services. It is being able to say:
> **“This is my conclusion. Here is the evidence. Here is the source. Here is the timestamp. Here are the alternative hypotheses I rejected, and here is why.”**
That matches almost the entire scoring rubric.
